1. 讀懂 /scan：一圈距離組成的陣列

🔊 旁白文字

光達就像一個不停轉圈的雷射測距儀，每轉一圈，就把每個方向量到的距離打包成一則訊息，送到 scan 話題。這則訊息最重要的是一個叫 ranges 的陣列，裡面一格就是一個方向的距離，單位是公尺。那第幾格是哪個方向呢？訊息裡會告訴你第一格的角度和每格之間差幾度，用起始角度加上格數乘以間隔，就算得出來。看懂這一條公式，這一單元的四支程式你就全都看得懂了。

sensor_msgs/LaserScan 重要欄位：

欄位 意義 單位
ranges[] 每一條雷射打到東西的距離 公尺
angle_min、angle_max 第一條、最後一條雷射的角度 弧度
angle_increment 相鄰兩條雷射的角度差 弧度
range_min、range_max 光達量得到的最近、最遠距離；超出範圍的值不可信 公尺
header.frame_id 這份資料屬於哪個座標系（光達本身） — 
第 i 條雷射的角度 = angle_min + angle_increment × i        （弧度）
角度（度）        = 上式 × 180 / π
        +90° 左
          ↑
  ±180° ← 車 → 0° 正前方         ROS 慣例：逆時針為正，左邊是正角度
          ↓
        -90° 右

官方四支程式都用同一段迴圈把每一格換成「度」，並把大於 180 的角度減 360，讓前方是 0、左正右負：

在車上 Docker 容器內（yahboomcar_laser 共同寫法）
RAD2DEG = 180 / math.pi
for i in range(len(ranges)):
    angle = (scan_data.angle_min + scan_data.angle_increment * i) * RAD2DEG
    if angle > 180: angle = angle - 360

自己看一眼真實資料：

在車上 Docker 容器內
ros2 interface show sensor_msgs/msg/LaserScan     # 看欄位定義
ros2 topic echo /scan --once --no-arr             # 只看 angle_min、angle_increment 等，不印 ranges
ros2 topic hz /scan                               # 一秒幾圈

沒車也可以在電腦上看模擬車的 /scan（模擬環境由講義另外提供，指令固定如下）：

在電腦 WSL（Jazzy）
cd ~/yahboom_ws && source install/setup.bash && ros2 launch microros_pi5_sim sim.launch.xml
# 另一個終端：
source /opt/ros/jazzy/setup.bash
ros2 topic echo /scan --once --no-arr
💡 小提示

ranges 裡可能出現 inf（太遠沒打到）、nan 或 0.0（無效點）。官方程式有的用 ranges[i] > 0 濾掉 0，有的沒有；自己寫程式時一律先過濾無效值（M5 會示範）。MS200 的實際點數與 0° 方向請用上面的 --no-arr 指令在實車確認（需實車確認）。

2. 共同前置：陀螺儀初始化與 Switch 開關

🔊 旁白文字

光達課每一課開頭都有同樣的準備動作，其中最容易被跳過的，是讓陀螺儀初始化。開機時車子必須穩穩放在地上、靜止五秒，讓陀螺儀量出「不動的時候是多少」。如果開機時車子在你手上晃，之後里程計會一直以為車在轉，巡邏走不出正方形，第三級的建圖導航更會整個歪掉。另一件事是每支程式都有一個叫 Switch 的開關參數，它的意思要看清楚。

每次上課的開機流程：

  1. 車子斷電，平穩放在地上。
  2. 開電源，放著不動 5 秒（陀螺儀初始化）。
  3. 啟動 agent、按控制板 reset、進容器：
在 Pi 5 主機
sh ~/start_agent_rpi5.sh
sh ros2_humble.sh            # 另開終端；多開請用 docker ps -a ＋ docker exec -it <ID> /bin/bash
在車上 Docker 容器內
ros2 node list               # 看到 /YB_Car_Node 才繼續
ros2 topic list              # 要有 /scan、/cmd_vel、/beep
⚠️ 注意

Switch 的意思，文件和原始碼不一致：

  • 官方文件說 Switch 是「功能開關，要打開才會動」。
  • 但 laser_Avoidance、laser_Tracker、laser_Warning 的原始碼寫的是 if self.Joy_active or self.Switch == True: → 停車並暫停。也就是預設 False 時一啟動就會動，勾成 True 反而是「暫停」。
  • patrol 則相反：Switch 為 True 才開始走，走完一段會自動改回 False。
  • 車上映像的版本可能與原始碼不同（需實車確認）。第一次執行前先把車架高或放在空曠處，並準備好隨時 Ctrl+C。

另外，搖桿一動（/JoyState 為 True），所有程式都會讓出控制權並停車。

3. 第 1 課 避障 laser_Avoidance

🔊 旁白文字

避障的邏輯是把前方切成三個扇區：正前方、左前方、右前方，然後數一數每個扇區裡有幾個點比安全距離還近。只看一個點很容易被雜訊騙，所以要超過十個點才算「那邊有東西」。接著就是一張判斷表：只有右邊有東西就左轉，只有左邊有東西就右轉，三邊都有就右轉試著脫困，都沒有就直走。這就是最基本的「感測、判斷、動作」迴圈。

在車上 Docker 容器內
ros2 run yahboomcar_laser laser_Avoidance
ros2 run rqt_reconfigure rqt_reconfigure        # 另一個終端；找節點 laser_Avoidance，看不到就按 Refresh

扇區定義（LaserAngle 預設 45°；距離門檻是 ResponseDist × 1.5）：

扇區 角度範圍 計數條件
左 Left_warning 20° < angle < LaserAngle ranges[i] < ResponseDist*1.5
右 Right_warning -LaserAngle < angle < -20° 同上
前 front_warning |angle| ≤ 20° ranges[i] <= ResponseDist*1.5

判斷表（計數 > 10 才算有障礙；原始碼完整版）：

前 左 右 終端機訊息 動作
有 有 有 1, there are obstacles in the left and right, turn right 邊走邊右轉
有 無 有 2, there is an obstacle in the middle right, turn left 左轉
有 有 無 4. There is an obstacle in the middle left, turn right 右轉（但原始碼這行的 publish 被註解掉，實際不會送出新速度）
有 無 無 6, there is an obstacle in the middle, turn left 左轉
無 有 有 7. There are obstacles on the left and right, turn right 右轉
無 有 無 8, there is an obstacle on the left, turn right 右轉
無 無 有 9, there is an obstacle on the right, turn left 左轉
無 無 無 10, no obstacles, go forward 直走

參數：

參數 意義 預設
linear 線速度 m/s 0.3
angular 角速度 rad/s 1.0
LaserAngle 左右扇區的外側角度 45.0
ResponseDist 障礙距離（程式乘 1.5 使用） 0.55
Switch 見上一小節的警告 False
⚠️ 注意
  • 官方文件把線速度參數拼成 linera，原始碼實際是 linear。在 rqt 或 ros2 param set 請用 linear。
  • 預設 0.3 m/s 在室內偏快，第一次建議先 ros2 param set /laser_Avoidance linear 0.15。
  • 程式每次送完轉彎速度會 sleep(0.2)，所以反應會有一點延遲，這是正常的。

4. 第 2 課跟隨 laser_Tracker、第 3 課警衛 laser_Warning

🔊 旁白文字

跟隨和警衛都在做同一件事：在掃描範圍裡找出最近的那個點，記下它的距離和角度。跟隨程式用兩個 PID：距離差多少決定前進或後退，角度差多少決定轉多少，讓車和你保持固定距離。警衛程式只轉不走，原地轉身盯著最近的東西，一旦太近就讓蜂鳴器響。你可以拿一個紙箱慢慢移動，親眼看到控制器怎麼追。

跟隨：

在車上 Docker 容器內
ros2 run yahboomcar_laser laser_Tracker
ros2 run rqt_reconfigure rqt_reconfigure        # 節點 laser_Tracker
在車上 Docker 容器內（laser_Tracker.py 節錄）
self.lin_pid = SinglePID(2.0, 0.0, 2.0)
self.ang_pid = SinglePID(3.0, 0.0, 5.0)
# 優先：正前方 ±priorityAngle 內、距離 < ResponseDist + 0.5 的點；沒有才看 ±LaserAngle 內的點
if abs(minDist - self.ResponseDist) < 0.1: minDist = self.ResponseDist    # 差 0.1 m 內算到位
velocity.linear.x = -self.lin_pid.pid_compute(self.ResponseDist, minDist)  # 太近倒退、太遠前進
ang_pid_compute = self.ang_pid.pid_compute(minDistID/48, 0)               # 角度 ÷ 48 是官方經驗常數
if abs(ang_pid_compute) < 0.1: velocity.angular.z = 0.0                    # 死區
參數 意義 預設
priorityAngle 優先追蹤的正前方角度 10.0
LaserAngle 偵測角度 45.0
ResponseDist 想保持的距離 m 0.55
Switch 為 True 時暫停 False

警衛：

在車上 Docker 容器內
ros2 run yahboomcar_laser laser_Warning
ros2 run rqt_reconfigure rqt_reconfigure        # 節點名是 laser_Warnning（兩個 n）
  • 只發 angular.z（原地轉向最近物體），沒有線速度。
  • 最近距離 ≤ ResponseDist（預設 0.3）時印 --------------- 並發布 /beep（std_msgs/UInt16，data: 1 響）；否則印 no obstacles@ 並發 data: 0。
  • LaserAngle 預設 45.0。
⚠️ 注意

可執行檔叫 laser_Warning，但程式裡建立節點時寫成 laser_Warnning（多一個 n），文件裡的原始檔名也寫成 laser_Warnning.py。所以：啟動用 ros2 run yahboomcar_laser laser_Warning，調參數時節點名要用 /laser_Warnning。

5. 第 4 課 巡邏 patrol：第一次用到 TF 與里程計

🔊 旁白文字

巡邏是讓車照著設定好的路線走，例如正方形、圓形或三角形。車子怎麼知道自己走了一公尺、轉了九十度呢？靠的是里程計，它用輪子轉了幾圈加上陀螺儀，估算出車子從開機起點走到哪裡。這個位置用座標轉換 TF 來表示，從 odom 到 base footprint。所以這一課要先啟動底層資料處理，TF 存在了，巡邏程式才算得出距離和角度。

在車上 Docker 容器內
# 終端 1：底層資料處理（IMU 濾波 + EKF 融合 + 機器人模型），會發布 odom → base_footprint 的 TF
ros2 launch yahboomcar_bringup yahboomcar_bringup_launch.py
# 終端 2：巡邏程式
ros2 run yahboomcar_bringup patrol
# 終端 3：
ros2 run rqt_reconfigure rqt_reconfigure        # 節點 YahboomCarPatrol；Command 選路線，再勾 Switch 開始
參數 意義 預設
Command LengthTest（直線）、Circle、Square、Triangle Square
Switch True 才開始（與前三支相反） False
Set_loop 走完再重來 False
Linear、Angular 線速度、角速度 0.2、0.9
Length 直線距離 m 0.5
LineTolerance、RotationTolerance 直線、旋轉的容許誤差 0.05、0.25
LineScaling、RotationScaling 里程計校正係數 1.0、1.0
circle_adjust 圓形大小係數 2.0
ResponseDist、LaserAngle 避障距離、角度 0.6、20.0
odom_frame、base_frame 座標系名稱 odom、base_footprint

程式核心：tf_buffer.lookup_transform(odom_frame, base_frame, ...) 取得目前位置與航向；advancing() 直走到距離誤差小於 LineTolerance，Spin() 轉到角度誤差小於 RotationTolerance；Square() 用 self.index 依序「直走 → 轉 90° → 直走 …」。

⚠️ 注意
  • 沒先跑 bringup，TF 不存在，程式會一直印 transform not ready。
  • 速度話題在這支程式寫成 cmd_vel（沒有斜線），效果與 /cmd_vel 相同。
  • 手上這份原始碼的 patrol.py 中，訂閱 /scan 的那一行被註解掉了（#self.sub_scan = ...），所以「遇障停車並響蜂鳴器」的功能可能不會發生。車上映像版本可能不同（需實車確認）；保險起見巡邏路線上不要放障礙物，並隨時準備 Ctrl+C。
  • 走出來的正方形歪掉，先回 B6 做線速度、角速度校準，再微調 LineScaling、RotationScaling。

6. 執行中調參數：rqt_reconfigure 與 ros2 param

🔊 旁白文字

這四支程式都把速度、距離、角度做成「參數」，而且每隔一小段時間就重新讀一次，所以程式不用重開，改了馬上生效。改的方法有兩種：圖形介面的 rqt reconfigure，適合邊看邊拉；指令列的 ros2 param，適合精確設定和存檔。這種「把可調的數字做成參數」的設計，下一單元你自己寫節點時也會用上。

圖形介面：ros2 run rqt_reconfigure rqt_reconfigure → 左側選節點（看不到按 Refresh）→ 改數值 → 在空白處點一下才會送出。

指令列：

在車上 Docker 容器內
ros2 param list /laser_Avoidance                        # 列出這個節點有哪些參數
ros2 param get /laser_Avoidance ResponseDist            # 查目前值
ros2 param set /laser_Avoidance ResponseDist 0.4        # 改成 0.4（要寫小數，型別是 double）
ros2 param set /laser_Avoidance linear 0.15
ros2 param set /laser_Avoidance Switch true             # 暫停（依原始碼語意）
ros2 param dump /laser_Avoidance > avoid.yaml           # 存成 YAML
# 下次啟動直接帶參數：
ros2 run yahboomcar_laser laser_Avoidance --ros-args -p linear:=0.15 -p ResponseDist:=0.4
ros2 run yahboomcar_laser laser_Avoidance --ros-args --params-file avoid.yaml
💡 小提示

參數有型別。ResponseDist 宣告時是 0.55（浮點數），用 ros2 param set ... ResponseDist 1 會因為 1 被當成整數而失敗，要寫 1.0。巡邏的 Command 是字串，例如 ros2 param set /YahboomCarPatrol Command Circle。

沒車先練（選做）：yahboomcar_laser 只依賴標準訊息，可以從原始碼複製到電腦，在模擬車上跑：

在電腦 WSL（Jazzy）
WINHOME=$(wslpath "$(cmd.exe /c echo %USERPROFILE% 2>/dev/null | tr -d '\r')")
mkdir -p ~/laser_ws/src
cp -r "$WINHOME/workspace/yahboom-microros-pi5/source-code/src/18. Summary of program source code/yahboomcar_ws/src/yahboomcar_laser" ~/laser_ws/src/
cd ~/laser_ws && source /opt/ros/jazzy/setup.bash && colcon build
source install/setup.bash
ros2 run yahboomcar_laser laser_Avoidance --ros-args -p linear:=0.15   # 先另開終端啟動模擬車

模擬車沒有蜂鳴器，laser_Warning 發的 /beep 只是沒人收；Jazzy 編譯時出現 SetuptoolsDeprecationWarning 可忽略。

7. 出問題時怎麼辦

🔊 旁白文字

光達程式出問題時，先問自己三個問題：有沒有收到 scan、程式有沒有發出 cmd vel、車子有沒有照 cmd vel 動。用 topic hz 看頻率、用 topic echo 看速度值，就能分出是哪一段壞掉。另外，如果車子明明沒動，螢幕上的模型卻自己在轉，那幾乎都是開機時沒有讓陀螺儀靜止初始化。

症狀 檢查 怎麼做
程式啟動後完全不動 Switch 是否被設成 True；搖桿是否被碰到 ros2 param get /laser_Avoidance Switch；放開搖桿
巡邏不動 Switch 沒勾、Command 打錯字 巡邏要勾 Switch；Command 只能是 LengthTest、Circle、Square、Triangle
ros2 topic hz /scan 沒數字 光達或 agent 沒連上 重啟 agent、按 reset；確認光達有在轉
一直判斷有障礙、原地打轉 地板反光、車身附近有線材被掃到、無效點被當成障礙 清空周圍；把 ResponseDist 調小；ros2 topic echo /scan --once 看是否有一堆 0
巡邏一直印 transform not ready 沒跑 bringup 先 ros2 launch yahboomcar_bringup yahboomcar_bringup_launch.py
車沒動但 RViz 模型自己轉／漂 開機時陀螺儀沒靜止初始化 斷電、放平、開機後靜置 5 秒
ros2 param set 說 Wrong parameter type 整數與浮點數混用 浮點參數寫 0.4、1.0
rqt 找不到 laser_Warning 節點 節點名多一個 n 選 laser_Warnning
Ctrl+C 後車還在走 停車指令沒送到 ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{}"
