micro-ROS agent 與 Docker 容器：第一次看到車的節點

⏱ 45 分鐘🚗 真車：是
🎯 學習目標
理解 agent 與 ROS 2 容器各自的角色，能自己關掉開機自動啟動的終端機、再手動啟動 agent 和容器，並在容器內看到車子的節點
✅ 完成標準
在車上 Docker 容器內執行 ros2 node list，看到 /YB_Car_Node；並能用 docker exec 再開第二個終端機進入同一個容器

1. 三個角色：小腦、翻譯官、大腦裡的工作室

🔊 旁白文字

上一課桌面上有兩個自動開啟的終端機，這一課要搞懂它們在做什麼。車上的 ESP32 小腦跑的是 micro-ROS，它是 ROS 2 的瘦身版，記憶體太小，沒辦法自己加入 ROS 2 網路。所以樹莓派上要跑一個翻譯官，叫做 micro-ROS agent，把小腦說的話翻成正式的 ROS 2 話題。第二個終端機則是一個 Docker 容器，你可以想成大腦裡一間裝潢好的工作室，ROS 2 Humble 和亞博寫好的所有套件都放在裡面。

示意圖（不用執行）
 ESP32-S3（micro-ROS 韌體，節點 /YB_Car_Node）
        │  USB 序列線 /dev/ttyUSB0，921600 baud
        ▼
 Pi 5 主機：micro-ROS agent（Docker 映像 microros/micro-ros-agent:humble）
        │  DDS（ROS 2 的通訊底層），ROS_DOMAIN_ID=20
        ▼
 Pi 5 主機：ROS 2 Humble 容器（yahboomcar_* 套件）→ 你在這裡打 ros2 指令
名詞 白話 在哪裡
micro-ROS 能跑在微控制器上的迷你 ROS 2 ESP32 韌體
agent（代理） 翻譯官：沒有它，ESP32 就是一座孤島 Pi 5 主機，由 start_agent_rpi5.sh 用 Docker 啟動
Docker 映像（image） 唯讀的範本，像「工作室的設計圖」 Pi 5 主機的 Docker 裡
Docker 容器（container） 用映像蓋出來、正在使用的工作室 由 ros2_humble.sh 啟動
ROS_DOMAIN_ID 頻道號碼：同頻道的節點才看得到彼此 控制板、容器、你的電腦三邊都要一樣，預設 20

2. 兩支啟動腳本到底寫了什麼

🔊 旁白文字

官方教學每一課開頭都叫你打兩行指令，一行啟動 agent、一行進入容器。我們先打開這兩支腳本看一眼，知道它們在做什麼，出問題時才知道從哪裡查。兩支腳本都只有一行重點，都是 docker run。差別在於 agent 那支開的是官方的翻譯官映像，透過序列埠跟 ESP32 講話；容器那支開的是亞博的 ROS 2 映像，最後執行一個叫 root 底下一點 sh 的腳本，這個腳本會順便啟動手把控制。

在 Pi 5 上看腳本內容（SSH 或 VNC 終端機都可以）：

在 Pi 5 主機
cat ~/start_agent_rpi5.sh
cat ~/ros2_humble.sh

官方原始碼包（18. Summary of program source code）裡的 start_agent_rpi5.sh：

在 Pi 5 主機
#!/bin/bash
# WIFI
#docker run -it --rm -v /dev:/dev -v /dev/shm:/dev/shm --privileged --net=host microros/micro-ros-agent:humble udp4 --port 8090 -v4
# serial
docker run -it --rm -v /dev:/dev -v /dev/shm:/dev/shm --privileged --net=host microros/micro-ros-agent:humble serial --dev /dev/ttyUSB0 -b 921600 -v4
  • 被 # 註解掉的是 WiFi（UDP 8090 埠）版，給「虛擬機／電腦版」車用；Pi 5 版用下面那行序列版。
  • serial --dev /dev/ttyUSB0 -b 921600：從 USB 序列線、以 921600 鮑率跟 ESP32 通訊。
  • --net=host：容器直接用 Pi 5 的網路，DDS 才能和區網其他機器互通。
  • -v4：輸出比較詳細的 log，所以連上後 agent 終端機會「刷很多行」。

同一包裡的 ros2_humble.sh：

在 Pi 5 主機
#!/bin/bash
xhost +
docker run -it --rm \
--privileged=true \
--net=host \
--env="DISPLAY" \
--env="QT_X11_NO_MITSHM=1" \
-v /tem/.X11-unix:/tmp/.X11-unix \
--security-opt apparmor:unconfined \
-v /dev/input:/dev/input \
-v /dev/video0:/dev/video0 \
yahboomtechnology/ros-humble:4.0.3 /bin/bash /root/1.sh
  • 映像：yahboomtechnology/ros-humble:4.0.3（你車上的版本號可能不同，以 cat ~/ros2_humble.sh 為準）。
  • -v /dev/input：把手把掛進容器；-v /dev/video0：把 USB 攝影機掛進容器。
  • --rm：離開容器時自動刪除容器，所以在容器裡改的檔案，離開就消失。
  • 最後執行 /root/1.sh：容器啟動時順便開手把控制（B4 會教怎麼關）。
⚠️ 注意

原始碼包裡這一行寫成 -v /tem/.X11-unix:/tmp/.X11-unix，/tem 應該是 /tmp 的筆誤。因為有 --net=host，圖形視窗多半還是開得起來；如果你在容器裡開 rqt、rviz2 出現「cannot connect to X server」，可以檢查這一行（需實車確認車上版本是否相同）。

ℹ️ 補充

Docker 課（第 13 章）的範例映像是 yahboomtechnology/ros-foxy、帳號 jetson，那是別款產品的 Foxy 版本，本車是 Humble，不要照抄。

3. 關掉自動啟動的兩個終端機

🔊 旁白文字

開機自動開的 agent 和容器其實已經可以用了。但官方每一課的步驟都是從「自己啟動 agent」開始，如果自動開的那個 agent 還在跑，你再開一個就會打架，因為一台車同時只能有一個 agent 占用序列埠。所以我們先學會正確關掉它們。agent 那個視窗按 Ctrl 加 C 停止；Docker 那個視窗輸入 exit 離開。注意不要直接按視窗右上角的叉叉關掉，那樣 Docker 可能還在背景偷偷跑，之後就會出錯。

用 VNC 進到 Pi 5 桌面（B2），然後：

  1. 點一下 agent 終端機，按 Ctrl+C，等它回到 pi@...$ 提示字元。
  2. 點一下 Docker 終端機，輸入：
在車上 Docker 容器內
exit

關掉以後，手把就暫時不能控制車了（官方影片 hq0Zbi7BmFA 有提醒），這是正常的。

確認沒有殘留的 agent 容器：

在 Pi 5 主機
docker ps -a | grep microros/micro-ros-agent

沒有輸出＝乾淨。有輸出的話，記下第一欄的容器 ID，用 docker stop 停掉（見第 7 節）。

4. 手動啟動 agent，等 ESP32 連上

🔊 旁白文字

現在自己啟動翻譯官。在 Pi 5 的終端機輸入 sh 空格 波浪號斜線 start 底線 agent 底線 rpi5 點 sh。啟動後先看輸出：如果只印了兩三行就停住，代表 ESP32 還沒連上，這時按一下擴展板上的 Reset 鍵，大約十秒內就會開始刷出一大串訊息，那就是連上了。同時看看擴展板的 MCU 指示燈，從每秒慢閃一次，變成每三秒快閃兩次，就是正常狀態。

在 VNC 桌面開一個新的終端機（Pi 5 主機）：

在 Pi 5 主機
sh ~/start_agent_rpi5.sh

然後：

  1. 若車子電源還沒開 → 打開電源，ESP32 會自動連 agent。
  2. 若車子早就開著、agent 只輸出兩行就停住 → 按擴展板 Reset，等約 10 秒。
  3. agent 終端機開始大量輸出（建立 session、建立 topic 之類的訊息）＝連上。
判斷依據 沒連上 已連上
agent 終端機 只印兩行左右就停住 一直刷出多行訊息
MCU 指示燈 每 1 秒慢閃一次 每 3 秒快閃 2 次
⚠️ 注意

這個 agent 終端機要一直開著，不要關。整堂課 ESP32 都要靠它連進 ROS 2。也不要再開第二個 agent。

5. 進入容器，看到車的節點

🔊 旁白文字

翻譯官就位後，再開一個新的終端機，進入 ROS 2 的工作室。輸入 sh 空格 ros2 底線 humble 點 sh。注意要在家目錄執行，官方影片特別說，在別的資料夾執行會找不到檔案。進去之後，提示字元會變成 root 開頭，代表你現在在容器裡。輸入 ros2 node list，如果看到斜線 YB 底線 Car 底線 Node，恭喜，這就是 ESP32 小腦在 ROS 2 世界裡的身分，你第一次「看到」這台車了。

開第二個 Pi 5 終端機：

在 Pi 5 主機
cd ~
sh ros2_humble.sh

進入容器後（提示字元變成 root@...）：

在車上 Docker 容器內
ros2 node list

預期看到：

在車上 Docker 容器內（輸出範例）
/YB_Car_Node

如果手把自動控制還在（每次執行 ros2_humble.sh 都會跑 /root/1.sh），清單裡也可能多出手把相關的節點，例如 yahboom_joy、joy_node（官方影片 G7wb07OQIIQ 提到），這是正常的。

順便確認頻道號碼：

在車上 Docker 容器內
echo $ROS_DOMAIN_ID

應該是 20，和控制板一致。

ℹ️ 補充

官方文件有的寫 ./ros2_humble.sh、有的寫 sh ros2_humble.sh，兩者效果相同。本課程統一用 sh ros2_humble.sh。

💡 小提示

分辨你在哪一層，看提示字元就好：pi@... 是 Pi 5 主機，root@... 是容器內。docker、sh ~/start_agent_rpi5.sh、python3 config_robot.py 都在主機打；ros2 ... 都在容器內打。

6. 第二個終端機：用 docker exec 進同一個容器

🔊 旁白文字

後面的課常常要同時跑兩三個程式，例如一個終端機啟動底層，另一個啟動鍵盤控制。這時候有個新手最常犯的錯：再執行一次進入容器的腳本。這樣做其實是蓋了「另一間」新的工作室，跟第一間互不相通，而且又會多啟動一份手把控制。正確作法是先用 docker ps 查出第一間工作室的編號，再用 docker exec 走進「同一間」。編號每次都不一樣，要每次重新查。

開第三個 Pi 5 終端機：

在 Pi 5 主機
docker ps -a

輸出範例（ID 每次都不同）：

在 Pi 5 主機（輸出範例）
CONTAINER ID   IMAGE                                 ...   STATUS
ef0e1b7da319   yahboomtechnology/ros-humble:4.0.3    ...   Up 3 minutes
a1b2c3d4e5f6   microros/micro-ros-agent:humble       ...   Up 5 minutes

找 IMAGE 是 yahboomtechnology/ros-humble 那一行（不是 agent 那一行），用它的 ID 進入：

在 Pi 5 主機
docker exec -it ef0e1b7da319 /bin/bash
  • ef0e1b7da319 換成你看到的 ID；只要能唯一辨識，打前兩三個字也可以，例如 docker exec -it ef /bin/bash。
  • 進去後一樣是 root@...，執行 ros2 node list 結果應該和第一個終端機相同。
指令 結果
再執行一次 sh ros2_humble.sh 開一個新容器，又啟動一份手把控制 ✗
docker exec -it <ID> /bin/bash 在同一個容器開新終端機 ✓
在容器內 exit 離開；若是第一個終端機（docker run 那個），整個容器會停止並刪除
⚠️ 注意

因為 ros2_humble.sh 有 --rm，第一個終端機一 exit，整個容器就刪掉了，用 docker exec 開的其他終端機也會一起斷線。在容器裡新增的檔案（例如之後建的地圖）要先備份，官方作法是 docker cp 或 docker commit（W3 與 Docker 課有教）。

7. 出問題時怎麼辦

🔊 旁白文字

這一課是整個課程最常卡關的地方，所以出問題的表格特別長。看不到車的節點，九成是三個原因之一：agent 沒連上、頻道號碼不一致、或你其實不在容器裡。比較少見但很嚴重的是韌體被覆蓋，例如你玩過高級課的 ESP32 練習程式，車子就認不得了，這時要重新燒出廠韌體，再用 config 底線 robot 點 py 把參數寫回去。這兩個步驟放在表格後面，平常不需要做。

7.1 症狀對照表

7.2 清掉殘留的 agent 容器

agent 視窗被直接關掉時，Docker 會在背景繼續跑，之後再開 agent 會失敗（官方 FAQ 第 9 題）：

在 Pi 5 主機
docker ps -a | grep microros/micro-ros-agent
docker stop xxxxxxxxxx

xxxxxxxxxx 換成第一欄的容器 ID，然後重新 sh ~/start_agent_rpi5.sh。最簡單的萬用解是重開機。

⚠️ 注意

官方 FAQ 第 9 題接著給的重啟指令是 docker run ... microros/micro-ros-agent:humble udp4 --port 8090 -v4，那是 WiFi／UDP 版（給虛擬機／電腦版車），Pi 5 版要用序列版，也就是直接再跑一次 sh ~/start_agent_rpi5.sh。

7.3 重燒出廠韌體（只有韌體被覆蓋時才做）

出廠韌體已經燒好，沒有燒過別的程式就不用做這一步。需要時準備一台 Windows 電腦和一條能傳資料的 Type-C 線。流程是：裝序列埠驅動 → 用樂鑫（Espressif）燒錄工具把出廠 bin 檔燒到位址 0 → 用序列助手確認看到 hello Yahboom。

步驟（官方 03.Preparation/1、影片 WuLcfn4lkRo），全部在 Windows：

  1. 裝 CP2102 驅動：官方資料 Hardware related information → CP2102 serial port chip → CP2102-Windows driver file.zip，64 位元執行 CP210xVCPInstaller_x64.exe → Next → Finish。Type-C 線接擴展板 Serial 口到電腦，「裝置管理員 → 連接埠」出現 CP210x 即成功。
  2. 下載燒錄工具：Espressif Flash Download Tool（https://www.espressif.com.cn/zh-hans/support/download/other-tools），解壓後執行 flash_download_tool，晶片選 ESP32-S3。
  3. 設定：SPIDownload 選 microROS_Robot_Vx.x.x.bin（Vx.x.x 是版本號），位址填 0x0，勾選 DoNotChgBin，選 COM 埠，其他預設。
  4. 按 Start。沒有自動開始 → 按住 BOOT（文件寫 BOOT0）→ 按一下 Reset → 放開 BOOT。
  5. 出現藍色 FINISH → 斷電重開或按 Reset。
  6. 驗證：用官方附的 UartAssist.exe，選該 COM 埠，115200、8 資料位元、1 停止位元、無同位、無流控；按 Reset，輸出出現 hello Yahboom，下一行是韌體版本號。
⚠️ 注意

燒錄前要先停掉 Pi 5 上的 agent（它占著序列埠），而且燒錄時 Type-C 線是接到電腦，不是 Pi 5。燒完記得把線接回 Pi 5 的 USB 孔。

7.4 用 config_robot.py 寫回控制板參數

重燒韌體、或要改 ROS_DOMAIN_ID 時才需要（官方 03.Preparation/2、影片 MNMRW13Uzgs）。config_robot.py 放在 Pi 5 家目錄，最後一段決定要寫入的值，原始碼包裡是：

在 Pi 5 主機
if __name__ == '__main__':
    robot = MicroROS_Robot(port='/dev/ttyUSB0', debug=False)

    #robot.set_wifi_config("yahboom2", "yahboom890729")
    #robot.set_udp_config([192, 168, 2, 103], 8090)
    #robot.set_car_type(robot.CAR_TYPE_COMPUTER)
    robot.set_car_type(robot.CAR_TYPE_RPI5)
    robot.set_ros_domain_id(20)
    robot.set_ros_serial_baudrate(921600)
    robot.set_ros_namespace("")
    robot.set_pwm_servo_offset(1, 0)
    robot.set_pwm_servo_offset(2, 0)
    robot.set_motor_pid_parm(1, 0.2, 0.2)
    robot.set_imu_yaw_pid_parm(1, 0, 0.2)

重點：車型要是 robot.CAR_TYPE_RPI5（序列版）、ID 預設 20、namespace 空字串、其他保持預設。

執行步驟：

  1. agent 終端機 Ctrl+C、Docker 終端機 exit（序列埠要空出來）。
  2. 確認序列裝置：
在 Pi 5 主機
ls /dev/ttyUSB*
  1. 視需要編輯：vi ~/config_robot.py（一般不用改）。
  2. 短按擴展板 Reset，在 5 秒內（MCU 燈每 300 毫秒閃一次的設定狀態）執行：
在 Pi 5 主機
cd ~
python3 config_robot.py
  1. 程式會印出讀回來的 version、car_type、domain_id、ros_serial_baudrate、ros_namespace 等，檢查和你設定的一致。
  2. 再按一次 Reset，讓板子載入新設定，然後回到第 4 節重新啟動 agent。
⚠️ 注意

官方 FAQ 說 ROS_DOMAIN_ID 範圍是 0～101，但 config_robot.py 原始碼會把大於 100 的值強制改成 100。實際請用 0～100。改了控制板的 ID，容器的 ~/.bashrc 也要改成一樣；B4 會講到開機自啟的手把服務也要跟著改。

⚠️ 注意

多機課程（A3）會叫你把 set_ros_namespace 改成 robot1／robot2。回到單車課程前一定要改回 "" 並重新執行，否則所有話題都會變成 /robot1/...，本課程所有單車指令都會失效。
