多機協作：namespace、多車遙控與導航

⏱ 90 分鐘🚗 真車：是
🎯 學習目標
理解 namespace（命名空間）如何讓兩台車在同一個 ROS 網路裡互不打架，並用一支手把或一個鍵盤同時控制兩台車，再讓兩台車各自導航。
✅ 完成標準
兩台車設成 robot1、robot2 後，一支手把能同時控制兩台；做完後把兩台車都改回單車設定（namespace 空白），單車課程恢復正常。

1. 為什麼多機需要 namespace

🔊 旁白文字

想像一間教室有兩個同學都叫小明，老師喊小明站起來，兩個人會一起站起來。ROS 也一樣：兩台車的速度話題都叫 cmd vel，你發一個前進命令，兩台會一起動，而且兩台的光達資料也會混在同一個 scan 話題裡。解法是幫每台車加一個姓氏，叫做 namespace，命名空間。一台叫 robot1，一台叫 robot2，話題就變成 robot1 斜線 cmd vel 和 robot2 斜線 cmd vel，各聽各的。

1.1 兩個概念不要搞混

設定 作用 多機時怎麼設
ROS_DOMAIN_ID 「頻道」：同一個 ID 的節點才互相看得到 兩台車、電腦全部設一樣（預設 20）
namespace 「姓氏」：同一個頻道裡，用前綴區分是誰的話題 兩台車設不一樣：robot1、robot2

為什麼不乾脆給兩台車不同的 Domain ID？那樣兩台車就完全看不到對方，一支手把也沒辦法同時控制兩台。同頻道、不同姓氏才是多機協作的做法。

1.2 加了 namespace 之後話題長怎樣

單車（namespace 空白） 多機 robot1 多機 robot2
/cmd_vel /robot1/cmd_vel /robot2/cmd_vel
/scan /robot1/scan /robot2/scan
/odom_raw、/imu /robot1/odom_raw、/robot1/imu /robot2/odom_raw、/robot2/imu
/beep、/servo_s1、/servo_s2 /robot1/beep… /robot2/beep…

座標系（TF frame）也會加前綴，例如 robot1/base_link、robot1/odom、robot1/laser_frame，避免兩台車的 TF 樹打架。

ℹ️ 補充

namespace 是寫進 ESP32 韌體設定裡的（不是 Pi 5 上的檔案），所以 ESP32 一開機發布的話題就已經帶前綴。這也是為什麼做完多機課，一定要改回來，否則所有單車課程都會因為找不到 /cmd_vel、/scan 而失敗（見第 6 節）。

1.3 事前準備

  • 兩台 MicroROS-Pi5 車，電池都充飽。
  • 兩台車要連到同一個 WiFi 路由器。出廠時每台車各自開熱點 Micro_ros，兩台各開各的熱點是互相看不到的；請先照 B2 單元把兩台都設成連你家的 WiFi，並記下兩台的 IP。
  • 一支手把接收器（只要插在其中一台 Pi 5 上）。官方程式以 Yahboom 的「ROS Robot USB Wireless Controller」為例，其他手把按鍵對應可能不同。
  • 多機導航建議另備一台電腦跑 RViz（在 Pi 上開 RViz 會很卡），電腦設定見 A5。

2. 兩台車的設定：config_robot.py

🔊 旁白文字

設定 namespace 要用 Pi 5 家目錄裡的 config robot 點 py。它會透過序列線，把設定寫進 ESP32 控制板。有一個時間限制要記住：按下控制板的 Reset 後，只有前五秒是設定狀態，指示燈每零點三秒閃一次，要在這五秒內執行程式才寫得進去。寫好之後再按一次 Reset，新設定才會生效。兩台車各做一次，一台填 robot1，另一台填 robot2。

2.1 先停掉 agent 與容器

設定期間序列埠不能被 agent 佔用。在 VNC 桌面上：

  1. Docker 終端輸入 exit 離開容器。
  2. agent 終端按 Ctrl+C 關掉 agent。
在 Pi 5 主機（確認序列裝置還在）
ls /dev/ttyUSB*

2.2 修改 config_robot.py

config_robot.py 在 Pi 5 家目錄（/home/pi）。原始檔最後一段長這樣：

config_robot.py（原始碼節錄，在 Pi 5 主機的 /home/pi）
if __name__ == '__main__':
    robot = MicroROS_Robot(port='/dev/ttyUSB0', debug=False)

    #robot.set_wifi_config("yahboom2", "yahboom890729")
    #robot.set_udp_config([192, 168, 2, 103], 8090)
    #robot.set_car_type(robot.CAR_TYPE_COMPUTER)
    robot.set_car_type(robot.CAR_TYPE_RPI5)
    robot.set_ros_domain_id(20)
    robot.set_ros_serial_baudrate(921600)
    robot.set_ros_namespace("")
    robot.set_pwm_servo_offset(1, 0)
    robot.set_pwm_servo_offset(2, 0)
    robot.set_motor_pid_parm(1, 0.2, 0.2)
    robot.set_imu_yaw_pid_parm(1, 0, 0.2)

改之前先備份：

在 Pi 5 主機
cd ~
cp config_robot.py config_robot.py.bak
nano config_robot.py

只改一行：

車 把 robot.set_ros_namespace("") 改成
第一台 robot.set_ros_namespace("robot1")
第二台 robot.set_ros_namespace("robot2")

其他行（CAR_TYPE_RPI5、set_ros_domain_id(20)、鮑率 921600、PID）都不要動。兩台的 set_ros_domain_id 必須相同。

2.3 寫入板子

  1. 短按控制板 Reset，看 MCU 指示燈每 300 毫秒閃一次（設定狀態，約 5 秒）。
  2. 在這 5 秒內執行：
在 Pi 5 主機
cd ~
sudo python3 config_robot.py
  1. 程式最後會印出目前所有韌體參數（print_all_firmware_parm()），確認 ros_namespace: robot1（或 robot2）、domain_id: 20。
  2. 程式提示 Please reboot the device to take effect → 再按一次 Reset，讓板子載入新設定。
⚠️ 注意

官方文件〈控制板設定參數〉寫 python3 config_robot.py，多機課程寫 sudo python3 config_robot.py，兩種寫法並存；如果不加 sudo 出現序列埠權限錯誤，就加 sudo。另外 FAQ 說 ROS_DOMAIN_ID 範圍是 0～101，但 config_robot.py 原始碼實際會把大於 100 的值壓成 100，所以請用 0～100 之間的數字。

2.4 確認兩台都上線

兩台各自啟動 agent 與容器：

在 Pi 5 主機（兩台都做）
sh ~/start_agent_rpi5.sh

按控制板 Reset 等連上後，另開終端：

在 Pi 5 主機（兩台都做）
sh ros2_humble.sh

任選一台的容器：

在車上 Docker 容器內（任一台）
ros2 node list
ros2 topic list

應該看到兩組話題：/robot1/cmd_vel、/robot1/scan…以及 /robot2/cmd_vel、/robot2/scan…。只看到自己那台，見第 7 節。

3. 一支手把控兩台車

🔊 旁白文字

手把接收器只要插在其中一台 Pi 上。在那台車的容器裡開兩個節點：一個是 joy node，負責讀手把按鍵；另一個是 Yahboom 寫的多機手把程式，它把同一份速度命令同時發給 robot1 和 robot2。所以你推一下搖桿，兩台車會做一模一樣的動作，像在跳整齊的雙人舞。

在車上 Docker 容器內（插著手把接收器的那台；兩行各開一個終端，用 docker exec 進同一個容器）
ros2 run joy joy_node
ros2 run yahboomcar_multi multi_joy_ctrl
在車上 Docker 容器內（看節點關係圖）
ros2 run rqt_graph rqt_graph

multi_joy_ctrl（原始碼 yahboomcar_multi/multi_yahboom_joy.py）做的事：

  • 訂閱 joy（手把按鍵）
  • 發布 /robot1/cmd_vel、/robot2/cmd_vel（速度）
  • 發布 /robot1/beep、/robot2/beep（蜂鳴器）
  • 發布 /robot1/servo_s1、robot2/servo_s1、/robot1/servo_s2、/robot2/servo_s2（雲台）
  • 發布 JoyState（手把是否接管）

按鍵與單車手把（B4）相同；R1 要先按下，手把才會輸出速度。

⚠️ 注意

原始碼裡 robot2/servo_s1 少了開頭的 /（其他都有）。在預設的根命名空間下兩者結果相同，但這看起來是原廠的小瑕疵；如果你以後把這個節點放進某個 namespace 執行，robot2 的雲台 S1 可能會收不到。原始碼也預留了 /robot3/cmd_vel、/robot3/beep，代表程式設計上可以擴充到第三台。

⚠️ 注意

車子開機時，容器會自動啟動單車版的手把程式（/root/1.sh）。它發的是沒有前綴的 /cmd_vel，在多機設定下沒有車會聽，但仍會佔用手把。如果多機手把沒反應，先照 B4 單元關掉自啟動的手把行程，再開上面兩個節點。

4. 多機鍵盤控制

🔊 旁白文字

沒有手把也沒關係，鍵盤一樣能同時控制兩台。這個鍵盤程式會開兩個發布者，分別送到 robot1 和 robot2 的速度話題，按鍵和單車鍵盤控制一模一樣：i 前進、逗號後退、j 和 l 原地轉、s 停車。記得要先用滑鼠點一下終端機視窗，鍵盤輸入才會進得去。

在車上 Docker 容器內（任一台）
ros2 run yahboomcar_multi multi_keyboard_ctrl
鍵 動作
i 前進
, 後退
j / l 原地左轉 / 右轉
q / z 線速度與角速度一起加大 / 減小
w / x 只調線速度
e / c 只調角速度
s 或空白鍵 停車
Ctrl+C 離開

原始碼重點（multi_yahboom_keyboard.py）：建立 /robot1/cmd_vel、/robot2/cmd_vel 兩個 Twist 發布者；每 0.1 秒讀一次鍵盤；連續沒有按鍵超過 4 次就自動歸零，所以放開按鍵車子會自己停。超過速度上限會印 Linear speed limit reached!。

💡 小提示

鍵盤程式會把終端切成 raw 模式。如果程式異常結束後終端打字怪怪的，輸入 reset 按 Enter 就會恢復。

5. 多機導航

🔊 旁白文字

多機導航是把上一課的 Nav2 複製成兩份，各自加上 robot1 和 robot2 的姓氏。順序是：先在電腦開多機版 RViz 和地圖伺服器，再在兩台車上各自啟動底層、AMCL 定位、導航。RViz 工具列上有四個按鈕，前兩個管 robot1 的初始位置和目標，後兩個管 robot2 的。紅色是 robot1，藍色是 robot2，規劃出的路線則一黃一綠。

5.1 事前準備

  • 一張兩台車都在裡面的地圖（用 A1 建好）。
  • 兩台車都完成第 2 節設定，並各自啟動 agent、進容器。
  • 先在任一台容器確認兩車節點都在：
在車上 Docker 容器內
ros2 node list

5.2 RViz 與地圖（官方建議在電腦／虛擬機執行）

在電腦的 Humble 環境（官方虛擬機，或 A5 的 Docker ros:humble 容器）
ros2 launch yahboomcar_nav multi_nav_display_launch.py
在電腦的 Humble 環境（另一終端）
ros2 launch yahboomcar_multi map_server_launch.py

電腦上要有 Yahboom 的 yahboomcar_nav 與 yahboomcar_multi 套件才跑得起來；如果電腦端還沒準備好，這兩行也可以在其中一台車的容器裡執行（RViz 會比較卡）。地圖有時載入失敗，按 Ctrl+C 重跑即可。

RViz 工具列：

按鈕 作用
【1】 robot1 設初始位置
【2】 robot1 設目標點
【3】 robot2 設初始位置
【4】 robot2 設目標點
⚠️ 注意

官方文件說 map_server_launch.py 預設載入 /root/yahboomcar_ws/src/yahboomcar_multi/maps/yahboom_map.yaml，但原始碼實際寫的是：

yahboomcar_multi/launch/map_server_launch.py（原始碼節錄）
map_file = os.path.join('/root/yahboomcar_ws/src/yahboomcar_nav','maps','yahboom_map.yaml')

也就是讀 yahboomcar_nav/maps 底下的 yahboom_map.yaml。所以最簡單的做法：把你的地圖照 A1 的方式放成 /root/yahboomcar_ws/src/yahboomcar_nav/maps/yahboom_map.yaml（以車上實際行為為準，需實車確認）。官方文件這一節的章節編號也寫錯（寫成 4.2），指令順序本身沒問題。

5.3 兩台車各自啟動底層

在車上 Docker 容器內（robot1 那台）
ros2 launch yahboomcar_multi yahboomcar_bringup_multi.launch.xml robot_name:=robot1
在車上 Docker 容器內（robot2 那台）
ros2 launch yahboomcar_multi yahboomcar_bringup_multi.launch.xml robot_name:=robot2

這個 XML launch 用 <push-ros-namespace namespace="$(var robot_name)"/> 把群組內所有節點加上前綴，並啟動 imu_filter_madgwick_node、ekf_filter_node（參數檔 param/ekf_$(var robot_name).yaml）、IMU 靜態 TF，以及 description_multi_$(var robot_name).launch.py（帶前綴的 URDF）。

5.4 兩台車各自啟動 AMCL

在車上 Docker 容器內（robot1 那台，另一終端）
ros2 launch yahboomcar_multi robot1_amcl_launch.py
在車上 Docker 容器內（robot2 那台，另一終端）
ros2 launch yahboomcar_multi robot2_amcl_launch.py

出現 Please set the initial pose... 之後，在 RViz 用【1】、【3】分別替兩台車設初始位置（點擊拖曳）。光達點和牆大致重合就是準的。

5.5 兩台車各自啟動導航

在車上 Docker 容器內（robot1 那台，另一終端）
ros2 launch yahboomcar_multi robot1_navigation_dwb_launch.py
在車上 Docker 容器內（robot2 那台，另一終端）
ros2 launch yahboomcar_multi robot2_navigation_dwb_launch.py

出現 Creating bond timer... 代表載入完成。接著用【2】、【4】分別給兩台車目標點。黃線是 robot1 的路徑、綠線是 robot2 的路徑。

ℹ️ 補充

robot1_navigation_dwb_launch.py 使用 yahboomcar_nav/params/robot1_nav_params.yaml，並啟動 stop_robot1_car 節點，Ctrl+C 時只對 robot1 送停車。想加第三台車要複製一整套 URDF、EKF、AMCL、導航參數與 launch，再改 multi_nav.rviz 並 colcon build，工程不小，建議兩台玩熟了再挑戰。

6. 做完一定要改回單車設定

🔊 旁白文字

這一節最重要，請一定要做。多機的 namespace 是寫在 ESP32 板子裡的，你關機再開機它還是 robot1。之後你回去練建圖、導航、避障，所有程式找的都是沒有前綴的 cmd vel 和 scan，車子會完全沒反應，看起來像壞掉，其實只是姓氏還沒改回來。兩台車都要改回空白，再重新寫入一次。

步驟和第 2 節一樣，只是把 namespace 改回空字串：

  1. 容器內 exit、agent 終端 Ctrl+C。
  2. 還原備份（或手動把那一行改回 robot.set_ros_namespace("")）：
在 Pi 5 主機（兩台都做）
cd ~
cp config_robot.py.bak config_robot.py
grep set_ros_namespace config_robot.py

確認印出的是 robot.set_ros_namespace("")。

  1. 短按 Reset，5 秒內執行：
在 Pi 5 主機（兩台都做）
sudo python3 config_robot.py
  1. 確認印出 ros_namespace: 後面是空的，再按一次 Reset。
  2. 重開 agent 與容器，ros2 topic list 應該又看到沒有前綴的 /cmd_vel、/scan，ros2 node list 看到 /YB_Car_Node。
⚠️ 注意

只改 Pi 5 上的 config_robot.py 檔案不夠，一定要在設定狀態下執行它，把設定寫進 ESP32，再按 Reset。忘了這一步是「多機課做完，其他課全部失效」的頭號原因。

7. 出問題時怎麼辦

🔊 旁白文字

多機最常卡在三件事：兩台車看不到彼此、設定沒寫進板子、做完忘了改回來。先用 ros2 topic list 看看話題有沒有帶前綴、有沒有兩組，就能很快判斷問題在哪一層。網路層的問題，例如兩台車不在同一個路由器、Domain ID 不同，請搭配 A5 單元一起排查。

症狀 最可能的原因 怎麼做
ros2 topic list 只看到自己那台的話題 兩台不在同一 WiFi（各開各的熱點）或 Domain ID 不同 兩台都連同一個路由器；確認兩台 set_ros_domain_id 相同、容器 ~/.bashrc 的 ROS_DOMAIN_ID 相同
話題沒有 /robot1/ 前綴 namespace 沒寫進板子 Reset 後 5 秒內重跑 sudo python3 config_robot.py，再按 Reset
兩台都是 /robot1/... 第二台忘了改成 robot2 第二台改 set_ros_namespace("robot2") 重寫
執行 config_robot.py 沒反應或讀到奇怪的值 超過 5 秒設定窗口，或 agent 還佔著序列埠 先 Ctrl+C 關 agent；按 Reset 後立刻執行
手把推了兩台都不動 沒按 R1、自啟動手把程式搶手把、接收器插錯台 按 R1；關掉 /root/1.sh 的自啟動行程；接收器要插在跑 joy_node 的那台
鍵盤按了沒反應 終端視窗沒有被選取 用滑鼠點一下鍵盤程式的終端
一直沒出現 Please set the initial pose... 時間戳不同步 按車子 Reset 讓它重新連 agent，多試幾次
地圖沒出來 map_server_launch.py 讀的是 yahboomcar_nav/maps/yahboom_map.yaml 確認容器內那個路徑有你的地圖；Ctrl+C 重跑
Pi 上的 RViz 很卡 Pi 5 同時跑導航與繪圖太吃力 RViz 改在電腦開（A5）
多機課做完，單車課全部沒反應 namespace 還是 robot1／robot2 照第 6 節改回空白並重新寫入
