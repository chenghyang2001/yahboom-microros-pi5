初級 B5

讀懂車的話題：手動發 /cmd_vel、聽 /imu、/odom_raw、/scan

⏱ 1 小時🚗 真車：是
🎯 學習目標
用 ros2 node／topic 系列指令看懂車子「說什麼、聽什麼」，親手發布指令讓車轉圈、蜂鳴器響、雲台轉動，並分辨 /odom_raw 與 /odom
✅ 完成標準
用 ros2 topic pub /cmd_vel 讓車原地轉一圈並停下、用 /beep 讓蜂鳴器叫一聲、用 /servo_s1 與 /servo_s2 轉動雲台，並用 ros2 topic hz 量出 /scan、/imu、/odom_raw 的頻率

1. 節點與話題：車子的「嘴巴」和「耳朵」

🔊 旁白文字

上一課我們用三種方式開車，但都是別人寫好的程式。這一課要拿掉中間人，直接跟車子對話。在 ROS 2 裡，每個會做事的程式叫節點，節點之間用話題傳訊息。話題像是廣播電台的頻道：發布者對著頻道說話，訂閱者打開收音機收聽。車上的 ESP32 是一個叫 YB 底線 Car 底線 Node 的節點，它有幾個「耳朵」，聽速度、蜂鳴器、雲台的指令；也有幾個「嘴巴」，不停播報陀螺儀、輪子里程和光達的資料。

先照 B3 的流程準備好（之後每一課都一樣，不再重複）：

  1. VNC 桌面：關掉自動開的 agent 與 Docker 終端機。
  2. sh ~/start_agent_rpi5.sh，按 Reset 等連上。
  3. 新終端機 sh ros2_humble.sh 進容器。
  4. 容器內暫時關掉手把（B4 第 3.1 節），避免它也在發速度。
在車上 Docker 容器內
ros2 node list
ros2 node info /YB_Car_Node

ros2 node info 會列出這個節點的 Subscribers（耳朵）和 Publishers（嘴巴）。依官方文件整理：

方向 話題 訊息型別 用途
訂閱（車聽） /cmd_vel geometry_msgs/msg/Twist 車速
訂閱（車聽） /beep std_msgs/msg/UInt16 蜂鳴器
訂閱（車聽） /servo_s1 std_msgs/msg/Int32 下方舵機（左右），範圍 [−90, 90]
訂閱（車聽） /servo_s2 std_msgs/msg/Int32 上方舵機（上下），範圍 [−90, 20]
發布（車說） /imu sensor_msgs/msg/Imu 六軸慣性測量單元
發布（車說） /odom_raw nav_msgs/msg/Odometry 輪子算出來的原始里程
發布（車說） /scan sensor_msgs/msg/LaserScan MS200 光達
⚠️ 注意

官方 05-1 文件列「發布話題」時寫的是 /odom，但同一頁查資料用的指令是 ros2 topic echo /odom_raw，而 05-4 也說 /odom 是 EKF 融合後才產生的。車本體發布的應該是 /odom_raw，請用 ros2 node info /YB_Car_Node 的實際輸出為準（需實車確認）。另外 /imu、/odom_raw、/scan 的型別是依 ROS 慣例補上，文件只明寫了 /beep、/cmd_vel、/servo_s1、/servo_s2 的型別。

2. 五個必學的 topic 指令

🔊 旁白文字

ROS 2 有一組以 ros2 topic 開頭的指令，就像收音機上的旋鈕。list 列出所有頻道；info 看某個頻道的訊息型別和有幾個人在收聽；echo 把頻道內容印出來；hz 量它每秒播幾次；pub 則是自己拿起麥克風對頻道說話。前四個只是「聽」，完全安全，可以隨便試。最後一個 pub 會真的讓車動起來，所以下一節會特別小心地用。

在車上 Docker 容器內
ros2 topic list
ros2 topic list -t
ros2 topic info /cmd_vel
ros2 interface show geometry_msgs/msg/Twist
指令 做什麼
ros2 topic list 列出所有話題；-t 同時顯示型別
ros2 topic info <話題> 型別、發布者數量、訂閱者數量；加 -v 看是哪些節點
ros2 topic echo <話題> 持續印出內容，Ctrl+C 停止
ros2 topic hz <話題> 量每秒幾筆，Ctrl+C 停止
ros2 topic pub <話題> <型別> <內容> 自己發布訊息
ros2 interface show <型別> 看訊息有哪些欄位

ros2 interface show 的輸出（簡化示意，實際還會展開每個 Vector3 的 x、y、z）：

在車上 Docker 容器內（輸出範例）
Vector3  linear     # 線速度 x, y, z（公尺／秒）
Vector3  angular    # 角速度 x, y, z（弧度／秒）

這台四輪車只用得到兩個數字：linear.x（前正後負）和 angular.z（左轉為正、右轉為負）。

💡 小提示

ros2 topic info /cmd_vel -v 可以看到有誰在發布 /cmd_vel。如果發布者不只一個，就代表有兩個程式在搶方向盤，這是 B4 那張問題表的「正式查法」。

3. 聽車子說話：echo 與 hz

🔊 旁白文字

先來聽聽車子在說什麼。光達的資料量很大，一次會印出幾百個數字，所以我們先只看一筆。再來看陀螺儀：把車子拿起來轉一轉，你會看到角速度的數字跟著變。最後看輪子里程：用手推車子往前一點，位置 x 會變大。用 hz 量一下每個話題的頻率，就知道車子每秒回報幾次，這個數字之後寫程式時很重要。

光達 /scan：

在車上 Docker 容器內
ros2 topic echo /scan --once --no-arr
ros2 topic echo /scan --once
  • --once 只印一筆就結束；--no-arr 把長陣列省略，先看結構。
  • 重點欄位：angle_min／angle_max（掃描角度範圍，弧度）、range_min／range_max（量得到的最近／最遠距離，公尺）、ranges（每個角度的距離陣列）。
  • 用手掌靠近光達，再印一次，ranges 裡會出現比較小的數字。

陀螺儀 /imu：

在車上 Docker 容器內
ros2 topic echo /imu
  • angular_velocity.z：繞垂直軸旋轉的速度，原地轉車時會變。
  • linear_acceleration.z：靜止時約 9.8（重力加速度）。
  • orientation：姿態四元數（W4 學過的旋轉表示法）。

輪子里程 /odom_raw：

在車上 Docker 容器內
ros2 topic echo /odom_raw
  • pose.pose.position.x／y：從開機到現在，輪子「以為」自己走到哪。
  • twist.twist.linear.x／angular.z：目前速度。
  • 用手把車往前推 10 公分，position.x 應該增加約 0.1。

量頻率：

在車上 Docker 容器內
ros2 topic hz /scan
ros2 topic hz /imu
ros2 topic hz /odom_raw

把結果記在下表（官方沒有寫出廠頻率，以下參考值來自 ESP32 練習範例與光達規格，以你量到的為準）：

話題 參考頻率 你量到
/scan 約 10 Hz（MS200 掃描頻率 10 Hz） ____ Hz
/imu 約 20 Hz（練習範例值） ____ Hz
/odom_raw 約 20 Hz（練習範例值） ____ Hz

4. 對車子說話：/cmd_vel 讓車原地轉一圈

🔊 旁白文字

現在拿起麥克風。原地轉圈只要給角速度、線速度給零。角速度的單位是弧度每秒，轉一整圈是兩個派，大約六點二八弧度，所以如果用每秒零點五弧度，大約十二點六秒會轉一圈。有一件事一定要記住：ros2 topic pub 會一直重複發送，按 Ctrl 加 C 才會停止發送，但車子可能還記得最後一個速度繼續轉。所以每次都要再發一筆全部是零的指令，確定車子停下來。官方範例用的零點五公尺每秒在室內偏快，我們先用小一點的數字。

安全準備：車放地上、周圍淨空 1 公尺；另一隻手隨時準備按 Ctrl+C；記住停車指令放在哪。

官方範例（線速度 0.5、角速度 0.2，會一邊前進一邊左轉，室內偏快）：

在車上 Docker 容器內
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.5, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.2}}"

原地左轉一圈（本課作業，數值是建議值）：

在車上 Docker 容器內
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.5}}"
  • -r 10：每秒發 10 次（預設是每秒 1 次）。
  • 看著車頭，轉回原本方向時（約 12～13 秒）按 Ctrl+C。

停車（每次都要發）：

在車上 Docker 容器內
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"

官方文件的停車寫法是不加 --once（持續每秒發 0，按 Ctrl+C 結束），兩種都可以。

⚠️ 注意

車子 Ctrl+C 之後會不會自己停，取決於 ESP32 韌體有沒有「逾時自動停車」的設計，官方文件沒寫（需實車確認）。在確認之前，一律當成不會自己停，每次都補發停車指令。

💡 小提示

實際轉的角度可能不剛好一圈：命令是 0.5 rad/s，不代表輪子真的轉出 0.5 rad/s（打滑、地面材質）。這個誤差正是 B6 角速度校準要處理的問題。可以再開一個終端機 ros2 topic echo /odom_raw 對照車子「以為」自己轉了多少。

5. 蜂鳴器與雲台舵機

🔊 旁白文字

接著玩兩個比較安全的「耳朵」。蜂鳴器聽的是 beep 話題，型別是無號十六位元整數，送一就開始響，送零就停。雲台有兩顆舵機，S1 在下面管左右，範圍負九十到九十度；S2 在上面管上下，範圍負九十到二十度。超出範圍時舵機不會報錯，只是不轉，所以如果你送了一百度發現沒反應，先檢查數字有沒有超過範圍。

蜂鳴器 /beep：

在車上 Docker 容器內
ros2 topic info /beep
ros2 topic pub /beep std_msgs/msg/UInt16 "data: 1"

聽到響聲後 Ctrl+C，再關掉：

在車上 Docker 容器內
ros2 topic pub /beep std_msgs/msg/UInt16 "data: 0"

「叫一聲就停」的小技巧：用 --once 先送 1、馬上再送 0。

在車上 Docker 容器內
ros2 topic pub --once /beep std_msgs/msg/UInt16 "data: 1"
ros2 topic pub --once /beep std_msgs/msg/UInt16 "data: 0"
ℹ️ 補充

ESP32 練習範例裡，/beep 的值大於等於 10 時代表「響幾毫秒後自動停」，例如 data: 100 響 0.1 秒。出廠韌體是否相同官方沒寫（需實車確認），可以試試 ros2 topic pub --once /beep std_msgs/msg/UInt16 "data: 100"。

雲台舵機：

在車上 Docker 容器內
ros2 topic pub /servo_s1 std_msgs/msg/Int32 "data: 30"
ros2 topic pub /servo_s2 std_msgs/msg/Int32 "data: -30"
舵機 位置 範圍（度） 試試看
S1 下方，左右轉 −90～90 0、30、-60
S2 上方，上下轉 −90～20 0、-30、20

把兩顆都轉到 0，就是 B1 說的「中間位置」，可以趁這時候把攝影機支架鎖正。

ℹ️ 補充

手把節點啟動時會先把 S1 設成 0、S2 設成 −60（原始碼 yahboom_joy.py 的初始值），所以開機後鏡頭常是朝下的，這是正常的。

6. /imu、/odom_raw、/odom 與 rqt_graph

🔊 旁白文字

最後釐清三個很像的名字。斜線 imu 是陀螺儀的原始資料；斜線 odom 底線 raw 是只靠輪子算的里程，輪子打滑它也不知道，會越走越偏；斜線 odom 則是把前兩者融合以後比較準的里程，要等下一課啟動底層程式才會出現。用 rqt graph 可以把節點和話題畫成一張圖，誰對誰說話一目了然。這是圖形程式，要在 VNC 桌面的終端機執行。

話題 誰發布 內容 什麼時候有
/imu /YB_Car_Node（ESP32） 原始角速度、加速度 agent 連上就有
/odom_raw /YB_Car_Node（ESP32） 純輪速里程，會累積誤差 agent 連上就有
/imu/data IMU 濾波節點（Pi 5） 濾波後的 IMU 啟動 yahboomcar_bringup_launch.py 後
/odom /ekf_filter_node（Pi 5） 融合 /imu/data ＋ /odom_raw 同上（B6 主題）

現在（還沒啟動 bringup）檢查一下：

在車上 Docker 容器內
ros2 topic list | grep odom

應該只看到 /odom_raw；若也看到 /odom，表示有其他程式在跑（例如 B4 留下的 bringup）。

節點關係圖（在 VNC 桌面的終端機，用 docker exec 進同一容器後執行）：

在車上 Docker 容器內
ros2 run rqt_graph rqt_graph

一開始沒顯示的話，左上角下拉選 Nodes/Topics (all)，再按左上角的重新整理鈕。你會看到 /YB_Car_Node 和它連出去的話題；如果手把節點還在，也會看到 joy_node → /joy → yahboom_joy → /cmd_vel → /YB_Car_Node 這條線。

ℹ️ 補充

這台車的 /scan 也是 ESP32 發布的：光達接在擴展板上，由 ESP32 讀資料再轉成 ROS 話題，所以光達沒資料時要先查 agent，不是查 Pi 5 的 USB。

7. 出問題時怎麼辦

🔊 旁白文字

這一課的問題多半跟「型別打錯」或「格式打錯」有關。ROS 2 對大小寫和空格很挑剔，例如 data 冒號後面一定要有空格，型別名稱中間要有 msg。如果指令沒報錯、車卻沒反應，就用 topic info 看訂閱者數量，零就代表車子根本沒在聽，回去檢查 agent。發完速度車子停不下來，馬上補發全零的停車指令，必要時直接關擴展板電源。

症狀 可能原因 解法
ros2 topic list 只有 /parameter_events、/rosout agent 沒連上或 ID 不一致 回 B3 第 7 節
The passed message type is invalid 型別打錯 要寫完整：geometry_msgs/msg/Twist、std_msgs/msg/UInt16、std_msgs/msg/Int32
Failed to populate field 或 YAML 錯誤 格式打錯 "data: 1" 冒號後有空格；Twist 的大括號、逗號成對；整段用雙引號包起來
pub 沒報錯但車不動 車沒訂閱（Subscription count: 0）；電量低 ros2 topic info /cmd_vel 看訂閱者；檢查 agent 與電池
車子忽轉忽停、抖動 手把或鍵盤節點也在發 /cmd_vel ros2 topic info /cmd_vel -v 看發布者；關掉多的那個
Ctrl+C 後車子繼續轉 最後一筆速度還有效 立刻發 --once 全零停車指令；緊急時關擴展板電源
舵機不轉 數值超出範圍 S1：−90～90；S2：−90～20
蜂鳴器一直響 送了 1 沒送 0 ros2 topic pub --once /beep std_msgs/msg/UInt16 "data: 0"
ros2 topic echo /scan 洗版看不清楚 陣列太長 加 --once --no-arr
ros2 topic hz 一直沒有數字 該話題沒人發布 ros2 topic info 確認 Publisher count
rqt_graph 視窗打不開 在 SSH 終端機執行（沒有圖形） 改在 VNC 桌面的終端機執行
找不到 /odom 還沒啟動 bringup 正常；B6 會啟動
