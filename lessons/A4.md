## 1. 為什麼要學韌體開發，以及最重要的警告

> 🔊 前面的單元，我們都在 Pi 5 這個大腦上寫程式；這一課要往下走一層，改寫 ESP32 這個小腦。ESP32 負責每十毫秒量一次輪子轉速、跑馬達控制、讀陀螺儀和光達，這些要準時的事交給它最穩。它跑的是 micro-ROS，一種瘦身版的 ROS 2，讓只有幾百 KB 記憶體的小晶片也能當 ROS 節點。開始前請記住一件事：把練習程式燒進車上的控制板，會蓋掉出廠韌體，車子會暫時不能動。

### 1.1 三層關係複習

```text title="micro-ROS 資料路徑"
 ESP32-S3（你寫的韌體，rclc）       Pi 5 或電腦                    其他 ROS 2 節點
┌────────────────────┐  序列 /dev/ttyUSB0 @921600  ┌──────────────────┐  DDS  ┌─────────────┐
│ node / publisher / │ ═══ 或 WiFi UDP:8090 ═════▶ │ micro-ROS agent  │ ════▶ │ ros2 topic  │
│ subscriber / timer │ ◀══════════════════════════ │（翻譯官，Docker） │ ◀════ │ rviz / nav2 │
└────────────────────┘                             └──────────────────┘       └─────────────┘
```

- **micro-ROS**：ROS 2 給微控制器（MCU）用的版本。MCU 上用 C 語言的 **rclc** 函式庫寫程式。
- **micro-ROS agent**：MCU 說的是精簡協定（Micro XRCE-DDS），agent 把它翻譯成一般 ROS 2 的 DDS。**agent 沒開，ESP32 就一直卡在 `Connecting agent`。**
- 車子出廠走**序列**（Pi 5 的 `sh ~/start_agent_rpi5.sh`）；這一課的練習走 **WiFi UDP**（埠 `8090`）。

### 1.2 硬體選擇：強烈建議另買一片 ESP32-S3 開發板

| 練習對象 | 優點 | 風險 |
| --- | --- | --- |
| **ESP32-S3 開發板**（DevKitC 類，建議） | 不影響車子；燒錯也沒關係 | LED、按鍵腳位和車上控制板不同，要自己改 GPIO |
| 車上的 microROS 控制板 | 馬達、IMU、光達都現成 | **會覆蓋出廠韌體**；馬達類程式燒完輪子會立刻轉 |

板子一定要選 **ESP32-S3**（官方一律 `idf.py set-target esp32s3`）。

:::warn
**燒練習程式會蓋掉出廠韌體。** 出廠韌體 `microROS_Robot_V2.0.0.bin` 只有 .bin、沒有原始碼；燒了練習程式之後，車子就不再是 `/YB_Car_Node`，所有遙控、建圖、導航都不能用，直到你照第 7 節燒回出廠韌體並用 `config_robot.py` 重設。馬達類練習（官方 16-7、16-9、16-16、17-6、17-7）**燒完輪子就會轉，一定先把車架空**。
:::

## 2. 安裝 ESP-IDF v5.1.2（在電腦 WSL）

> 🔊 ESP-IDF 是 ESP32 原廠的開發工具包，裡面有編譯器、燒錄工具和設定介面。官方教材用 v5.1.2 版，我們照用，不要裝最新版，因為 micro-ROS 元件和範例都是對這一版測過的。安裝分四步：裝相依套件、下載原始碼、只裝 esp32s3 的工具鏈、最後啟用環境。第四步每開一個新終端都要重做一次，忘了就會找不到 idf 點 py 指令。

### 2.1 安裝

官方文件以 Ubuntu 為例，在電腦的 WSL 裡照做即可：

```bash title="在電腦 WSL（Jazzy）"
# 1) 相依套件
sudo apt-get install git wget flex bison gperf python3 python3-pip python3-venv cmake ninja-build ccache libffi-dev libssl-dev dfu-util libusb-1.0-0

# 2) 下載 ESP-IDF v5.1.2
mkdir -p ~/esp
cd ~/esp
git clone -b v5.1.2 --recursive https://github.com/espressif/esp-idf.git

# 3) 只裝 esp32s3 工具鏈
cd esp-idf
./install.sh esp32s3

# 4) 啟用環境（每開一個新終端都要做！）
source ~/esp/esp-idf/export.sh
```

:::info
官方另有預先裝好 ESP-IDF 與 micro-ROS 元件的 Ubuntu 虛擬機（`21. Virtual machine file compression package`），裡面的範例在 `~/esp/Samples/esp32_samples/`、`~/esp/Samples/microros_samples/`。用虛擬機可以省下安裝時間；本課以自己在 WSL 安裝為主。WSL 是 Ubuntu 24.04、Python 3.12，與官方測試的環境不同，`install.sh` 若出現 Python 套件錯誤請記下完整訊息再排查（需實機確認）。
:::

### 2.2 讓 WSL 看得到 USB 序列埠

WSL 預設看不到 USB 裝置，要用 Windows 的 **usbipd-win** 把板子「借」給 WSL：

```powershell title="在 Windows（系統管理員 PowerShell）"
winget install usbipd
usbipd list
usbipd bind --busid <BUSID>
usbipd attach --wsl --busid <BUSID>
```

`<BUSID>` 換成 `usbipd list` 裡 CP210x 或 USB JTAG/serial 那一列的編號（例如 `2-3`）。每次重插板子都要再 `attach` 一次。

```bash title="在電腦 WSL（Jazzy）"
ls /dev/ttyUSB* /dev/ttyACM*
sudo usermod -aG dialout $USER
```

- 車上控制板（CP2102 晶片）通常出現為 `/dev/ttyUSB0`；開發板接「原生 USB」孔時可能是 `/dev/ttyACM0`。
- 加入 `dialout` 群組後要**關掉 WSL 終端重開**才生效，否則燒錄會出現權限錯誤。

## 3. 第一個程式：build、flash、monitor 與 menuconfig

> 🔊 第一個程式先不碰 ROS，只燒官方的 hello world，確認整條工具鏈是通的。三個最常用的指令要記住：build 是編譯，flash 是燒進板子，monitor 是打開序列埠看板子印出的訊息。三個可以串成一行一次做完。離開監看畫面要按 Ctrl 加右中括號，不是 Ctrl C。接著用 menuconfig 這個文字選單，把 Flash 大小、CPU 速度這些硬體設定調成和車上控制板一樣。

### 3.1 hello_world

```bash title="在電腦 WSL（Jazzy）"
source ~/esp/esp-idf/export.sh
cd ~/esp/esp-idf/examples/get-started/hello_world
idf.py set-target esp32s3
idf.py build
idf.py flash -p /dev/ttyUSB0
idf.py monitor -p /dev/ttyUSB0
```

| 指令 | 作用 |
| --- | --- |
| `idf.py set-target esp32s3` | 指定晶片，每個新專案做一次 |
| `idf.py build` | 編譯，產出 `build/*.bin` |
| `idf.py flash` | 燒錄（只有一個序列裝置時可省略 `-p`） |
| `idf.py monitor` | 看序列輸出，**離開按 Ctrl+]** |
| `idf.py build flash monitor` | 一次做完（官方每課都用這行） |

燒錄進度到 100% 並顯示 `Done` 就是成功。燒錄不會自動開始時，手動進入燒錄模式：**按住 BOOT0 → 按一下 Reset → 放開 BOOT0**。

### 3.2 menuconfig：官方推薦設定

```bash title="在電腦 WSL（Jazzy）"
mkdir -p ~/esp/Samples/esp32_samples
cd ~/esp/Samples/esp32_samples
idf.py create-project main
cd main
idf.py set-target esp32s3
idf.py menuconfig
```

| 選單位置 | 設定 |
| --- | --- |
| `Serial flasher config` | Flash size 改 **4MB**，勾選 `Detect flash size when flashing bootloader` |
| `Component config` → `ESP PSRAM` | 啟用 `Support for external, SPI-connected RAM` |
| `Component config` → `ESP System Settings` → `CPU frequency` | **240MHz** |
| `Component config` → `FreeRTOS` → `Kernel` → `configTICK_RATE_HZ` | **1000**（1 毫秒一個 tick，10 毫秒的延遲才準） |
| `Partition Table` | `Single factory app (large), no OTA` |

按 `S` 存檔、`Q` 離開，設定存在專案根目錄的 `sdkconfig`。

:::tip
這些數值是照車上控制板（ESP32-S3-WROOM-1U-N4R2：4MB Flash＋2MB PSRAM）設的。你的開發板 Flash 或 PSRAM 大小若不同，要改成開發板的規格，否則可能開機失敗。不確定時，先保留預設值，只改 CPU 頻率和 tick。
:::

## 4. 安裝 micro-ROS 的 ESP-IDF 元件

> 🔊 ESP-IDF 本身不懂 ROS，要另外裝一個 micro-ROS 元件，它會在第一次編譯時下載並編出一個 lib microros 點 a 的靜態函式庫。這個元件預設很節省，只允許兩個發布者和兩個訂閱者，所以官方建議先把上限改成三。改完上限一定要清掉舊的函式庫重新編，否則改了等於沒改。

```bash title="在電腦 WSL（Jazzy）"
mkdir -p ~/esp/Samples/extra_components
cd ~/esp/Samples/extra_components
git clone -b humble https://github.com/micro-ROS/micro_ros_espidf_component.git
cd micro_ros_espidf_component

source ~/esp/esp-idf/export.sh
pip3 install catkin_pkg lark-parser empy colcon-common-extensions
```

:::warn
`pip3 install` **一定要在 `source export.sh` 之後**執行，這樣套件才會裝進 ESP-IDF 自己的 Python 虛擬環境。如果沒先 source，Ubuntu 24.04 會拒絕把套件裝進系統 Python（出現 `externally-managed-environment`）。分支用 `humble`，對應車上的 ROS 2 Humble 與 agent 映像 `microros/micro-ros-agent:humble`。
:::

### 4.1 調高 publisher／subscriber 上限

編輯 `micro_ros_espidf_component/colcon.meta` 的 `rmw_microxrcedds` 區塊：

```json title="colcon.meta（rmw_microxrcedds 區塊，官方建議值）"
"rmw_microxrcedds": {
    "cmake-args": [
        "-DRMW_UXRCE_XML_BUFFER_LENGTH=400",
        "-DRMW_UXRCE_TRANSPORT=udp",
        "-DRMW_UXRCE_MAX_NODES=1",
        "-DRMW_UXRCE_MAX_PUBLISHERS=3",
        "-DRMW_UXRCE_MAX_SUBSCRIPTIONS=3",
        "-DRMW_UXRCE_MAX_SERVICES=1",
        "-DRMW_UXRCE_MAX_CLIENTS=1",
        "-DRMW_UXRCE_MAX_HISTORY=3"
    ]
},
```

### 4.2 重編 libmicroros.a

```bash title="在電腦 WSL（Jazzy）"
cd ~/esp/Samples/extra_components/micro_ros_espidf_component/examples/int32_publisher
idf.py clean-microros
idf.py set-target esp32s3
ls ../../*.a
```

看到 `Configuring done`、`Generating done`，且 `ls` 列出 `libmicroros.a` 就成功。這一步要從 GitHub 下載很多東西，網路不穩容易失敗，失敗就再跑一次。

自己的專案要用這個元件，在專案根目錄的 `CMakeLists.txt` 加：

```cmake title="專案根目錄 CMakeLists.txt（依實際相對路徑調整）"
set (EXTRA_COMPONENT_DIRS "../../extra_components")
```

## 5. rclc 程式骨架：node、publisher、timer、executor

> 🔊 每個 micro-ROS 程式都長得差不多，像填表格。先連 WiFi，再設定 Domain ID 和 agent 的位址，然後一直嘗試連 agent，連上了才往下走。接著建立節點、發布者和定時器，最後把定時器交給一位調度員，叫 executor。調度員要放在無窮迴圈裡不停巡邏，看哪個定時器到點了就呼叫對應的函式。忘了讓調度員巡邏，你寫的函式永遠不會被執行。

### 5.1 名詞對照

| rclc 名詞 | 白話 | 對應 Pi 5 上的 Python（rclpy） |
| --- | --- | --- |
| `support` | micro-ROS 的執行環境 | `rclpy.init()` |
| `node` | 節點，程式在 ROS 網路裡的身分 | `Node("名字")` |
| `publisher` / `subscription` | 發布者／訂閱者 | `create_publisher` / `create_subscription` |
| `timer` | 定時器，到點呼叫 callback | `create_timer` |
| `executor` | 調度員，決定何時呼叫哪個 callback | `rclpy.spin()` |
| `std_msgs__msg__Int32` | C 語言裡的訊息型別名稱（包名__msg__型別） | `from std_msgs.msg import Int32` |

### 5.2 骨架（官方第 17 組各課共用，逐字節錄）

```c title="main/main.c 的 micro-ROS 骨架（官方節錄，在電腦 WSL 編譯）"
// 1) 連 WiFi（SSID/密碼來自 menuconfig 的 micro-ROS Settings->WiFi Configuration）
ESP_ERROR_CHECK(uros_network_interface_initialize());

// 2) 取 ROS 參數（來自 menuconfig）
#define ROS_NAMESPACE   CONFIG_MICRO_ROS_NAMESPACE
#define ROS_DOMAIN_ID   CONFIG_MICRO_ROS_DOMAIN_ID
#define ROS_AGENT_IP    CONFIG_MICRO_ROS_AGENT_IP
#define ROS_AGENT_PORT  CONFIG_MICRO_ROS_AGENT_PORT

// 3) 建立 init options，設 domain id 與 agent 位址
rcl_allocator_t allocator = rcl_get_default_allocator();
rclc_support_t support;
rcl_init_options_t init_options = rcl_get_zero_initialized_init_options();
RCCHECK(rcl_init_options_init(&init_options, allocator));
RCCHECK(rcl_init_options_set_domain_id(&init_options, ROS_DOMAIN_ID));
rmw_init_options_t *rmw_options = rcl_init_options_get_rmw_init_options(&init_options);
RCCHECK(rmw_uros_options_set_udp_address(ROS_AGENT_IP, ROS_AGENT_PORT, rmw_options));

// 4) 反覆嘗試連 agent，成功才往下（每 500ms 重試）
while (1) {
    ESP_LOGI(TAG, "Connecting agent: %s:%s", ROS_AGENT_IP, ROS_AGENT_PORT);
    state_agent = rclc_support_init_with_options(&support, 0, NULL, &init_options, &allocator);
    if (state_agent == ESP_OK) { ESP_LOGI(TAG, "Connected agent: %s:%s", ROS_AGENT_IP, ROS_AGENT_PORT); break; }
    vTaskDelay(pdMS_TO_TICKS(500));
}

// 5) 建節點 → publisher / subscription / timer → 加進 executor
rcl_node_t node;
RCCHECK(rclc_node_init_default(&node, "節點名", ROS_NAMESPACE, &support));
rclc_executor_t executor;
RCCHECK(rclc_executor_init(&executor, &support.context, handle_num, &allocator));
RCCHECK(rclc_executor_add_timer(&executor, &timer));

// 6) 主迴圈：讓 executor 不停巡邏
while (1) {
    rclc_executor_spin_some(&executor, RCL_MS_TO_NS(100));
    usleep(1000);
}
```

### 5.3 官方 17-1：發布 Int32（`microros_samples/publisher`）

- 節點 `esp32_publisher`，話題 `publisher`，型別 `std_msgs/msg/Int32`。
- timer 100 毫秒（10 Hz），`handle_num = 1`。
- callback `timer_callback` 做三件事：印 `Publishing: %d`、`rcl_publish(&publisher, &msg, NULL)`、`msg.data++`。

建立 publisher 與 timer 的寫法（依官方說明整理）：

```c title="publisher 與 timer（依官方 17-1 說明整理）"
rclc_publisher_init_default(&publisher, &node,
    ROSIDL_GET_MSG_TYPE_SUPPORT(std_msgs, msg, Int32), "publisher");
rclc_timer_init_default(&timer, &support, RCL_MS_TO_NS(100), timer_callback);
```

:::tip
沒有官方虛擬機的範例檔時，最快的做法是直接從元件內建的 `examples/int32_publisher` 改起：它和官方 17-1 做的事幾乎一樣，而且 4.2 節已經編過一次。把整個資料夾複製一份再改，不要改原檔。

```bash title="在電腦 WSL（Jazzy）"
cp -r ~/esp/Samples/extra_components/micro_ros_espidf_component/examples/int32_publisher ~/esp/Samples/my_publisher
cd ~/esp/Samples/my_publisher
```

複製到別處後，`CMakeLists.txt` 裡指向元件的路徑要跟著改成 `set (EXTRA_COMPONENT_DIRS "../extra_components")` 這類正確的相對位置（需實機確認範例的寫法）。
:::

### 5.4 menuconfig 裡的 micro-ROS 設定

```bash title="在電腦 WSL（Jazzy）"
source ~/esp/esp-idf/export.sh

```

| 選單 | 填什麼 |
| --- | --- |
| `micro-ROS Settings` → `Agent IP` | **跑 agent 那台機器的區網 IP**（不是 localhost） |
| `micro-ROS Settings` → `Agent Port` | `8090`（對應 agent 的 `--port 8090`） |
| `micro-ROS Settings` → `WiFi Configuration` | `WiFi SSID`、`WiFi Password` |

## 6. 開 UDP agent、驗證發布與訂閱

> 🔊 板子燒好之後，要開一個 UDP 版的 agent 讓它連進來。agent 可以開在電腦上，也可以開在車上的 Pi 5，只要和 ESP32 在同一個 WiFi，而且 menuconfig 裡填的 Agent IP 就是那台機器。連上後，用熟悉的 ros2 node list 看看有沒有 esp32 publisher 這個節點，再用 topic echo 和 topic hz 看資料和頻率。十赫茲左右就代表成功了。

### 6.1 開 agent（二選一）

**選項 A：開在車上的 Pi 5**（Pi 5 已經有 Docker 和 ROS 2 容器，最省事）

```bash title="在 Pi 5 主機（另開終端，不影響車子原本的序列 agent）"
docker run -it --rm -v /dev:/dev -v /dev/shm:/dev/shm --privileged --net=host microros/micro-ros-agent:humble udp4 --port 8090 -v4
```

menuconfig 的 Agent IP 填 **Pi 5 的 IP**（熱點模式是 `10.42.0.1`，開發板要先連上車的熱點 `Micro_ros`）。和車上原本的序列 agent 同時存在是否互相干擾，官方沒寫（需實車確認）；有疑慮就先把序列 agent 關掉。

**選項 B：開在電腦 WSL**（需先在 WSL 裝好 Docker Engine，並照 A5 設好 mirrored 網路）

```bash title="在電腦 WSL（Jazzy）"
docker run -it --rm -v /dev:/dev -v /dev/shm:/dev/shm --privileged --net=host microros/micro-ros-agent:humble udp4 --port 8090 -v4
```

Agent IP 填 **Windows 電腦的 WiFi IP**（mirrored 模式下 WSL 和 Windows 共用 IP）。Windows 防火牆可能擋 UDP 8090 的連入，連不上時先檢查防火牆（需實機確認）。

:::warn
agent 只能開**一個**同埠的；結束請按 **Ctrl+C**，不要直接關終端，否則容器會殘留在背景，下次啟動就報錯。殘留時：

```bash title="在 Pi 5 主機或電腦 WSL（開 agent 的那台）"
docker ps -a | grep microros/micro-ros-agent
docker stop <殘留的 CONTAINER ID>
```

:::

### 6.2 驗證發布者

```bash title="在車上 Docker 容器內（或任何 ROS_DOMAIN_ID=20 的 ROS 2 環境）"
ros2 node list
ros2 node info /esp32_publisher
ros2 topic echo /publisher
ros2 topic hz /publisher
```

看到數字一直加 1，頻率約 10 Hz 就成功。

### 6.3 驗證訂閱者（官方 17-2）

官方 17-2 的節點 `esp32_subscriber` 訂閱話題 `subscriber`（`std_msgs/msg/Int32`），callback 收到就印 `Received: %d`。加訂閱者的關鍵一行：

```c title="加入訂閱（官方 17-2 說明）"
RCCHECK(rclc_executor_add_subscription(&executor, &subscriber, &recv_msg, &callback, ON_NEW_DATA));
```

燒好後從 ROS 2 端送一個數字：

```bash title="在車上 Docker 容器內"
ros2 topic pub /subscriber std_msgs/msg/Int32 "data: 123"
```

`idf.py monitor` 印出 `Received: 123` 就成功。

:::info
`handle_num` 是 executor 最多要照顧幾個「事件來源」，要大於等於「timer 數＋subscriber 數」。官方 17-3 同時有 3 個 timer＋3 個 subscriber，所以 `handle_num = 6`，也剛好用滿第 4.1 節的「3／3」上限。設太小時，多出來的 callback 會靜悄悄地不執行。
:::

### 6.4 接著可以做的官方練習

| 官方課 | 節點／話題 | 需要的硬體 |
| --- | --- | --- |
| 17-3 多話題 | `esp32_pub_sub`：`publisher_1/2/3`、`subscriber_1/2/3` | 只要板子 |
| 17-4 蜂鳴器 | `beep_subscriber`：`beep`（`std_msgs/msg/UInt16`） | 外接主動蜂鳴器 |
| 17-5 舵機 | `servo_subscriber`：`servo_s1`、`servo_s2`（`std_msgs/msg/Int32`） | 外接舵機 |
| 17-6 速度 | `twist_subscriber`：`cmd_vel`（`geometry_msgs/msg/Twist`） | 馬達、編碼器（**架空**） |
| 17-7 里程計 | `odom_publisher`：`odom_raw`（`nav_msgs/msg/Odometry`，20 Hz） | 同上 |
| 17-8 IMU | `imu_publisher`：`imu`（`sensor_msgs/msg/Imu`，20 Hz） | ICM42670P |
| 17-9 光達 | `lidar_publisher`：`scan`（`sensor_msgs/msg/LaserScan`，約 11 Hz） | MS200 |
| 17-10 序列傳輸 | `custom_transport`：`custom_publisher` | 只要 USB 線，改用序列 agent |

:::warn
官方 17-8 的驗證段落文字寫 `Subscribe to the data of the /odom_raw topic`，但指令是 `ros2 topic echo /imu`，文字是複製錯誤，以指令為準。17-10 文件寫「串口 2」，但用的 GPIO43／44 其實是 UART0（Type-C 燒錄口）。另外官方 IMU 範例把「度／秒」和「g」直接塞進 Imu 訊息，而 ROS 標準是 rad/s 與 m/s²，自己做融合時要注意單位。
:::

## 7. 燒回出廠韌體與 config_robot.py 重設

> 🔊 用車上控制板練習完，一定要把出廠韌體燒回去，車子才會變回原本的樣子。出廠韌體是一個合併好的單一檔案，燒在位址零，而且要勾選 DoNotChgBin，意思是不要讓工具改動這個檔。這和自己編的程式分成三個檔、燒在三個位址完全不同，千萬別搞混。燒完之後，再到 Pi 5 用 config robot 點 py 把車型、Domain ID 和 namespace 寫回去。

### 7.1 用 Windows 的 Flash Download Tool 燒錄（官方做法）

1. 安裝 **CP2102 驅動**（隨附資料 `Hardware related information → CP2102 serial port chip → CP2102-Windows driver file.zip`，64 位元執行 `CP210xVCPInstaller_x64.exe`）。Type-C 線接控制板標 **Serial** 的孔，裝置管理員 → 連接埠要看到 CP210x。
2. 若之前用 `usbipd attach` 把板子借給 WSL，先在 Windows PowerShell 執行 `usbipd detach --busid <BUSID>` 還給 Windows。
3. 下載 Espressif **flash_download_tool**（`https://www.espressif.com.cn/zh-hans/support/download/other-tools`），開啟後晶片選 **ESP32-S3**。
4. `SPIDownload` 頁籤設定：

| 欄位 | 設定 |
| --- | --- |
| 檔案 | `microROS_Robot_V2.0.0.bin`（本專案在 `source-code/firmware/Factory-Firmware/`） |
| 位址 | **`0x0`** |
| 勾選 | **`DoNotChgBin`** |
| COM | 控制板的 COM 埠 |
| 其他 | 保持預設 |

1. 按 **Start**。沒自動開始：**按住 BOOT0 → 按 Reset → 放開 BOOT0**。
2. 出現藍色 **FINISH** 後，斷電重啟或按 Reset。
3. 驗證：用序列埠助手（隨附 `UartAssist.exe`），**115200、8 bit、1 stop、無 parity、無流控**，按 Reset，要看到 `hello Yahboom` 和下一行的韌體版本號。

| | 出廠韌體 | 自己編的程式 |
| --- | --- | --- |
| 檔案 | 單一檔 `microROS_Robot_V2.0.0.bin` | `bootloader.bin`、`partition-table.bin`、`main.bin` |
| 位址 | `0x0` | `0x0000`、`0x8000`、`0x10000` |
| DoNotChgBin | **要勾** | 不用 |

:::tip
已經裝好 ESP-IDF 的話，也可以在 WSL 用 ESP-IDF 內附的 esptool 燒（這是文件外的做法，官方只教 Windows 工具，需實機確認）：

```bash title="在電腦 WSL（Jazzy）"
source ~/esp/esp-idf/export.sh
esptool.py --chip esp32s3 -p /dev/ttyUSB0 write_flash 0x0 microROS_Robot_V2.0.0.bin
```

:::

### 7.2 用 config_robot.py 重設參數

燒回出廠韌體後，把板子接回 Pi 5，在 VNC 桌面：Docker 終端 `exit`、agent 終端 Ctrl+C，然後確認 `config_robot.py` 是單車設定：

```python title="config_robot.py 必須是這幾行（在 Pi 5 主機的 /home/pi）"
robot.set_car_type(robot.CAR_TYPE_RPI5)
robot.set_ros_domain_id(20)
robot.set_ros_serial_baudrate(921600)
robot.set_ros_namespace("")
```

短按控制板 Reset，**5 秒內**（燈每 300 毫秒閃）執行：

```bash title="在 Pi 5 主機"
cd ~
python3 config_robot.py
```

確認印出的 `domain_id: 20`、`ros_namespace:` 空白、車型 `CAR_TYPE_RPI5`，再按一次 Reset。最後照常開 agent 與容器：

```bash title="在 Pi 5 主機"
sh ~/start_agent_rpi5.sh
```

```bash title="在車上 Docker 容器內"
ros2 node list
```

重新看到 `/YB_Car_Node` 就完全恢復了。

:::warn
`config_robot.py` 裡的 `CAR_TYPE_RPI5` 讓板子走序列埠接 Pi 5；如果誤設成 `CAR_TYPE_COMPUTER`，板子會改走 WiFi UDP，Pi 5 的序列 agent 就永遠連不上。兩種版本用的是**同一個**出廠韌體，差別只在這個參數。
:::

## 8. 出問題時怎麼辦

> 🔊 韌體開發的除錯鏈很長，問題可能在 WiFi、agent、Docker、Domain ID 或序列埠任何一環，而且很多失敗不會報錯，只是一直顯示正在連線。先看板子的序列輸出卡在哪一步，再看指示燈怎麼閃，最後用下面這張表對照。記住一個萬用招：關掉 agent、按板子的 Reset、再重開 agent。

| 症狀 | 最可能的原因 | 怎麼做 |
| --- | --- | --- |
| `idf.py: command not found` | 新終端忘了啟用環境 | `source ~/esp/esp-idf/export.sh` |
| WSL 裡沒有 `/dev/ttyUSB0` | USB 沒借給 WSL | Windows 執行 `usbipd attach --wsl --busid <BUSID>` |
| 燒錄出現 Permission denied | 不在 `dialout` 群組 | `sudo usermod -aG dialout $USER` 後重開終端 |
| 燒錄失敗、連不到板子 | 序列埠被 monitor、序列 agent 或序列助手佔用 | 先 Ctrl+] 離開 monitor、Ctrl+C 關序列 agent、關掉 UartAssist |
| 燒錄卡在等待連線 | 沒進燒錄模式 | 按住 BOOT0 → 按 Reset → 放開 BOOT0 |
| 一直印 `Connecting agent: ...` | agent 沒開、埠不是 8090、Agent IP 填錯、WiFi 不同網段 | 檢查 menuconfig 的 Agent IP／Port／WiFi；agent 和板子要同一個區網 |
| agent 啟動就報錯 | 已有一個 agent 或上次殘留的容器 | `docker ps -a \| grep microros/micro-ros-agent`、`docker stop <ID>` |
| `ros2 node list` 看不到 `esp32_publisher` | Domain ID 不一致 | menuconfig 的 `ROS domain id` 與 ROS 端 `ROS_DOMAIN_ID` 都設 20；改完 `ros2 daemon stop` |
| 建立 subscriber 失敗、某個 callback 不執行 | 超過 `colcon.meta` 上限或 `handle_num` 太小 | 改 `colcon.meta` 後 `idf.py clean-microros` 重編；調大 `handle_num` |
| 改了 `colcon.meta` 卻沒變化 | 沒清掉舊的 `libmicroros.a` | `idf.py clean-microros` 再 build |
| 17-10 燒完 monitor 全是亂碼 | 正常：序列埠上跑的是二進位協定 | Ctrl+] 離開，改開序列 agent |
| 改了 `sdkconfig` 之後行為怪怪的 | 舊的編譯結果殘留 | `idf.py fullclean` 再 build（常見做法，文件未寫） |
| 車子燒完練習程式後完全不能控制 | 出廠韌體被覆蓋 | 照第 7 節燒回 `microROS_Robot_V2.0.0.bin` 並重設 |
| 馬達類程式燒完輪子狂轉 | 正常行為 | 先架空；按 Reset 重新開始，或斷電 |
| 蜂鳴器一直嗶、車不聽指令 | 電池低電壓 | 充電 |

**MCU 指示燈對照**（出廠韌體）：

| 閃法 | 狀態 |
| --- | --- |
| 每 300 毫秒閃一次 | 設定狀態（開機約 5 秒內） |
| 每 1 秒慢閃 | 正在連 agent |
| 每 50 毫秒快閃 | micro-ROS 錯誤 |
| 每 3 秒快閃 2 次 | 正常 |
| 每 100 毫秒閃＋蜂鳴器 | 低電壓 |
