## 1. 先有地圖，再上路

> 🔊 歡迎來到第一個暖身單元。車子還沒到也沒關係，這三十分鐘我們不碰任何指令，只做一件事：在腦中建立這台車的地圖。
> 很多初學者一拿到機器人就急著照教學打指令，結果一出錯，完全不知道是哪一層壞掉。
> 所以我們先搞懂這台車由哪幾塊組成、誰跟誰講話，之後每一個單元，你都會知道自己正在操作地圖上的哪一格。

這台 Yahboom MicroROS-Pi5 是一台四輪的 ROS 2 教學車。ROS 2（Robot Operating System 2，機器人作業系統第 2 版）不是真的作業系統，而是一套「讓很多小程式互相傳訊息」的框架，下一個單元 W2 會詳細練習。

本單元結束後你要能回答三個問題：

1. 這台車的「大腦」和「小腦」分別是哪塊板子？
2. 為什麼車上的 ROS 2 要裝在 Docker 容器裡？
3. 我要讓車往前走，指令要送到哪個話題？誰會收到？

建議先把三支影片看過一遍，對實體長什麼樣子有印象：

## 2. 三層架構：大腦、翻譯官、小腦

> 🔊 用一個比喻來記：樹莓派 5 是大腦，負責思考，例如看相機畫面、算地圖、決定要往哪走。
> 底下那塊 ESP32 擴充板是小腦，負責反射動作，例如讓馬達照指定速度轉、讀陀螺儀、讓蜂鳴器響。
> 但大腦和小腦講的語言不太一樣，所以中間還有一位翻譯官，叫做 micro-ROS agent。
> 翻譯官和大腦的 ROS 2 環境，都裝在樹莓派上的 Docker 容器裡。記住這三層，之後遇到問題就一層一層往下查。

```text
 手機 App / 手把 / 鍵盤 / 電腦 RViz
            │  WiFi（ROS_DOMAIN_ID=20）
┌──────── 第 1 層：Raspberry Pi 5（Raspberry Pi OS）────────┐
│  第 2 層 Docker 容器 A：ROS 2 Humble（裝好 yahboomcar_* 套件）│
│  第 2 層 Docker 容器 B：micro-ROS agent（翻譯官）             │
└──────────────┬────────────────────────────────────────────┘
               │ USB 序列線 /dev/ttyUSB0（921600 baud）
┌──────── 第 3 層：ESP32-S3 擴充板（micro-ROS 韌體，節點 /YB_Car_Node）┐
│ 4×編碼馬達　IMU　蜂鳴器　雲台舵機×2　MS200 光達                      │
└───────────────────────────────────────────────────────────────────┘
 2MP USB 相機直接插在 Pi 5，由容器 A 內的 usb_cam 發布影像
```

| 層 | 是什麼 | 負責什麼 | 你會怎麼碰到它 |
| --- | --- | --- | --- |
| 第 1 層 Pi 5 主機 | Raspberry Pi 5，跑 Raspberry Pi OS | 開 WiFi 熱點、跑 Docker、接相機與手把接收器 | VNC 看桌面、SSH 登入 |
| 第 2 層 Docker | 兩個容器 | 容器 B（agent）：把 ESP32 的訊息轉成 ROS 2 話題；容器 A（ROS 2 Humble）：所有 `yahboomcar_*` 程式在這裡跑 | `sh ~/start_agent_rpi5.sh` 開 agent；`sh ros2_humble.sh` 進容器 A |
| 第 3 層 ESP32 | ESP32-S3 雙核微控制器 + 馬達/舵機驅動 + 六軸 IMU | 即時控制馬達、讀 IMU、轉發光達資料 | 平常不用碰；高級單元 A4 才改韌體 |

:::info
**micro-ROS 是什麼？** 縮小版的 ROS 2，專門跑在 ESP32 這種記憶體很小的微控制器上。微控制器沒辦法直接加入 ROS 2 網路，所以需要 Pi 5 上的 **agent（代理人）** 幫它轉話。沒有 agent，ESP32 就是一座孤島，`ros2 node list` 看不到車。
:::

## 3. 為什麼 ROS 2 要裝在 Docker 裡

> 🔊 你可能會好奇，樹莓派本身就是一台 Linux 電腦，為什麼不直接把 ROS 2 裝上去，還要多一層 Docker？
> 原因是 ROS 2 Humble 原本是配 Ubuntu 22.04 的，而樹莓派跑的是自己的系統。
> Docker 就像一個貨櫃屋，把 Ubuntu、ROS 2 和車子所有程式整箱打包好，放在樹莓派這塊地上。
> 好處是環境固定、不會跟主機互相干擾，弄壞了關掉重開就恢復。代價是要學一點 Docker 指令，第三單元會教。

重點整理：

- **主機（Pi 5）指令**：`docker ...`、`sh ~/start_agent_rpi5.sh`、`sh ros2_humble.sh`
- **容器內指令**：所有 `ros2 ...` 指令
- 看提示符號分辨：容器內通常是 `root@...`，主機上是 `pi@...`

:::warn
官方的 Docker 課範例映像寫 `yahboomtechnology/ros-foxy`、帳號寫 `jetson`，那是其他產品的共用教材。**本車容器是 ROS 2 Humble**（原始碼中 `ros2_humble.sh` 用的映像是 `yahboomtechnology/ros-humble:4.0.3`），帳號是 `pi`。
:::

## 4. 硬體逐一認識

> 🔊 接下來認識車上的零件。先記一個原則：大部分感測器和馬達都接在 ESP32 小腦上，只有相機直接接在樹莓派大腦上。
> 光達是車頂那個會轉的小圓柱，用雷射量四周的距離，一圈三百六十度。
> 四顆編碼馬達會回報自己轉了幾圈，用來推算車子走了多遠。IMU 是陀螺儀加加速度計，知道車子有沒有在轉。
> 雲台上的相機可以左右、上下轉。最後是兩顆 18650 組成的 7.4 伏特電池，它是整台車的能量來源。

| 硬體 | 規格重點 | 接在哪 | 對應的 ROS 2 話題 |
| --- | --- | --- | --- |
| MS200 光達（LiDAR，雷射測距儀） | TOF 單線、360°、10 Hz、0.03～12 m、4500 點/秒、角解析度 0.8° | ESP32 的雷達介面（UART1） | 發布 `/scan` |
| 2MP USB 相機 | 裝在雙軸雲台上 | **直接插 Pi 5** | 容器內 `usb_cam` 發布影像 |
| 雙軸雲台舵機 | S1 左右轉、S2 上下轉 | ESP32 的 PWM 舵機介面 | 訂閱 `/servo_s1`、`/servo_s2` |
| 4 顆編碼馬達 | 一般輪胎（不能側移） | ESP32 馬達介面 M1～M4 | 訂閱 `/cmd_vel`；回報 `/odom_raw` |
| 六軸 IMU（慣性量測單元） | 陀螺儀 + 加速度計，焊在 ESP32 板上 | ESP32 板上 | 發布 `/imu` |
| 蜂鳴器 | 有源蜂鳴器，低電量會自己叫 | ESP32 板上 | 訂閱 `/beep` |
| 電池 | 7.4V、2000mAh、2 顆 18650，充電器 DC 8.4V | ESP32 板 T 型接口 | 沒有對應話題 |
| ESP32-S3 擴充板 | 兩個 Type-C：**Serial**（通訊/燒錄）、**5V OUT**（供電給 Pi 5） | — | 節點 `/YB_Car_Node` |

:::warn
**馬達型號**：你的資料寫 370 編碼馬達，但官方控制板介紹文件寫「310 編碼馬達」。對學習沒有影響，以實物標示為準（需實車確認）。
:::

:::info
**光達資料其實是 ESP32 轉發的**：MS200 接在 ESP32 的 UART1（GPIO17/18），不是接 Pi 5，所以 `/scan` 也是 `/YB_Car_Node` 發布的。這點和很多其他 ROS 車不同。
:::

## 5. 話題介面總表：車在「說什麼、聽什麼」

> 🔊 這一節是整個暖身課最重要的一張表。在 ROS 2 裡，程式之間用一種叫做話題的頻道互相傳資料，就像對講機的頻道。
> ESP32 小腦開了幾個頻道在聽指令，例如 cmd vel 這個頻道，收到速度就驅動馬達。
> 它也開了幾個頻道在報告狀態，例如 scan 是光達距離、imu 是陀螺儀、odom raw 是輪子推算出來的位置。
> 你之後讓車動、讀感測器，全部都是對這幾個頻道說話或收聽。

**`/YB_Car_Node` 訂閱（你下指令給車）**

| 話題 | 訊息型別 | 用途 | 值域 |
| --- | --- | --- | --- |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | 車速：`linear.x` 前後（m/s）、`angular.z` 旋轉（rad/s） | 範例韌體限制 Vx∈[-1.0, 1.0]、Vz∈[-5.0, 5.0] |
| `/beep` | `std_msgs/msg/UInt16` | 蜂鳴器 | 0 關、1 持續響、≥10 代表響幾毫秒 |
| `/servo_s1` | `std_msgs/msg/Int32` | 雲台左右 | [-90, 90]，超出範圍舵機不動 |
| `/servo_s2` | `std_msgs/msg/Int32` | 雲台上下 | [-90, 20]，超出範圍舵機不動 |

**`/YB_Car_Node` 發布（車回報給你）**

| 話題 | 訊息型別 | 內容 |
| --- | --- | --- |
| `/scan` | `sensor_msgs/msg/LaserScan` | MS200 光達一圈的距離 |
| `/imu` | `sensor_msgs/msg/Imu` | 六軸 IMU |
| `/odom_raw` | `nav_msgs/msg/Odometry` | 輪速里程計原始值 |

**Pi 5 這邊另外會出現的話題**

| 話題 | 誰發的 | 說明 |
| --- | --- | --- |
| `/odom` | 容器內 `/ekf_filter_node` | 把 `/odom_raw` 和濾波後的 IMU 融合，比較準；跑 `yahboomcar_bringup_launch.py` 才有 |
| `/rpi5_ip` | Pi 5 | 回報自己目前的 IP，換到家裡 WiFi 時用來找車 |
| 相機影像 | 容器內 `usb_cam` | 跑相機 launch 才有 |

:::warn
官方 05-1 文件的發布清單寫車子發布 `/odom`，但同一頁查詢指令用的是 `ros2 topic echo /odom_raw`，狀態估測課也說 EKF 是訂閱 `/odom_raw` 再輸出 `/odom`。**結論：ESP32 發的是 `/odom_raw`，`/odom` 是 Pi 端融合後的產物**（需實車以 `ros2 topic list` 確認）。
:::

## 6. 開機時發生了什麼事，以及預設值

> 🔊 現在把時間軸拉出來看。按下電源後，樹莓派開機大約三十秒，會自動開兩個終端機視窗：一個是翻譯官 agent，一個是 ROS 2 容器，而且出廠還會自動啟動手把控制。
> 同時 ESP32 也開機，先有五秒的設定時間，然後開始找翻譯官，找到之後才建立那些話題。
> 這裡有一個一定要記住的數字：ROS DOMAIN ID 等於二十。它像是社區的門牌號碼，號碼一樣的程式才看得到彼此。容器、電腦、ESP32 三邊都要是二十。

**開機流程**

```text
電源開 → Pi 5 開機（約 30 秒）
       → 自動開「agent 終端」＋「Docker 容器終端」＋自動啟動手把控制
ESP32  → 設定狀態約 5 秒（MCU 燈每 300 ms 閃一次）
       → 連線 agent 中（每 1 秒慢閃）
       → 連上後建立話題 → 正常狀態（每 3 秒快閃 2 次）
```

| MCU 燈號 | 意思 |
| --- | --- |
| 每 300 ms 閃一次 | 剛開機的設定狀態（約 5 秒） |
| 每 1 秒慢閃 | 正在找 agent，還沒連上 |
| 每 50 ms 快閃 | micro-ROS 出錯 |
| 每 3 秒快閃 2 次 | 正常 |
| 每 100 ms 閃＋蜂鳴器嗶嗶 | 低電量，**車無法控制**，請存檔關機充電 |

**出廠預設值（建議抄在便利貼上）**

| 項目 | 值 |
| --- | --- |
| 車子熱點名稱／密碼 | `Micro_ros`／`12345678` |
| 連熱點時 Pi 5 的 IP | `10.42.0.1` |
| Pi 5 帳號／密碼 | `pi`／`yahboom` |
| `ROS_DOMAIN_ID` | `20`（合法範圍 0～101） |
| ESP32 序列裝置 | `/dev/ttyUSB0` |
| ROS 2 版本（車上容器） | Humble |
| 你電腦 WSL 的 ROS 2 版本 | Jazzy（暖身單元用它練，指令幾乎相同） |

:::warn
**電池安全**：只用原廠電池與充電器；**充電時要關掉擴充板總電源開關，不可邊充邊用**；充電要有人在旁邊，充電器綠燈就拔掉；蜂鳴器嗶嗶叫就關機充電。B1 單元會再詳細講。
:::

## 7. 動手：畫出你的三層圖

> 🔊 最後來做這個單元的過關練習。拿一張白紙，不要看講義，畫出三層：最上面是樹莓派 5，中間是兩個 Docker 容器，最下面是 ESP32 和它身上的零件。
> 然後用箭頭畫出一個速度指令的旅程：從鍵盤出發，經過容器裡的程式，變成 cmd vel 話題，再經過翻譯官，最後到達 ESP32，讓四顆馬達轉起來。
> 畫完再反過來畫一條光達資料的旅程。兩條路都畫得出來，你就過關了。

**練習題目**

1. 畫出三層，每層寫一句「它負責什麼」。
2. 畫出「鍵盤 → 車子前進」的路徑，標出經過的程式和話題名稱。
3. 畫出「光達量到距離 → 你在電腦上看到」的路徑。

**參考答案（畫完再看）**

```text
速度指令：
鍵盤 → 容器 A 裡的 yahboom_keyboard 節點 → 發布 /cmd_vel
     → 容器 B 的 micro-ROS agent → USB 序列線 → ESP32 /YB_Car_Node → 4 顆馬達

光達資料：
MS200 → ESP32 /YB_Car_Node 發布 /scan → USB 序列線 → micro-ROS agent
      → ROS 2 網路（DOMAIN_ID=20）→ 容器 A 的程式／電腦上的 RViz
```

:::tip
之後只要車子「沒反應」，就照這張圖由上往下查：容器裡的程式有沒有在跑？`ros2 node list` 有沒有 `/YB_Car_Node`？agent 有沒有開？ESP32 燈號是不是正常？`ROS_DOMAIN_ID` 三邊是不是都是 20？
:::
