## 1. DDS 探索：節點怎麼找到彼此

> 🔊 ROS 2 沒有一台中央伺服器，節點之間是自己找朋友的。每個節點一啟動，就在區域網路上大聲喊：我是誰、我發布什麼話題、我想訂閱什麼。聽到的節點如果剛好需要，就直接和它連線。負責這件事的底層叫 DDS，資料分發服務。好處是不用設定，同一個網路裡自動就通；壞處是只要網路把這種廣播擋掉，例如 WSL 預設的虛擬網路，節點就完全找不到彼此。

### 1.1 DDS 是什麼

**DDS（Data Distribution Service，資料分發服務）**是 ROS 2 話題、服務、動作的底層通訊標準。官方教材的比喻是**旋轉火鍋**：資料放在「資料匯流排」上轉，每個節點只夾自己要的那一盤，不用知道是誰煮的。

| | ROS 1 | ROS 2（DDS） |
| --- | --- | --- |
| 怎麼找到彼此 | 先問中央的 master | 每個節點自己用**多播（multicast）**廣播「我在這」 |
| master 掛掉 | 全部失聯 | 沒有 master，不會單點故障 |
| 需要設定 | 每台都要設 `ROS_MASTER_URI` | 同網段、同 Domain ID 就自動通 |

**探索（discovery）**的兩個前提：

1. 雙方在**同一個網段**，而且網路允許 UDP 多播通過。
2. 雙方的 **`ROS_DOMAIN_ID` 相同**。

### 1.2 這台車的網路其實已經是「多機」

車子本身就是分散式系統：

- micro-ROS agent 容器用 `--net=host`
- ROS 2 Humble 容器（`ros2_humble.sh`）也用 `--net=host`

**host 網路模式**代表容器直接用 Pi 5 的網卡，所以容器裡的節點對外就像直接跑在 Pi 5 上。電腦只要和 Pi 5 在同一個網路、同一個 Domain ID，就能直接看到車上所有話題。

### 1.3 QoS：連得上但收不到的另一個原因

**QoS（服務品質）**是發布者和訂閱者對「怎麼送資料」的約定。最常遇到的是 Reliability（可靠性）：

| 發布者 | 訂閱者 | 結果 |
| --- | --- | --- |
| RELIABLE | RELIABLE | 收得到 |
| RELIABLE | BEST_EFFORT | 收得到（相容） |
| BEST_EFFORT | RELIABLE | **收不到**，會出現 QoS 不相容警告 |
| BEST_EFFORT | BEST_EFFORT | 收得到 |

感測器話題（像光達）常用 BEST_EFFORT。所以在 RViz 看不到光達點時，把顯示項目的 Reliability Policy 改成 **Best Effort** 試試看（第 6 節）。

## 2. ROS_DOMAIN_ID=20：同頻道才聽得到

> 🔊 Domain ID 就像對講機的頻道。調到同一個頻道的人才聽得到彼此，頻道不同就像在不同的房間。這台車出廠設定是二十，寫在三個地方：ESP32 控制板裡、車上 Docker 容器的 bashrc 裡，還有你的電腦。三個地方任何一個不一樣，ros2 node list 就看不到 YB Car Node。改完環境變數之後還要重啟 ros2 daemon，否則指令會拿舊的快取騙你。

### 2.1 三個地方要一致

| 位置 | 怎麼看／怎麼設 |
| --- | --- |
| ESP32 控制板 | `config_robot.py` 的 `robot.set_ros_domain_id(20)`（寫入方式見 A3 第 2 節） |
| 車上 Docker 容器 | 容器內 `~/.bashrc` 的 `export ROS_DOMAIN_ID=20` |
| 你的電腦 WSL | 自己加到 `~/.bashrc` |

```bash title="在車上 Docker 容器內（檢查）"
echo $ROS_DOMAIN_ID
```

```bash title="在電腦 WSL（Jazzy）"
echo 'export ROS_DOMAIN_ID=20' >> ~/.bashrc
source ~/.bashrc
ros2 daemon stop
```

**`ros2 daemon`** 是 `ros2` 指令在背景用來加速的小程式，它會記住上一次探索到的節點。改了 Domain ID 或網路設定後要 `ros2 daemon stop`，下一個 `ros2` 指令會自動以新設定重啟它。

### 2.2 Domain ID 的範圍

- 官方 ROS 2 教材建議 **0～101**。原理：DDS 從埠 7400 起算，每個 domain 佔 250 個埠，再扣掉 Linux 系統保留的埠。
- 一個 domain 最多約 120 個節點。

:::warn
FAQ 說 Domain ID 合法範圍是 0～101，但 `config_robot.py` 原始碼的 `set_ros_domain_id` 會把大於 100 的值壓成 100。為了三個地方都一致，請用 **0～100**。家裡只有一台車就維持預設 **20**；同一個網路有好幾台車又不想互相干擾，才給每台不同的 ID。
:::

## 3. WSL2 網路：改成 mirrored 模式

> 🔊 這是電腦端最關鍵的一步。WSL2 預設躲在 Windows 後面的一個虛擬小網路裡，就像住在大樓裡的套房，外面的人喊話它聽不到，它的廣播也傳不出去，所以 DDS 探索跨不過去。Windows 11 提供一個鏡像模式，叫 mirrored，讓 WSL 直接共用 Windows 的網卡，就像把套房的門直接開在大街上。改一個設定檔、重啟 WSL 就好。

### 3.1 編輯 .wslconfig

在 Windows 的使用者家目錄（`%USERPROFILE%`）建立或編輯 `.wslconfig`：

```powershell title="在 Windows（PowerShell）"
notepad "$env:USERPROFILE\.wslconfig"
```

內容加上：

```ini title="%USERPROFILE%\.wslconfig"
[wsl2]
networkingMode=mirrored
```

存檔後**完整關閉 WSL** 再重開：

```powershell title="在 Windows（PowerShell）"
wsl --shutdown
```

需求：Windows 11 22H2 以上。

### 3.2 確認生效

```bash title="在電腦 WSL（Jazzy）"
ip addr
```

mirrored 模式下，WSL 看到的 IP 應該和 Windows 的 WiFi 網卡相同（例如連車子熱點 `Micro_ros` 時是 `10.42.0.x`）。如果還是 `172.x.x.x` 這種內部 IP，代表設定沒生效。

### 3.3 防火牆

mirrored 模式下，Windows 的防火牆（含 Hyper-V 防火牆）可能擋掉進來的 DDS 封包，症狀是「電腦發的車收得到，車發的電腦收不到」。Microsoft 文件提供的放行指令如下，請在**系統管理員** PowerShell 執行（需實機確認）：

```powershell title="在 Windows（系統管理員 PowerShell）"
Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow
```

:::info
電腦要和車在同一個網路：最簡單是電腦直接連車的熱點 `Micro_ros`（密碼 `12345678`），車子 IP 固定是 `10.42.0.1`；或照 B2 讓車連你家 WiFi，再用 `ros2 topic echo /rpi5_ip` 找車子的 IP。
:::

## 4. Jazzy 的探索範圍設定與 static peers

> 🔊 Jazzy 對探索範圍做了改版。以前的 Humble 用一個叫 localhost only 的開關，Jazzy 換成探索範圍這個新設定，可以選只在本機、整個子網路，或完全關閉。我們要和車子講話，所以設成子網路。如果你的網路環境把多播擋掉了，還有一招叫 static peers，直接把車子的 IP 告訴電腦，讓它不靠廣播、主動去敲門。

```bash title="在電腦 WSL（Jazzy）：加到 ~/.bashrc"
export ROS_DOMAIN_ID=20
export ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET
```

| `ROS_AUTOMATIC_DISCOVERY_RANGE` | 意思 |
| --- | --- |
| `SUBNET` | 在同一個子網路裡自動探索（要和車互通就用這個） |
| `LOCALHOST` | 只和本機的節點互通 |
| `OFF` | 不自動探索 |

多播不通時（例如某些公司或學校的 WiFi），用 **static peers** 直接指定車子 IP：

```bash title="在電腦 WSL（Jazzy）"
export ROS_STATIC_PEERS=10.42.0.1
ros2 daemon stop
```

多個 IP 用分號 `;` 分隔。車上的 Humble 沒有這個設定；只在電腦端設定，能不能讓雙向都通，請以實際測試為準（需實車確認）。

:::warn
`ROS_LOCALHOST_ONLY` 是 Humble 的舊設定，在 Jazzy 已被 `ROS_AUTOMATIC_DISCOVERY_RANGE` 取代。如果你的 `~/.bashrc` 裡殘留 `export ROS_LOCALHOST_ONLY=1`，電腦就只會跟自己講話，請刪掉。
:::

### 4.1 第一個互通測試：talker 與 listener

```bash title="在車上 Docker 容器內"
ros2 run demo_nodes_py talker
```

```bash title="在電腦 WSL（Jazzy）"
ros2 run demo_nodes_py listener
```

電腦印出 `I heard: [Hello World: N]` 就是互通成功。再試試看車上的話題：

```bash title="在電腦 WSL（Jazzy）"
ros2 node list
ros2 topic list
ros2 topic hz /scan
```

看到 `/YB_Car_Node`、`/scan` 頻率有數字，電腦就已經「看得到車」了。

## 5. Humble 與 Jazzy 混用的風險與建議

> 🔊 車上跑的是 Humble，你的 WSL 是 Jazzy，兩個版本混用就像兩個國家的人講話，日常用語大致相通，專業術語就容易雞同鴨講。標準訊息像速度、光達、影像通常沒問題，但 ROS 官方並不保證跨版本能互通，自訂訊息、Nav2、TF 這些比較容易出事。所以建議是：看資料、遙控可以直接用 Jazzy；要做認真的事，就在電腦上用 Docker 跑一個 Humble 容器，和車子同版本最穩。

### 5.1 風險整理

| 項目 | Jazzy 直接和車上 Humble 互通 | 說明 |
| --- | --- | --- |
| 標準訊息（`std_msgs`、`geometry_msgs`、`sensor_msgs`） | 通常可以 | 兩版預設都是 Fast DDS，但官方不保證跨版本 |
| `/scan`、`/cmd_vel` 看資料、遙控 | 通常可以 | 入門最常用 |
| Yahboom 自訂訊息（`yahboomcar_msgs` 等） | **很可能不行** | 電腦沒有這些套件，就算有，版本間定義也可能不同 |
| Nav2、TF、行為樹、參數服務 | 風險高 | 參數格式、外掛名稱在版本間有改（見 A2 第 6 節） |
| `RMW_IMPLEMENTATION` | 兩端要相同 | 都用預設的 Fast DDS 就好，不要一邊改成 Cyclone DDS |

### 5.2 建議：電腦端用 Docker 跑 Humble

先在 WSL 裡裝好 Docker Engine（例如 `sudo apt install docker.io`，並把自己加進 `docker` 群組），然後：

```bash title="在電腦 WSL（Jazzy）：只要指令列工具"
docker run -it --rm --net=host --ipc=host -e ROS_DOMAIN_ID=20 ros:humble bash
```

`ros:humble` 映像只有指令列工具，沒有 RViz。要開 RViz 用 `osrf/ros:humble-desktop`，並把 WSLg 的顯示通道帶進容器（需實機確認）：

```bash title="在電腦 WSL（Jazzy）：含 RViz 的 Humble 容器"
docker run -it --rm --net=host --ipc=host \
  -e ROS_DOMAIN_ID=20 \
  -e DISPLAY=$DISPLAY -e WAYLAND_DISPLAY=$WAYLAND_DISPLAY -e XDG_RUNTIME_DIR=$XDG_RUNTIME_DIR \
  -v /tmp/.X11-unix:/tmp/.X11-unix -v /mnt/wslg:/mnt/wslg \
  osrf/ros:humble-desktop bash
```

| 參數 | 為什麼要加 |
| --- | --- |
| `--net=host` | 容器用 WSL 的網卡，mirrored 模式下等於用 Windows 的網卡，才能和車互相探索 |
| `--ipc=host` | Fast DDS 在同一台機器上會用共享記憶體傳資料；不加的話，容器和 WSL 主機上的節點可能「看得到卻收不到」 |
| `-e ROS_DOMAIN_ID=20` | 和車同頻道 |
| `DISPLAY`、`/mnt/wslg` 等 | 讓容器裡的 RViz 視窗顯示在 Windows 桌面 |

:::tip
A3 多機導航的 `multi_nav_display_launch.py`、`map_server_launch.py` 需要 Yahboom 的 `yahboomcar_nav`、`yahboomcar_multi` 套件。可以把本專案 `source-code/` 裡的 `yahboomcar_ws/src` 掛進這個 Humble 容器再 `colcon build`；或直接用官方提供的 Humble 虛擬機。
:::

### 5.3 一張決策表

| 你想做的事 | 建議環境 |
| --- | --- |
| 看 `/scan`、`/odom`、遙控 `/cmd_vel` | 電腦 Jazzy 直接用 |
| 電腦 RViz 看建圖、導航畫面 | Jazzy 可以試；有怪問題就改 Docker `osrf/ros:humble-desktop` |
| 電腦跑 Yahboom 的 launch、自訂訊息、多機導航 RViz | Docker Humble 或官方 Humble 虛擬機 |
| 練習觀念、跑模擬（A1、A2 的模擬版） | 電腦 Jazzy（模擬全在電腦內，不跨版本） |

## 6. 在電腦 RViz 看車的 /scan 與地圖

> 🔊 最後來驗收。車上照常開 agent、進容器、跑底層 bringup，電腦這邊只要開 RViz。先看光達：把固定座標設成 laser frame，加一個雷射掃描的顯示，選 scan 話題，就會看到一圈點。再看地圖：車上開 Gmapping 建圖，電腦 RViz 把固定座標改成 map，加一個地圖顯示選 map 話題。這樣 Pi 5 不用自己畫圖，跑起來輕鬆很多。

### 6.1 車上

```bash title="在 Pi 5 主機"
sh ~/start_agent_rpi5.sh
```

```bash title="在車上 Docker 容器內（終端 A）"
ros2 launch yahboomcar_bringup yahboomcar_bringup_launch.py
```

```bash title="在車上 Docker 容器內（終端 B，docker exec 進同一個容器；要看地圖時才開）"
ros2 launch yahboomcar_nav map_gmapping_launch.py
```

建圖時一樣需要遙控（A1 第 4.2 節的 `yahboom_keyboard`）。這次**不用**在車上開 `display_launch.py`，RViz 改在電腦開。

### 6.2 電腦

```bash title="在電腦 WSL（Jazzy）（或第 5.2 節的 Humble 容器內）"
rviz2
```

**看光達：**

1. 左側 **Global Options → Fixed Frame** 輸入 `laser_frame`。
2. 左下 **Add → By topic → `/scan` → LaserScan**。
3. 看不到點：展開 LaserScan → **Topic → Reliability Policy** 改 `Best Effort`；**Size (m)** 調大到 `0.05`。

**看地圖：**

1. Fixed Frame 改成 `map`（要等車上的 gmapping 開始發布 `map → odom`）。
2. **Add → By topic → `/map` → Map**。
3. 地圖沒出現：展開 Map → **Topic → Durability Policy** 改 `Transient Local`。
4. 再加 **TF** 顯示，可以看到 `map`、`odom`、`base_footprint`、`laser_frame` 的座標軸跟著車移動。

:::info
`/scan` 的 `frame_id` 是 `laser_frame`（ESP32 韌體設定），所以只看光達時不需要任何 TF，Fixed Frame 直接設 `laser_frame` 最簡單。要在 `map` 或 `odom` 座標下看光達，就需要車上 bringup 與建圖節點提供完整 TF 鏈。
:::

:::tip
WiFi 頻寬有限。電腦遠端看 `/scan` 和 `/map` 很順，但若同時遠端看相機影像（`/usb_cam/image_raw`），可能會卡；看影像請用壓縮話題 `/usb_cam/image_raw/compressed`。
:::

## 7. 出問題時怎麼辦

> 🔊 電腦和車連不起來時，請從下往上一層一層查：先確認網路通不通，再確認頻道一不一樣，接著確認探索有沒有被擋，最後才是版本和 QoS 的問題。每改一個設定，都記得重啟 ros2 daemon。用 ping 確認網路、用 talker 和 listener 確認探索，是最快的兩個檢查。

### 7.1 由下往上的檢查順序

```bash title="在電腦 WSL（Jazzy）：1. 網路通不通"
ping -c 3 10.42.0.1
```

```bash title="在電腦 WSL（Jazzy）：2. 頻道與探索設定"
echo $ROS_DOMAIN_ID
echo $ROS_AUTOMATIC_DISCOVERY_RANGE
echo $ROS_LOCALHOST_ONLY
ros2 daemon stop
ros2 node list
```

```bash title="在車上 Docker 容器內：3. 車上自己看得到嗎"
ros2 node list
ros2 topic hz /scan
```

### 7.2 症狀對照表

| 症狀 | 最可能的原因 | 怎麼做 |
| --- | --- | --- |
| `ping` 不通 | 電腦和車不在同一網路 | 電腦連 `Micro_ros` 熱點，或兩邊都連同一個路由器 |
| WSL 的 `ip addr` 是 `172.x.x.x` | mirrored 沒生效 | 檢查 `%USERPROFILE%\.wslconfig`；`wsl --shutdown` 後重開 |
| `ping` 通，`ros2 node list` 卻空的 | Domain ID 不同，或 daemon 快取舊資料 | 兩邊都設 `20`；`ros2 daemon stop` |
| 還是空的 | 多播被擋、防火牆 | 試 `ROS_STATIC_PEERS=10.42.0.1`；照 3.3 節放行 Hyper-V 防火牆 |
| 電腦能發給車、車的資料電腦收不到 | Windows 防火牆擋連入 | 照 3.3 節；或暫時關閉防火牆測試，確認後再設規則 |
| 看得到話題名稱，`echo` 卻沒資料 | QoS 不相容，或 Docker 容器少了 `--ipc=host` | `ros2 topic echo /scan --qos-reliability best_effort` 試試；容器加 `--ipc=host` |
| RViz 有 `/scan` 但沒有點 | Fixed Frame 錯、Reliability 不符 | Fixed Frame 設 `laser_frame`；Reliability 改 Best Effort |
| RViz 的 Map 一直顯示 No map received | 建圖節點沒開，或 Durability 不符 | 車上開 gmapping；Durability 改 Transient Local |
| 車上看不到 `/YB_Car_Node` | 控制板與容器 Domain ID 不同，或 agent 沒連上 | 容器 `vi ~/.bashrc` 改 `ROS_DOMAIN_ID`；Pi 5 主機重開 agent、按 Reset |
| 自訂訊息的話題在電腦上顯示不出來 | 電腦沒有該訊息套件，或 Humble／Jazzy 定義不同 | 改用 Docker Humble 並編譯 Yahboom 套件 |
| `ros2` 指令在電腦上變很慢、列出一堆陌生節點 | 同網路有其他人也用 Domain 20 | 換一個 Domain ID（三個地方都要改） |
