## 1. 為什麼要「融合」：輪子和陀螺儀各有盲點

> 🔊 上一課我們看到兩個會報告「車子在哪裡」的話題。odom 底線 raw 是數輪子轉了幾圈推算的，就像閉著眼睛數步數走路，走越久越偏，輪子一打滑它也不知道。imu 是陀螺儀，轉了多少角度它很敏感，但它算不出自己往前走了多遠。
> 所以 ROS 用一個叫擴展卡爾曼濾波器的方法，簡稱 EKF，把兩邊的資料「加權平均」：位置主要相信輪子，轉向角度多相信陀螺儀，得到一個比較準的 odom。之後的建圖和導航，用的都是這個融合後的結果。

| 感測器 | 擅長 | 弱點 |
| --- | --- | --- |
| 輪式里程計 `/odom_raw` | 走了多遠、速度 | 打滑、輪徑誤差會累積；轉彎角度容易不準 |
| IMU `/imu` | 轉了多少角度（角速度） | 不知道位移；會慢慢漂移 |
| EKF 融合 `/odom` | 兩者互補 | 仍然會累積誤差，只是慢很多 |

本課的資料流（依官方 05-4 與原始碼）：

```text title="示意圖（不用執行）"
 /imu ──► IMU 濾波節點 ──► /imu/data ──┐
                                       ├──► /ekf_filter_node ──► /odom ＋ TF：odom → base_footprint
 /odom_raw ────────────────────────────┘
 robot_state_publisher（URDF）──► TF：base_footprint → base_link → 各輪子、雲台…
```

## 2. 啟動底層：yahboomcar_bringup_launch.py

> 🔊 照之前的流程啟動 agent、進入容器之後，執行一行 ros2 launch，把底層資料處理一次全部打開。launch 檔就像一份開機清單，一次幫你啟動好幾個節點。
> 這份清單裡有四樣東西：IMU 濾波、EKF 融合、一個描述陀螺儀裝在車上哪裡的靜態座標轉換，以及載入車子的 URDF 模型。啟動時畫面最上面會印出 robot type 等於 x3，那是沿用別款車的程式留下的字，不用理它。

準備（同 B5）：關自動終端機 → `sh ~/start_agent_rpi5.sh`（按 Reset）→ `sh ros2_humble.sh` → 容器內暫時關掉手把。然後：

```bash title="在車上 Docker 容器內"
ros2 launch yahboomcar_bringup yahboomcar_bringup_launch.py
```

這個終端機會一直被占著。開新的 Pi 5 終端機，`docker ps -a` 查 ID，`docker exec -it <ID> /bin/bash` 進**同一個容器**，然後檢查：

```bash title="在車上 Docker 容器內"
ros2 node list
ros2 node info /ekf_filter_node
ros2 topic list | grep -E "odom|imu"
```

預期 `/ekf_filter_node` 訂閱 `/imu/data` 與 `/odom_raw`，發布 `/odom`。在 VNC 桌面的終端機看關係圖：

```bash title="在車上 Docker 容器內"
ros2 run rqt_graph rqt_graph
```

（沒顯示就選 **Nodes/Topics (all)** 再按左上角重新整理。）

**launch 檔啟動了什麼**（容器內路徑 `/root/yahboomcar_ws/src/yahboomcar_bringup/launch/yahboomcar_bringup_launch.py`）：

| 項目 | 內容 | 作用 |
| --- | --- | --- |
| IMU 濾波 | 把 `/imu` 濾波成 `/imu/data` | 去雜訊、估姿態 |
| `robot_localization` 的 `ekf.launch.py` | 節點 `ekf_filter_node` | 融合，輸出 `/odom` |
| `static_transform_publisher`（名稱 `base_link_to_base_imu`） | `-0.002999 -0.0030001 0.031701 0 0 0 base_link imu_frame` | 告訴 ROS 陀螺儀裝在車身中心偏哪裡 |
| `yahboomcar_description` 的 `description_launch.py` | `robot_state_publisher`＋`joint_state_publisher`＋靜態 TF `base_footprint → base_link`（高 0.05 公尺） | 載入 URDF |

:::warn
IMU 濾波用哪個套件，文件與原始碼不一致：官方 05-4 文件寫的是 `imu_filter_madgwick` 的 `imu_filter.launch.py`；但官方原始碼包裡的 `yahboomcar_bringup_launch.py` 改成了 `imu_complementary_filter` 的 `complementary_filter.launch.py`（節點名 `complementary_filter_gain_node`）。兩者都把 `/imu` 轉成 `/imu/data`，功能相同。**2026-10-28 實車確認：這台車是 `complementary_filter_gain_node`（互補濾波）**。另外文件寫「launch 檔位置以配套虛擬機為例」，但列的是容器內路徑 `/root/yahboomcar_ws/...`，在車上請以容器內為準。
:::

## 3. EKF 的設定檔讀懂三件事

> 🔊 EKF 的設定檔很長，有一大片矩陣，初學者只要看懂三件事就夠了。第一，它是二維模式，因為車子在地板上跑，不會飛起來。第二，它從哪裡拿資料：輪子里程提供位置、速度和轉向，陀螺儀只提供轉向角和轉向速度。第三，它輸出的話題被改名成 odom，並且負責發布 odom 到 base footprint 的座標轉換。
> 有了這個座標轉換，任何程式都能問「車子現在離出發點多遠」，下一節的校準程式就是這樣算距離的。

原始碼包 `robot_localization/params/ekf.yaml` 的重點（`ekf.launch.py` 把 `/odometry/filtered` 改名為 `/odom`）：

```yaml title="在車上 Docker 容器內"
ekf_filter_node:
    ros__parameters:
        frequency: 30.0
        two_d_mode: true
        publish_tf: true
        odom_frame: odom
        base_link_frame: base_footprint
        world_frame: odom
        odom0: /odom_raw
        odom0_config: [true, true, false,
                       false, false, true,
                       true, true, false,
                       false, false, true,
                       false, false, false]
        imu0: /imu/data
        imu0_config: [false, false, false,
                      false, false, true,
                      false, false, false,
                      false, false, true,
                      false, false, false]
        imu0_relative: true
```

`*_config` 的 15 個 true／false 依序是：`x y z`、`roll pitch yaw`、`vx vy vz`、`vroll vpitch vyaw`、`ax ay az`。

| 來源 | 採用的量 |
| --- | --- |
| `/odom_raw` | x、y 位置；yaw 角；vx、vy 速度；yaw 角速度 |
| `/imu/data` | yaw 角；yaw 角速度 |

用 TF 工具直接問「車子在哪」（車子靜止時數字應該幾乎不動）：

```bash title="在車上 Docker 容器內"
ros2 run tf2_ros tf2_echo odom base_footprint
```

:::tip
官方 Lidar 課提醒：建圖、導航前要把車放平、靜止約 5 秒，讓 IMU 完成初始化，否則 rviz 裡的模型會自己慢慢旋轉。校準前也一樣，先靜置再開始。
:::

## 4. 線速度校準：叫它走 1 公尺，量量看

> 🔊 校準的想法很簡單：叫車子走一公尺，再拿捲尺量它真的走了多少。程式靠剛才的座標轉換算出「自己以為走了多遠」，乘上一個比例係數，等到它以為走滿一公尺就停車。
> 如果捲尺量出來不是一公尺，就調整那個比例係數。調整工具叫 rqt reconfigure，是一個可以邊跑邊改參數的視窗。改完數字一定要用滑鼠點一下旁邊空白處，數字才會真的寫進去，這是官方特別提醒、很多人會漏掉的步驟。

**場地**：平坦地面，車子**前後都留 1.5 公尺以上**空間，旁邊放捲尺；在車輪旁地上貼一段膠帶當起點。

需要三個容器終端機（第二、三個都用 `docker exec` 進同一容器）：

```bash title="在車上 Docker 容器內"
ros2 launch yahboomcar_bringup yahboomcar_bringup_launch.py
```

```bash title="在車上 Docker 容器內"
ros2 run yahboomcar_bringup calibrate_linear
```

```bash title="在車上 Docker 容器內"
ros2 run rqt_reconfigure rqt_reconfigure
```

**操作**（官方 05-5、影片 UZIGEVnOjmY）：

1. rqt_reconfigure 剛開時可能是空的，按 **Refresh** 才看得到節點。
2. 左邊點選 **`calibrate_linear`**。
3. 勾選 **`start_test`** → 車子開始移動，到達後自動停車，`start_test` 會自己取消勾選。
4. 用捲尺量實際移動距離。
5. 不是 1 公尺 → 修改 **`odom_linear_scale_correction`** → **點一下空白處** → 再勾 `start_test` 測一次。

| 參數 | 原始碼預設 | 意義 |
| --- | --- | --- |
| `test_distance` | `1.0` | 測試距離（公尺） |
| `speed` | `0.5` | 測試時的線速度（公尺／秒） |
| `tolerance` | `0.03` | 容許誤差（公尺） |
| `odom_linear_scale_correction` | `1.5` | 比例係數：里程距離 × 係數 ＝ 程式認定的距離 |
| `start_test` | `False` | 開始開關 |
| `direction` | `True` | 給麥克納姆輪車測左右平移用，**本車忽略** |
| `base_frame`／`odom_frame` | `base_footprint`／`odom` | 用哪兩個座標系算距離 |

**怎麼調係數**：程式在「里程 × 係數 ＝ 1 公尺」時停車。所以

- 車子**走太短**（例如 0.8 公尺）→ 係數太大 → **調小**：新係數 ≈ 舊係數 × 實際距離 ÷ 1。
- 車子**走太長**（例如 1.2 公尺）→ 係數太小 → **調大**，同一個公式。

例：舊係數 1.5、實際走 0.8 公尺 → 新係數 ≈ 1.5 × 0.8 ＝ 1.2。

:::warn
以下是讀原始碼 `calibrate_linear.py` 得到的推論，請在實車上留意（需實車確認）：

1. 程式把起點固定當成 `(0, 0)`，不是按下 `start_test` 當下的位置。所以**每次測試前**最好依序：按擴展板 Reset 讓里程歸零、重新啟動 bringup、重新啟動 `calibrate_linear`；否則第二次測試會從上一次停下的地方「接著算」。
2. 程式用 `copysign(speed, error)` 決定方向，起點時誤差是負的，**車子可能是往後倒退 1 公尺**而不是往前。所以前後都要留空間。
3. 這個係數只存在校準節點裡，原始碼沒有把它寫回 ESP32 或 EKF。它的用途是「量出你這台車的里程偏差有多大」，請把最後的數字抄下來，之後自己寫控制程式（M5）時可以用。

:::

:::info
**2026-10-28 實車結果（電池 7.0 V）**
- 原始碼預設 `speed` 0.5 m/s 太快，用 `ros2 run yahboomcar_bringup calibrate_linear --ros-args -p speed:=0.1` 降速；不開 rqt_reconfigure，直接 `ros2 param set /calibrate_linear start_test true` 也能啟動。
- **確認車子往後倒退**（推論 2 正確），11 秒停。捲尺量約 70 cm；TF（`odom→base_footprint`）70.4 cm，側偏 6.3 cm。里程誤差 < 1%，預設係數 1.5 讓車只走 2/3 公尺 → 這台車應約 **1.05**。
:::

## 5. 角速度校準：叫它轉 360 度

> 🔊 角速度校準和線速度一模一樣，只是把「走一公尺」換成「轉一圈」。程式累加車子轉過的角度，乘上比例係數，等到它以為轉滿三百六十度就停。
> 你要觀察車頭最後有沒有回到原本的方向。可以在地上貼一條膠帶對齊車頭，轉完看看差了幾度。轉太多或太少，就調 odom angular scale correction，一樣改完要點一下空白處。

先在地上貼膠帶對齊車頭方向。三個容器終端機（同一容器）：

```bash title="在車上 Docker 容器內"
ros2 launch yahboomcar_bringup yahboomcar_bringup_launch.py
```

```bash title="在車上 Docker 容器內"
ros2 run yahboomcar_bringup calibrate_angular
```

```bash title="在車上 Docker 容器內"
ros2 run rqt_reconfigure rqt_reconfigure
```

操作同線速度：**Refresh** → 選 **`calibrate_angular`** → 勾 **`start_test`** → 看車頭轉完是否對齊膠帶 → 調整 **`odom_angular_scale_correction`** → 點空白處 → 再測。

:::info
**2026-10-28 實車結果**：預設 `speed` 2.0 rad/s 太快，用 `-p speed:=0.8`。11 秒停，車頭停在膠帶**左邊約 10°**（實轉約 370°）；程式自己累加到 478° × 0.75 = 358.5° 判定完成；TF 顯示約 385°。這台車的角速度係數應約 **0.77**（0.75 × 370 ÷ 358.5）。
:::

| 參數 | 原始碼預設 | 意義 |
| --- | --- | --- |
| `test_angle` | `360.0` | 測試角度（度，程式內轉成弧度） |
| `speed` | `2.0` | 測試時的角速度（弧度／秒） |
| `tolerance` | `1.5` | 容許誤差（與弧度比較） |
| `odom_angular_scale_correction` | `0.75` | 比例係數：里程角度 × 係數 ＝ 程式認定的角度 |
| `start_test` | `False` | 開始開關 |
| `base_frame`／`odom_frame` | `base_footprint`／`odom` | 用哪兩個座標系算角度 |

調法同上：轉**不到**一圈 → 係數調小；轉**超過**一圈 → 係數調大；新係數 ≈ 舊係數 × 實際轉的角度 ÷ 360。

:::warn
官方 05-6 文件把 `odom_angular_scale_correction` 寫成「線速度比例係數」，那是複製貼上的筆誤，它是**角速度**比例係數。另外依原始碼推論（需實車確認）：`tolerance` 預設 1.5 是直接和**弧度**比較，1.5 弧度約 86 度，車子可能提早停下；若轉不到一圈很多，可以先把 `tolerance` 改成 `0.05` 再測。程式每測一次會**自動反轉方向**（這次逆時針、下次順時針），而且起始角度固定當成 0，建議每次測試前也照線速度那樣重設里程。
:::

## 6. URDF：在 rviz2 看到車子的 3D 模型

> 🔊 最後來看車子的「數位分身」。URDF 是一種用 XML 寫的機器人說明書，記錄車子由哪些零件組成，叫做連桿，零件之間怎麼接，叫做關節，像輪子是可以一直轉的關節，雲台是有角度限制的關節。
> 啟動 display launch 會跳出一個滑桿視窗，再開 rviz2 加入機器人模型，拖動滑桿，就能看到畫面裡的輪子和雲台跟著轉。這和暖身課 W4 在電腦上做的一樣，只是這次是在真車上。注意樹莓派跑 rviz2 會比較卡，耐心等一下。

**先關掉第 2 節的 bringup**（Ctrl+C），因為兩個 launch 都會啟動 `robot_state_publisher`，同時開會重複。然後：

```bash title="在車上 Docker 容器內"
ros2 launch yahboomcar_description display_launch.py
```

另一個容器終端機（`docker exec` 進同一容器，在 VNC 桌面執行）：

```bash title="在車上 Docker 容器內"
rviz2
```

rviz2 操作（官方 05-7、影片 AAI_SxInfI4）：

1. 左下 **Add** → 選 **RobotModel** → OK。
2. 展開 RobotModel → **Description Topic** 選 **`/robot_description`**。
3. 左上 Global Options → **Fixed Frame** 改成 **`base_link`**。
4. 用滑鼠調整視角，拖動 Joint State Publisher 視窗的滑桿。

:::warn
官方文件寫「Fixed Frame 改為 `base_linke`」，多打了一個 e，正確是 **`base_link`**。
:::

**滑桿對應的關節**（URDF 檔 `urdf/MicroROS.urdf`，`<robot name="micro4.0">`）：

| 關節 | 控制 | 類型 |
| --- | --- | --- |
| `zq_Joint` | 左前輪（左前＝zuo qian） | `continuous`（無限轉動） |
| `yq_Joint` | 右前輪 | `continuous` |
| `yh_Joint` | 右後輪 | `continuous` |
| `zh_Joint` | 左後輪 | `continuous` |
| `jq1_Joint` | 雲台 1 | 有限位，約 ±1.57 弧度（±90 度） |
| `jq2_Joint` | 雲台 2 | 有限位，約 ±1.57 弧度 |
| Randomize | 每個關節隨機給值 | — |
| Center | 全部回中 | — |

`display_launch.py` 啟動三樣東西：`joint_state_publisher_gui`（滑桿視窗）、`robot_state_publisher`（把 URDF ＋ 關節角度轉成 TF 與 `/robot_description`）、靜態 TF `base_footprint → base_link`（`0 0 0.05 0 0 0`）。它和 bringup 用的 `description_launch.py` 唯一差別是滑桿版的 `joint_state_publisher_gui`。

URDF 片段範例（左前輪關節，原始碼）：

```xml title="在車上 Docker 容器內"
<joint name="zq_Joint" type="continuous">
  <origin xyz="0.0455 0.0675 -0.02125" rpy="0 0 0" />
  <parent link="base_link" />
  <child link="zq_Link" />
  <axis xyz="0 1 0" />
</joint>
```

讀法：輪子接在 `base_link` 上，位置在車身中心前方 4.55 公分、左邊 6.75 公分、下方約 2.1 公分，繞 Y 軸（左右方向的軸）無限旋轉。

:::tip
rviz2 在 Pi 5 上很吃效能。之後 A5 單元會教你在自己的電腦開 rviz2，透過網路看車上的資料，會順暢很多。
:::

## 7. 出問題時怎麼辦

> 🔊 這一課最常見的問題有三類。第一類是校準程式印出 transform not ready，意思是它問不到車子在哪，通常是忘了先開 bringup，或 bringup 開在另一個容器裡。第二類是 rqt reconfigure 視窗空空的，按一下 Refresh 就好。
> 第三類是校準結果每次都不一樣，這多半跟地面打滑、電量不足、或里程沒歸零有關。換一塊不滑的地面、充飽電、每次重設里程，再取三次平均，會穩定很多。

| 症狀 | 可能原因 | 解法 |
| --- | --- | --- |
| 開頭印 `robot_type = x3` | 沿用其他車型的程式 | 正常，忽略 |

| 每次結果差很多 | 地面打滑、電量不足、IMU 沒靜置 | 換不滑的地面、充飽電、開始前靜置 5 秒、取三次平均 |
| 建圖或導航時說拿不到即時 TF | 時間不同步 | 官方 FAQ 第 8 題：按 Reset 重新連 agent |
| rviz2 看不到車子模型 | Description Topic 沒選、Fixed Frame 錯 | 選 `/robot_description`；Fixed Frame 用 `base_link`（不是 `base_linke`） |
| rviz2 模型一片白或缺零件 | mesh 檔載入慢或路徑問題 | 等一下；確認 `display_launch.py` 沒有報錯 |
| rviz2／rqt 視窗打不開 | 在 SSH 終端機執行 | 改在 VNC 桌面的終端機 |
| 滑桿拖動但模型不動 | 同時開了 bringup，兩份 `robot_state_publisher` 打架 | 關掉 bringup，只留 `display_launch.py` |
