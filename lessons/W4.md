## 1. 機器人也需要一份「身體說明書」

> 🔊 前面我們讓小烏龜在平面上跑，但真正的車子是立體的，有輪子、有光達、有會轉的雲台。
> 程式要怎麼知道光達裝在車子中心前面幾公分、高幾公分？相機轉了三十度之後在看哪裡？
> 答案是一份身體說明書，叫做 URDF。它像一張骨架圖，寫清楚機器人有哪些骨頭、骨頭之間用什麼關節連起來。
> 有了它，RViz 才能畫出車子的樣子，TF 才能算出每個零件在空間中的位置。這個單元完全在電腦上做，不需要真車。

這個單元會用到三個工具：

| 工具 | 是什麼 | 比喻 |
| --- | --- | --- |
| URDF（Unified Robot Description Format，統一機器人描述格式） | 用 XML 寫的機器人結構檔 | 骨架圖 |
| RViz（rviz2） | ROS 的 3D 資料視覺化工具 | 透視鏡，讓你「看見」程式裡的資料 |
| TF（tf2，座標轉換） | 記錄每個零件座標系之間的相對位置 | 家族族譜：每個人都記得「我在爸爸的哪裡」 |

:::info
本單元在電腦上用本課程附的模擬套件 `microros_pi5_sim`（放在 `~/yahboom_ws`），它是根據這台車原始碼裡的 `MicroROS.urdf` 改的，零件名稱和真車相同。
:::

## 2. URDF 的兩種積木：link 與 joint

> 🔊 URDF 只有兩種主要積木。第一種是 link，中文叫連桿，就是一塊硬梆梆不會變形的零件，例如車身、一顆輪子、光達。
> 第二種是 joint，關節，負責把兩個 link 接起來，並規定它們可以怎麼動。
> 每個關節都有一個爸爸 parent 和一個小孩 child，還會寫小孩離爸爸多遠、繞哪個軸轉。
> 常見的關節有三種：可以一直轉的 continuous，像輪子；有角度限制的 revolute，像雲台；完全不動的 fixed，像鎖死在車上的光達。

**link 的內容**

| 標籤 | 用途 |
| --- | --- |
| `<visual>` | 外觀：形狀（這台車用 STL 網格檔）、顏色、位置偏移 |
| `<collision>` | 碰撞外形（模擬與避障用） |
| `<inertial>` | 質量、慣性（物理模擬用） |

**joint 的類型**

| 類型 | 動法 | 這台車上的例子 |
| --- | --- | --- |
| `continuous` | 無限旋轉 | 四顆輪子 |
| `revolute` | 有上下限的旋轉 | 雲台兩軸 |
| `fixed` | 固定不動 | IMU、光達 |
| `prismatic` | 直線滑動 | （本車沒有） |
| `floating`、`planar` | 浮動、平面 | 少用 |

**一個真實的 joint**（摘自原始碼 `MicroROS.urdf`，左前輪）：

```xml
<joint name="zq_Joint" type="continuous">
  <origin xyz="0.0455 0.0675 -0.02125" rpy="0 0 0" />   <!-- 輪子在車身中心前 4.55 cm、左 6.75 cm、下 2.1 cm -->
  <parent link="base_link" />                          <!-- 爸爸：車身 -->
  <child link="zq_Link" />                             <!-- 小孩：左前輪 -->
  <axis xyz="0 1 0" />                                  <!-- 繞 y 軸（左右方向）轉 -->
</joint>
```

:::tip
ROS 的座標慣例：**x 朝前、y 朝左、z 朝上**，單位是公尺與弧度。`rpy` 是 roll、pitch、yaw（繞 x、y、z 的旋轉角）。
:::

## 3. 拆解這台車的 MicroROS.urdf

> 🔊 現在來認識這台車骨架上的每一塊骨頭。名字是拼音縮寫，記起來很快：z 是左、y 是右、q 是前、h 是後。
> 所以 zq 是左前輪、yq 是右前輪、yh 是右後輪、zh 是左後輪。jq 是雲台，jq1 負責左右轉，jq2 疊在 jq1 上面，負責上下點頭。
> 所有零件的爸爸都是 base link，也就是車身，只有 jq2 的爸爸是 jq1。這種一層接一層的關係，就是下一節要講的 TF 樹。

原始碼位置：`yahboomcar_ws/src/yahboomcar_description/urdf/MicroROS.urdf`，`<robot name="micro4.0">`，共 9 個 link、8 個 joint。

| joint | 類型 | parent → child | 零件 | 位置 xyz（公尺） |
| --- | --- | --- | --- | --- |
| `zq_Joint` | continuous | `base_link` → `zq_Link` | 左前輪 | 0.0455, 0.0675, -0.02125 |
| `yq_Joint` | continuous | `base_link` → `yq_Link` | 右前輪 | 0.0455, -0.0675, -0.02125 |
| `yh_Joint` | continuous | `base_link` → `yh_Link` | 右後輪 | -0.0495, -0.0675, -0.02125 |
| `zh_Joint` | continuous | `base_link` → `zh_Link` | 左後輪 | -0.0495, 0.0675, -0.02125 |
| `imu_Joint` | fixed | `base_link` → `imu_Link` | IMU | -0.003, -0.003, 0.0317 |
| `radar_Joint` | fixed | `base_link` → `radar_Link` | MS200 光達 | 0, 0, 0.0789 |
| `jq1_Joint` | revolute（繞 z，±1.57 rad） | `base_link` → `jq1_Link` | 雲台左右（舵機 S1） | 0.064, 0, 0.014 |
| `jq2_Joint` | revolute（繞 y，±1.57 rad） | `jq1_Link` → `jq2_Link` | 雲台上下（舵機 S2） | 0.0169, 0, 0.024 |

```text
base_link（車身，約 0.22 kg）
├── zq_Link   左前輪   ┐
├── yq_Link   右前輪   │ continuous
├── yh_Link   右後輪   │
├── zh_Link   左後輪   ┘
├── imu_Link  IMU        fixed
├── radar_Link 光達      fixed
└── jq1_Link  雲台左右   revolute
    └── jq2_Link 雲台上下 revolute
```

:::warn
**URDF 的角度範圍和真實舵機不同**：URDF 兩個雲台關節都寫 ±1.57 rad（±90°），但真車的 `/servo_s2` 只接受 [-90, 20] 度（往上最多 20°）。RViz 滑桿拉得到的角度，真車不一定做得到。另外原始碼的 URDF **沒有相機 link**；電腦模擬套件為了在 Gazebo 產生影像，多加了一個 `camera_link`。
:::

## 4. 在 RViz 看模型、拖關節

> 🔊 理論夠了，來動手。在 WSL 進到工作空間，載入環境，再執行 display 這個 launch 檔。
> 它會同時開三個東西：一個是 robot state publisher，負責讀 URDF 並算出每個零件的位置；一個是關節滑桿視窗；還有 RViz。
> 拉動滑桿，你會看到 RViz 裡的輪子跟著轉、雲台跟著擺頭。這就是本單元的過關標準。
> 如果畫面一片空白，通常是左上角的 Fixed Frame 選錯了，把它改成 base link 就好。

```bash title="在電腦 WSL（Jazzy）"
cd ~/yahboom_ws && source install/setup.bash
ros2 launch microros_pi5_sim display.launch.xml      # RViz＋關節滑桿，看車的模型
```

**畫面上會出現**

| 視窗 | 用途 |
| --- | --- |
| Joint State Publisher（滑桿） | 6 個可動關節：`zq_Joint`、`yq_Joint`、`yh_Joint`、`zh_Joint`、`jq1_Joint`、`jq2_Joint`；`Randomize` 隨機、`Center` 全部歸零 |
| RViz | 3D 模型與座標軸 |

**RViz 設定（若沒有自動設好）**

1. 左上 **Global Options → Fixed Frame** 選 `base_link`。
2. 左下 **Add** → **RobotModel** → Description Topic 選 `/robot_description`。
3. 再 **Add** → **TF**，勾選 Show Names，就能看到每個零件的座標軸（紅 x、綠 y、藍 z）。

**觀察這些話題**

```bash title="在電腦 WSL（Jazzy）另一個終端機"
source ~/yahboom_ws/install/setup.bash
ros2 node list                      # /robot_state_publisher、/joint_state_publisher_gui、/rviz2
ros2 topic echo /joint_states       # 拉滑桿時數值會變（輪子和雲台的角度，單位弧度）
ros2 topic echo /robot_description --once   # 整份 URDF 被當成一個話題發出來
```

資料流：滑桿 `joint_state_publisher_gui` ──`/joint_states`──▶ `robot_state_publisher`（＋URDF）──`/tf`、`/tf_static`──▶ RViz。

## 5. TF：座標系的家族族譜

> 🔊 TF 是 ROS 最重要、也最容易讓人頭痛的觀念，我們用族譜來想。每個零件都有自己的座標系，而每個座標系只需要記住一件事：我在爸爸的哪裡、轉了幾度。
> 只要族譜連通，ROS 就能算出任何兩個零件的相對位置，例如光達看到的障礙物，在車身中心的哪裡。
> 固定不動的關係放在 tf static；會變的關係，例如輪子轉動、車子移動，放在 tf。
> 用 view frames 可以把整棵族譜畫成一個 PDF 檔。

```bash title="在電腦 WSL（Jazzy）"
ros2 run tf2_tools view_frames
# 約 5 秒後在目前資料夾產生 frames 開頭的 .pdf，用檔案總管打開看
explorer.exe .
```

```bash title="在電腦 WSL（Jazzy）"
ros2 run tf2_ros tf2_echo base_link radar_Link   # 光達相對車身：約 z=0.079 公尺，不會變
ros2 run tf2_ros tf2_echo base_link jq2_Link     # 拉雲台滑桿時這裡的數值會變
```

| 話題 | 放什麼 | 這台車的例子 |
| --- | --- | --- |
| `/tf_static` | 永遠不變的關係（fixed joint、靜態轉換） | `base_link → radar_Link`、`base_link → imu_Link` |
| `/tf` | 會變的關係 | 輪子、雲台關節；`odom → base_footprint`（車在地上的位置） |

**真車跑起來之後的完整 TF 樹**（依原始碼的 launch 檔整理）：

```text
map（A1 建圖、A2 導航時才有）
└── odom
    └── base_footprint        ← EKF 融合 /odom_raw＋IMU 後發布（yahboomcar_bringup_launch.py）
        └── base_link         ← 靜態，往上 0.05 公尺（display_launch.py／description_launch.py）
            ├── 4 個輪子、jq1_Link → jq2_Link、imu_Link、radar_Link   ← robot_state_publisher 讀 URDF
            ├── imu_frame     ← 靜態 TF，/imu 訊息用的 frame
            └── laser_frame   ← 靜態 TF（建圖、導航 launch 裡），/scan 訊息用的 frame
```

:::warn
**真車上感測器的 frame 名稱和 URDF 的 link 名稱不一樣**：`/imu` 用 `imu_frame`、`/scan` 用 `laser_frame`，而 URDF 裡叫 `imu_Link`、`radar_Link`。所以原廠另外用 `static_transform_publisher` 補了 `base_link → imu_frame`、`base_link → laser_frame`。在 RViz 看光達資料時，如果出現找不到 frame 的錯誤，就是這段 TF 沒有在跑（需實車確認）。電腦模擬套件則直接用 `radar_Link`、`imu_Link` 當 frame。
:::

## 6. 在 Gazebo 讓模擬車跑起來

> 🔊 只看模型還不夠過癮，我們讓模擬車真的跑。Gazebo 是一個物理模擬器，會模擬重力、摩擦和光達的雷射。
> 模擬車和真車一樣，聽 cmd vel 話題的速度指令，也會發出 scan、odom、imu。也就是說，你在這裡寫的程式和下的指令，之後幾乎可以原封不動搬到真車上。
> 啟動之後，用上一個單元學的 ros2 topic pub 讓車慢慢轉圈，再看 RViz 裡的光達紅點跟著轉動。

```bash title="在電腦 WSL（Jazzy）"
cd ~/yahboom_ws && source install/setup.bash
ros2 launch microros_pi5_sim sim.launch.xml          # Gazebo 模擬：車可接 /cmd_vel、發 /scan /odom /imu
```

```bash title="在電腦 WSL（Jazzy）另一個終端機"
source ~/yahboom_ws/install/setup.bash
ros2 topic list                                     # 應看到 /cmd_vel、/scan、/odom、/imu、/tf
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.1}, angular: {z: 0.5}}"
# Ctrl+C 後再發一次零速度讓車停
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0}, angular: {z: 0.0}}"
```

**在 RViz 加光達與里程**（若沒有自動開 RViz，另開終端執行 `rviz2`）：

1. **Fixed Frame** 改成 `odom`（車子移動時，模型會在畫面上移動）。
2. **Add → LaserScan**，Topic 選 `/scan`，看到一圈紅點就是光達打到牆的位置。
3. **Add → Odometry**，Topic 選 `/odom`，會畫出車子走過的箭頭。

| 模擬（電腦） | 真車 |
| --- | --- |
| Gazebo 的差速驅動外掛 | ESP32 `/YB_Car_Node` 驅動 4 顆馬達 |
| ros_gz_bridge 把 Gazebo 話題轉成 ROS 2 | micro-ROS agent 把 ESP32 話題轉成 ROS 2 |
| `/odom`（模擬器直接給） | `/odom_raw`（輪子）→ EKF → `/odom` |
| `/scan`、`/imu` | `/scan`、`/imu` |

**模擬常見問題**

| 現象 | 可能原因 | 解法 |
| --- | --- | --- |
| Gazebo 視窗全黑或很卡 | WSL 的顯示卡加速不足 | 先 `wsl --shutdown` 重開；仍不行可試 `LIBGL_ALWAYS_SOFTWARE=1` 再啟動 |
| `ros2 topic list` 看不到 `/scan` | 模擬還在載入，或終端沒 `source` | 等 10 秒；確認有 `source ~/yahboom_ws/install/setup.bash` |
| 發了 `/cmd_vel` 車不動 | Gazebo 暫停中，或訊息格式打錯 | 按 Gazebo 左下播放鍵；`ros2 topic info /cmd_vel` 確認型別是 `geometry_msgs/msg/Twist` |
| RViz 跳出 frame 不存在的警告 | Fixed Frame 設成不存在的座標系 | 改成 `odom` 或 `base_link` |

:::info
真車上車體用 4 個馬達各自驅動，但轉彎方式和兩輪差速車一樣（左右兩側速度不同），所以模擬用差速驅動外掛就夠了。Humble 的教材用的是舊的 Gazebo Classic，Jazzy 用的是新的 gz sim，兩者指令不同，本課程的模擬一律以 `microros_pi5_sim` 為準。
:::

## 7. 真車上怎麼做

> 🔊 等車子到了，同樣的事情在車上怎麼做？先照第三單元的流程，開翻譯官、進 ROS 2 容器。
> 然後在容器裡執行 yahboomcar description 套件的 display launch 檔，它會開關節滑桿和 robot state publisher，但不會自動開 RViz。
> 所以要用 docker exec 再開一個終端進同一個容器，執行 rviz2，加上 RobotModel。畫面要透過 VNC 才看得到。

```bash title="在車上 Docker 容器內"
ros2 launch yahboomcar_description display_launch.py
```

```bash title="在 Pi 5 主機"
docker ps                              # 查 ROS 2 容器的 ID
docker exec -it <容器ID> /bin/bash     # 進同一個容器
```

```bash title="在車上 Docker 容器內（第二個終端）"
rviz2
# Add → RobotModel → Description Topic 選 /robot_description；Fixed Frame 改為 base_link
```

`display_launch.py` 的內容（原始碼 `yahboomcar_description/launch/display_launch.py`）：

| 啟動的節點 | 作用 |
| --- | --- |
| `joint_state_publisher_gui` | 關節滑桿 |
| `robot_state_publisher` | 讀 `urdf/MicroROS.urdf`（經 `xacro` 展開），發布 TF 與 `/robot_description` |
| `tf2_ros static_transform_publisher` | `base_footprint → base_link`，`0 0 0.05 0 0 0`（車身離地 5 公分） |

| 電腦模擬 | 真車 |
| --- | --- |
| `ros2 launch microros_pi5_sim display.launch.xml` | `ros2 launch yahboomcar_description display_launch.py` ＋ 另開 `rviz2` |
| `ros2 launch microros_pi5_sim sim.launch.xml` | `sh ~/start_agent_rpi5.sh` ＋ 開車電源 ＋ `ros2 launch yahboomcar_bringup yahboomcar_bringup_launch.py` |

:::warn
**官方文件的筆誤**：05-7 把 Fixed Frame 寫成 `base_linke`，正確是 `base_link`。ROS 2 基礎課第 21 課寫 `ros2 launch yahboomcar_description display.launch.py`（以 muto 車為例），但本車原始碼的檔名是 **`display_launch.py`**（底線，不是點）。另外 `yahboomcar_bringup_launch.py` 啟動時會印 `robot_type = x3`，那是沿用其他車型的程式，不必理會。
:::
