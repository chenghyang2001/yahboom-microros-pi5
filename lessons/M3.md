## 1. 開工前的檢查：agent、Domain ID、雲台與相機

> 🔊 這一單元開始，程式算出來的結果要真的讓車子動起來，所以三件事缺一不可：
> micro ROS agent 要連上、樹莓派和控制板的 ROS DOMAIN ID 要一樣、而且不能有兩個程式搶同一支鏡頭。
> 最常見的狀況是畫面跑得好好的、終端機也一直印角度，可是雲台和輪子完全不動，
> 那幾乎都是前兩件事沒做好。所以我們先用一行指令手動轉一下雲台，確認整條路是通的。

```bash title="在 Pi 5 主機"
sh ~/start_agent_rpi5.sh     # 終端 A：啟動 agent，然後按控制板 reset 鈕，等連線成功
sh ros2_humble.sh            # 終端 B：進入容器（多開終端請用 docker ps -a ＋ docker exec -it <ID> /bin/bash）
```

```bash title="在車上 Docker 容器內"
echo $ROS_DOMAIN_ID                          # 要和控制板設定的一樣（出廠 20）
ros2 node list                               # 要看到 /YB_Car_Node
ros2 topic pub --once /servo_s1 std_msgs/msg/Int32 "data: 30"    # 雲台水平轉到 30 度
ros2 topic pub --once /servo_s1 std_msgs/msg/Int32 "data: 0"     # 轉回正中
ros2 topic pub --once /servo_s2 std_msgs/msg/Int32 "data: -30"   # 俯仰往下
```

| 雲台舵機 | 話題 | 型別 | 範圍 |
| --- | --- | --- | --- |
| S1 水平（左右） | `servo_s1` | `std_msgs/Int32` | -90～90 |
| S2 俯仰（上下） | `servo_s2` | `std_msgs/Int32` | -90～20 |

:::warn

- 原始碼裡的話題名寫成 `servo_s1`、`servo_s2`（沒有前導斜線），因為節點沒有命名空間，實際就是 `/servo_s1`、`/servo_s2`，兩種寫法都對得上。
- 這一單元的官方程式（`colorHSV`、`face_fllow`、`follow_line`、`qrTracker`、`HandCtrl` 等）**都自己用 `cv.VideoCapture(0)` 打開鏡頭**，所以**不要同時開 `usb_cam_node_exe`**，否則會搶鏡頭、畫面全黑。
- 所有程式都會開 OpenCV 視窗，請在 VNC 桌面的終端執行。手勢控車類的課，第一次先把車架高讓輪子離地。
- **實車實測（2026-10-29）**：這幾支官方程式一啟動都會送俯仰角（`colorTracker` -50、`face_fllow` -60、`follow_line` -75、`HandCtrl` -45），追蹤時還會一路送到 -90 或 +20。本專案這台車的 S2 送 -10 就扯斷過相機線，所以演練時用 `-r servo_s1:=servo_s1_raw -r servo_s2:=servo_s2_raw` 改名，交給自己寫的守門員 `drill/live/20261029-m3-visual/servo_guard.py`：S2 一律攔下，S1 只准在正前方（這台是 -30）±10 度內轉。一場演練攔下 276 次 S2 指令。

:::

## 3. 顏色追蹤：HSV 選色＋PID 控雲台（8.2、8.3）

> 🔊 用紅綠藍來找顏色很不可靠，因為燈光一暗，三個數字全部一起變。
> 所以要換到 HSV 色彩空間，H 是色相、S 是飽和度、V 是亮度，找顏色只要盯著色相，亮度變化影響就小很多。
> 找到色塊之後算出中心點，和畫面中心比一比，差多少就是「誤差」。
> PID 控制器會把誤差換成雲台要轉的角度，誤差大就轉多一點，誤差小就轉少一點，讓色塊一直待在畫面中央。

```
鏡頭 → colorHSV（HSV 遮罩 → 最大色塊 → 中心座標）──/Current_point──▶ colorTracker
                    └── 也發布 /image_raw                                     │ PID
                                                                              ▼
                                                       servo_s1 / servo_s2（雲台角度）
```

**PID 一句話版**：P＝看「現在差多少」、I＝看「累積差了多久」、D＝看「差距變化得多快」，三者加權相加就是輸出。官方 `colorTracker.py` 的核心：

```python title="在車上 Docker 容器內（colorTracker.py 節錄）"
[x_Pid, y_Pid] = self.linear_pid.update([point_x - 320, point_y - 240])  # 誤差 = 色塊中心 - 畫面中心
if self.img_flip == True:
    self.PWMServo_X += x_Pid
    self.PWMServo_Y += y_Pid
else:
    self.PWMServo_X -= x_Pid
    self.PWMServo_Y += y_Pid
# 限幅：X 在 -90~90，Y 在 -90~20，然後發布 servo_s1、servo_s2
```

**實車操作**（兩個節點都要開）：

```bash title="在車上 Docker 容器內"
ros2 run yahboomcar_astra colorHSV           # 終端 1：開鏡頭、選色、發布 /Current_point
ros2 run yahboomcar_astra colorTracker       # 終端 2：PID 控雲台
ros2 run rqt_reconfigure rqt_reconfigure     # 終端 3：即時調參數
```

**操作順序（少一步就不會動）**：

1. 在影像視窗按 **`r`** 進入選色模式。
2. 用滑鼠**框出只含單一顏色**的區域，放開滑鼠。右側出現黑白遮罩，只有該顏色是白的。
3. 按**空白鍵**進入追蹤模式。
4. 慢慢移動物體，雲台會跟著轉。`i` 切到辨識模式（讀上次存的顏色，存在 `colorHSV.text`）、`q` 離開。

**rqt_reconfigure 參數**（改完要在 GUI 空白處點一下才會寫進程式）：

| 節點（`ros2 node list` 看到的名字） | 參數 | 預設值 |
| --- | --- | --- |
| `ColorIdentify`（`colorHSV` 程式） | `Hmin`、`Smin`、`Vmin`、`Hmax`、`Smax`、`Vmax` | 0、85、126、9、253、253（紅色） |
| `ColorTracker`（`colorTracker` 程式） | `linear_Kp`、`linear_Ki`、`linear_Kd` | 20.0、0.0、2.0 |

**8.3 框選物體追蹤**：不用先選顏色，直接框目標物：

```bash title="在車上 Docker 容器內"
ros2 run yahboomcar_astra mono_Tracker       # 按 r → 框選目標 → 放開 → 空白鍵；物體要慢慢移動
ros2 run rqt_reconfigure rqt_reconfigure     # 節點 monoIdentify，Kp/Ki/Kd 預設 12、0、0.9
```

:::warn
`mono_Tracker.py` 的 `img_flip` 兩個分支寫得一模一樣（`target_servox -= x_Pid`、`target_servoy += y_Pid`），是官方複製貼上的小瑕疵；如果你翻轉了影像，雲台方向可能會反過來。

**實車踩坑：框選紅色，遮罩卻整片變白（2026-10-29）**

紅色剛好落在 HSV 色環的接縫：OpenCV 的 H 是 0～180 繞一圈，紅色一半在 0 附近、一半在 175 附近。框選區域裡兩種紅都有，`Roi_hsv` 只取最小、最大值，結果 H 變成 0～184，所有顏色都算進去。用 `rqt_reconfigure` 或 `ros2 param set` 改 Hmin／Hmax **沒有效**（`process()` 只用框選或檔案的範圍）。可行的改法是改檔案再按 `i`：

```bash title="在車上 Docker 容器內"
echo "160, 90, 40, 180, 255, 255" > /root/yahboomcar_ws/src/yahboomcar_astra/yahboomcar_astra/colorHSV.text
# 回到影像視窗按 i：辨識模式每張畫面都重讀這個檔
```

另一個實測現象是**控制器飽和**：雲台被守門員限制只能轉 ±10 度，目標一直回不到畫面中央，PID 就把要求的角度一路加到程式上限 ±90。
:::

**沒車先練**：下面這支程式完全照官方的操作順序（r、框選、空白鍵），只是把雲台換成畫面上的「虛擬角度」。注意它的 PID 正負號只是示意，真車方向以官方程式為準。

```python title="在 Windows（color_track_sim.py）"
"""筆電 webcam 版顏色追蹤：r 進選色、滑鼠框選、空白鍵開始追蹤，算出「虛擬雲台」角度。q 離開。"""
import sys
import cv2 as cv
import numpy as np

state = {"mode": "identify", "p0": None, "p1": None, "dragging": False}


def on_mouse(event, x, y, flags, param):
    if state["mode"] != "init":
        return
    if event == cv.EVENT_LBUTTONDOWN:
        state.update(p0=(x, y), p1=(x, y), dragging=True)
    elif event == cv.EVENT_MOUSEMOVE and state["dragging"]:
        state["p1"] = (x, y)
    elif event == cv.EVENT_LBUTTONUP:
        state.update(p1=(x, y), dragging=False)


def roi_to_hsv_range(hsv, p0, p1):
    """把框選區域的 HSV 最小、最大值當作門檻，並稍微放寬。"""
    x0, x1 = sorted((p0[0], p1[0]))
    y0, y1 = sorted((p0[1], p1[1]))
    if x1 - x0 < 5 or y1 - y0 < 5:
        return None
    roi = hsv[y0:y1, x0:x1].reshape(-1, 3)
    low = np.clip(roi.min(axis=0) - [5, 20, 20], 0, 255)
    high = np.clip(roi.max(axis=0) + [5, 20, 20], 0, 255)
    high[0] = min(high[0], 180)                     # OpenCV 的 H 只到 180
    return low.astype(np.uint8), high.astype(np.uint8)


class SimplePID:
    def __init__(self, kp, ki, kd):
        self.kp, self.ki, self.kd = kp, ki, kd
        self.integral, self.last = 0.0, 0.0

    def update(self, error):
        self.integral += error
        derivative = error - self.last
        self.last = error
        return self.kp * error + self.ki * self.integral + self.kd * derivative


def main():
    cap = cv.VideoCapture(0)
    if not cap.isOpened():
        sys.exit("錯誤：打不開鏡頭")
    cv.namedWindow('frame')
    cv.setMouseCallback('frame', on_mouse)
    hsv_range = None
    pid_x, pid_y = SimplePID(0.02, 0.0, 0.01), SimplePID(0.02, 0.0, 0.01)
    servo_x, servo_y = 0.0, -30.0                    # 虛擬雲台：X ±90、Y -90~20（和車上一樣）
    while True:
        ret, frame = cap.read()
        if not ret:
            break
        frame = cv.resize(frame, (640, 480))
        hsv = cv.cvtColor(frame, cv.COLOR_BGR2HSV)
        key = cv.waitKey(10) & 0xFF
        if key in (ord('r'), ord('R')):
            state["mode"], hsv_range = "init", None
        elif key == 32 and hsv_range is not None:    # 空白鍵
            state["mode"] = "tracking"
        elif key in (ord('q'), ord('Q')):
            break
        if state["mode"] == "init" and state["p0"] and state["p1"]:
            cv.rectangle(frame, state["p0"], state["p1"], (0, 255, 0), 2)
            if not state["dragging"]:
                hsv_range = roi_to_hsv_range(hsv, state["p0"], state["p1"])
        if hsv_range is not None:
            mask = cv.inRange(hsv, hsv_range[0], hsv_range[1])
            mask = cv.morphologyEx(mask, cv.MORPH_OPEN, np.ones((5, 5), np.uint8))
            contours, _ = cv.findContours(mask, cv.RETR_EXTERNAL, cv.CHAIN_APPROX_SIMPLE)
            cv.imshow('mask', mask)
            if contours:
                (cx, cy), r = cv.minEnclosingCircle(max(contours, key=cv.contourArea))
                if r > 10:
                    cv.circle(frame, (int(cx), int(cy)), int(r), (255, 0, 255), 2)
                    if state["mode"] == "tracking":
                        # 誤差 = 色塊中心 - 畫面中心 (320, 240)，PID 輸出累加到舵機角度
                        servo_x = float(np.clip(servo_x - pid_x.update(cx - 320), -90, 90))
                        servo_y = float(np.clip(servo_y - pid_y.update(cy - 240), -90, 20))
        cv.putText(frame, f"mode={state['mode']}  servo_s1={int(servo_x)} servo_s2={int(servo_y)}",
                   (10, 30), cv.FONT_HERSHEY_SIMPLEX, 0.6, (0, 255, 255), 2)
        cv.drawMarker(frame, (320, 240), (0, 0, 255), cv.MARKER_CROSS, 20, 2)
        cv.imshow('frame', frame)
    cap.release()
    cv.destroyAllWindows()


if __name__ == "__main__":
    main()
```

用 M2 建好的環境執行：`~/mp-venv/Scripts/python color_track_sim.py`（只需要 OpenCV，任何裝了 `opencv-python` 的 Python 都可以）。

## 4. 人臉追蹤（8.4）

> 🔊 人臉追蹤和顏色追蹤是同一套控制邏輯，只是「找目標」的方法換成 Haar 級聯分類器。
> 它是一種很老派、不需要顯示卡的人臉偵測方法，速度快但只認正臉。找到臉框之後，
> 一樣算誤差、一樣經過 PID、一樣送到兩個雲台舵機。要特別注意官方節點名稱拼錯了，
> 必須照著錯的拼法打才跑得動。

```bash title="在車上 Docker 容器內"
ros2 run yahboomcar_astra face_fllow         # 注意：fllow 是官方拼法，打 follow 會找不到
ros2 run rqt_reconfigure rqt_reconfigure     # 節點 FaceTracker，Kp/Ki/Kd 預設 20、0、0.9
```

成功的樣子：畫面上臉被綠框框住，終端機一直印 `servo1 ...` 角度，雲台跟著你的臉轉。

```python title="在車上 Docker 容器內（face_fllow.py 節錄）"
face_patterns = cv2.CascadeClassifier('/root/yahboomcar_ws/src/yahboomcar_astra/yahboomcar_astra/haarcascade_frontalface_default.xml')
faces = face_patterns.detectMultiScale(frame, scaleFactor=1.1, minNeighbors=5, minSize=(100, 100))
[x_Pid, y_Pid] = self.PID_controller.update([point_x - 320, point_y - 240])
```

:::warn

- 節點名 `face_fllow` 是官方拼錯（應為 follow），但 `setup.py` 就是這樣登記的，**照打 `face_fllow`**。
- 官方程式把臉框**左上角**（x, y）當目標，而不是臉的中心，所以雲台停下來時臉會偏右下；畫面有多張臉時只用最後一張。
- `minSize=(100, 100)` 代表臉要夠大才偵測得到，請離鏡頭一公尺內。
- 實測：9 張截圖只有 3 張框到臉，都是正對鏡頭的時候；側臉、低頭就找不到。

:::

## 5. 自動巡線（8.5）：偏差變成角速度

> 🔊 巡線是第一個真的讓輪子動起來的視覺課。原理很直覺：每一幀找出地上那條線的中心點，
> 看它偏離畫面中央多少。線在右邊，車就往右轉；線在左邊，就往左轉；線在正中間，就直直往前開。
> 這個左右偏差經過 PID 之後，變成速度指令裡的角速度，前進速度則固定不變。
> 另外程式也會聽光達，前方太近有東西就停車並叫一聲。

```python title="在車上 Docker 容器內（follow_line.py 節錄）"
[z_Pid, _] = self.PID_controller.update([(point_x - 320)*1.0/16, 0])  # 偏差除以 16 縮小
twist.angular.z = -z_Pid          # img_flip=True 時取負號
twist.linear.x = self.linear      # 前進速度固定（預設 0.18 m/s）
if abs(point_x-320) < 40: twist.angular.z = 0.0    # 線在中間 ±40 像素內：直走（死區）
if self.warning > 10:             # 光達：前方 ±90° 內、0.2 m 以外、小於 ResponseDist 的點超過 10 個
    self.pub_cmdVel.publish(Twist())   # 停車
    b.data = 1; self.pub_Buzzer.publish(b)   # 蜂鳴器響
```

```bash title="在車上 Docker 容器內"
ros2 run yahboomcar_astra follow_line
ros2 run rqt_reconfigure rqt_reconfigure     # 節點 follow_line
```

**操作順序**：

1. 程式一啟動會把雲台俯仰設到 -75 度（往下看）。確認畫面看得到地上的線，不夠的話用 `ros2 topic pub --once /servo_s2 std_msgs/msg/Int32 "data: -60"` 微調。
2. 在影像視窗按 **`r`** → 滑鼠框住**線本身**的一段 → 放開，右側只剩線的部分是白色。
3. 按**空白鍵**開始巡線。找不到線時會印 `Not Found` 並停車。

| 參數 | 意義 | 預設 |
| --- | --- | --- |
| `Kp`、`Ki`、`Kd` | PID（實際會除以 `scale`） | 60、0、20 |
| `scale` | PID 縮放係數 | 1000 |
| `linear` | 前進速度 m/s | 0.18 |
| `ResponseDist` | 避障距離 m | 0.55 |
| `LaserAngle` | 光達偵測角度 | 30 |
| `Hmin`～`Vmax` | 線的 HSV 範圍（框選後自動填入） | — |

:::warn

- PDF 說「以黃線為例」卻寫「框選藍色線區域」，前後不一致；什麼顏色都可以，重點是框到線本身。
- 原始碼雖然宣告了 `LaserAngle` 參數，但避障判斷實際寫死看前方 ±90°，改 `LaserAngle` 不會有效果（以車上檔案為準）。
- 第一次跑請把 `linear` 調到 0.1，地上用寬 2～3 公分、和地板顏色反差大的膠帶。
- 2026-10-29 實車演練這一節**還沒做**（沒有色膠帶）。另外這台車 S2 不能用指令低頭，鏡頭朝前時大約只看得到車頭 30 公分外的地面，補做時線要從那裡開始貼。

## 6. QR code 與手勢控車（8.6～8.10）

> 🔊 最後一組是「看懂指令就動」。QR code 控車是讀出卡片上的文字，再照對照表送出速度；
> 手勢控車則是用第二單元學過的手指伸直判斷，比五就前進、握拳就後退。
> 這幾支程式反應比較慢，而且只要誤判一次車子就會動，所以第一次一定要把車架高、
> 讓輪子懸空測試，確認每個指令對應的動作都正確，再放到地上。

**8.6 QR code 控車**（指令卡可用 M1 的 `qr_make.py` 產生）：

```bash title="在車上 Docker 容器內"
ros2 run yahboomcar_astra qrTracker          # q 關閉
```

| QR 內容 | `pub_vel(x, y, z)` | 實際動作 |
| --- | --- | --- |
| `forward` | `(0.3, 0.0, 0.0)` | 前進 |
| `back` | `(-0.3, 0.0, 0.0)` | 後退 |
| `left` | `(0.0, 0.0, 1.0)` | **原地左轉**（不是橫移） |
| `right` | `(0.0, 0.0, -1.0)` | **原地右轉** |
| `turnleft` | `(0.3, 0.0, 0.5)` | 邊走邊左轉 |
| `turnright` | `(0.3, 0.0, -0.5)` | 邊走邊右轉 |
| `stop` | `(0.0, 0.0, 0.0)` | 停止 |

**8.7～8.10 手勢與手掌**（都在 `yahboomcar_mediapipe` 套件，共用 `media_library.py`）：

```bash title="在車上 Docker 容器內"
ros2 run yahboomcar_mediapipe HandCtrl       # 8.7 手勢控制移動
ros2 run yahboomcar_mediapipe RobotCtrl      # 8.8 手掌位置控制移動
ros2 run yahboomcar_mediapipe FingerCtrl     # 8.9 手勢觸發動作組
ros2 run yahboomcar_mediapipe control_shape  # 8.10 手掌控制雲台
```

| 程式 | 判斷 | 動作（依原始碼） |
| --- | --- | --- |
| `HandCtrl` | 五指全開／拳頭／只有食指／食指＋中指 | 前進 0.3／後退 0.3／原地左轉 0.5／原地右轉 0.5 |
| `RobotCtrl` | 手掌中心（landmark 9）y ≤ 210／y ≥ 270；x ≤ 290／x ≥ 350 | 前進 0.2／後退 0.2；左轉／右轉（角速度 ±0.2） |
| `FingerCtrl` | `Yes`（食指＋中指）／`OK`／`Thumb_down`／食指＋小指／五指 | 走方形／轉圈／前進再後退／S 形／停止 |
| `control_shape` | 手掌中心離開中央死區（x 290～350、y 210～270） | 每幀雲台轉 2 度，把手掌拉回中央 |

:::warn

- 8.9 的 PDF 對照表排版錯亂，看不出哪個手勢對哪個動作；上表是照 `FingerCtrl.py` 原始碼整理的。注意原始碼裡的 `Yes` 是**食指＋中指（比 V）**，不是比讚。
- 8.8 原文把「右」寫成 bottom，是筆誤；而且左右其實是**原地旋轉**（角速度），不是橫移。
- 官方提醒 8.8 在 Pi 5 上可能跑得很慢，先架高測試；手要慢慢動，太快影像處理跟不上。
- `control_shape` 裡的 `ThumbTOforefinger` 原本是控制機械手爪開合用的（從機械臂課程沿用），這台車沒有手爪，可忽略。
- **實測（2026-10-29）**：`HandCtrl` 四種手勢都認得出來（食指 26 次、比二 15 次），但它每認出一次只送一筆速度、然後 `sleep(0.5)`，兩筆間隔約 0.7 秒。如果你在中間加了「0.5 秒沒指令就停車」的看門狗，原地轉彎會轉不起來（實測平均角速度 0.02 rad/s；連續送則是 0.52）。看門狗放寬到 1.0 秒後恢復正常（0.27 rad/s）。安全裝置的逾時要配合上游程式的發送節奏。

:::

## 7. 出問題時怎麼辦

> 🔊 視覺控車的問題可以分成三層來查：第一層是畫面，有沒有影像、有沒有框到東西；
> 第二層是話題，程式有沒有真的發出舵機角度或速度；第三層是硬體，控制板有沒有收到。
> 用 ros2 topic echo 看話題，就能立刻知道問題卡在哪一層，不用整台車亂猜。

| 症狀 | 檢查 | 怎麼做 |
| --- | --- | --- |
| 有畫面、終端機一直印角度，但雲台／輪子不動 | `ros2 node list` 有沒有 `/YB_Car_Node`；`echo $ROS_DOMAIN_ID` | 重啟 agent 並按 reset；Domain ID 改成和控制板一致 |
| 畫面全黑 | 是否同時開了 `usb_cam_node_exe` 或另一支視覺程式 | 一次只開一支會開鏡頭的程式；`ls /dev/video*` |
| 按了空白鍵還是不追 | 有沒有先按 `r` 並框選成功（右側遮罩要出現白色色塊） | 重新 `r` → 框選單一顏色 → 空白鍵 |
| 追一下就丟失目標 | 環境光改變、框到雜色、物體移動太快 | 換環境要重新選色；在 rqt_reconfigure 收窄 HSV；物體慢慢移動 |
| 雲台抖個不停 | PID 太大 | 把 `Kp` 調小、`Kd` 稍微加大；改完在 GUI 空白處點一下 |
| 巡線一直左右甩 | 角速度太大或速度太快 | 降低 `Kp` 或把 `linear` 調到 0.1 |
| 巡線突然停下並叫 | 光達偵測到前方 `ResponseDist` 內有東西 | 清空前方，或暫時把 `ResponseDist` 調小 |
| rqt_reconfigure 看不到節點 | 剛開啟還沒刷新 | 按 Refresh；確認在同一個容器 |
| `ros2 run yahboomcar_astra face_follow` 說找不到 | 拼法 | 改打 `face_fllow` |
| 手勢控車車子亂跑 | 誤判 | 立刻 Ctrl+C，再發 `ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{}"` 停車 |
