## 1. Nav2 是什麼：把車從 A 送到 B 的團隊

> 🔊 上一課我們遙控車子畫出地圖，這一課要讓車自己走。想像你叫計程車：你先告訴司機你在哪裡，再說要去哪裡；司機先看地圖規劃大路線，開車時再一邊看路況閃開行人和機車，遇到塞車還會改道。Nav2 就是 ROS 2 裡做這件事的導航團隊，由好幾個各司其職的節點組成，最後輸出的只有一樣東西，就是給車子的速度命令。

**Nav2（Navigation2）** 是 ROS 2 的標準導航框架。本車用的是車上 Humble 容器裡的 `nav2_bringup`（路徑 `/opt/ros/humble/share/nav2_bringup/launch`），Yahboom 再用自己的 launch 檔與參數檔把它包起來。

整個導航最後只輸出一個東西：**`/cmd_vel` 速度命令**，跟你在 B5 單元手動 `ros2 topic pub /cmd_vel` 是同一個話題。差別只是現在由程式自己算。

| 你叫計程車 | Nav2 對應 |
| --- | --- |
| 司機手上的地圖 | Map Server 載入上一課存的 `.yaml`＋`.pgm` |
| 告訴司機「我在這裡」 | 在 RViz 點 **2D Pose Estimate**，交給 AMCL |
| 司機規劃走哪幾條大路 | Planner Server（全域規劃） |
| 開車時閃機車、行人 | Controller Server（局部控制，本車用 DWB） |
| 塞車時倒車、改道 | Behavior Server（恢復行為）＋行為樹 |
| 總指揮 | BT Navigator（行為樹導航器） |

## 2. 五個關卡：地圖、AMCL、全域規劃、局部控制、行為樹

> 🔊 Nav2 的流程可以想成五個關卡一關接一關。第一關地圖，把整間房子的牆告訴大家。第二關 AMCL 定位，用光達掃到的牆去和地圖比對，算出車子在地圖上的哪裡。第三關全域規劃，在整張地圖上畫一條從現在位置到目標的路線。第四關局部控制，只看車子周圍三公尺，一邊沿路線走一邊閃障礙。第五關行為樹，負責指揮前面四關，失敗時決定要重試、原地轉圈還是倒退。

```text title="Nav2 資料流（示意）"
   上一課的地圖 yahboom_map.yaml
              │
        ┌─────▼─────┐        /scan（光達）
        │ Map Server │──/map──┐     │
        └───────────┘        ▼     ▼
                         ┌──────────────┐   map→odom TF
   2D Pose Estimate ───▶ │     AMCL      │ ───────────────┐
   （初始位置）           └──────────────┘                 │
                                                          ▼
   2D Goal Pose ─▶ ┌───────────────┐  路徑  ┌─────────────────────┐  /cmd_vel
   （目標）        │ Planner Server │──────▶ │ Controller Server   │ ─────────▶ ESP32 → 馬達
                   │ NavfnPlanner   │        │ DWB（局部避障）      │
                   └───────▲───────┘        └──────────▲──────────┘
                           └──────── BT Navigator（行為樹總指揮）──┘
                                      失敗 → Behavior Server：spin / backup / wait
```

### 2.1 每個元件一句話

| 元件 | 本車設定 | 白話 |
| --- | --- | --- |
| Map Server | 讀 `maps:=` 指定的 `.yaml` | 把地圖發到 `/map` |
| AMCL | 粒子 `min_particles: 500`～`max_particles: 2000`，差速模型 `nav2_amcl::DifferentialMotionModel` | 在**已知地圖**上用粒子濾波猜車在哪，發布 `map → odom` TF |
| Planner Server | `nav2_navfn_planner/NavfnPlanner`，`use_astar: false`，`allow_unknown: true` | 在整張地圖上畫路線 |
| Controller Server | `dwb_core::DWBLocalPlanner`，`controller_frequency: 20.0` | 每秒 20 次算出速度命令 |
| BT Navigator | `navigate_to_pose_w_replanning_and_recovery.xml` | 行為樹：一邊走一邊重新規劃，失敗就恢復 |
| Behavior Server | `spin`、`backup`、`drive_on_heading`、`assisted_teleop`、`wait` | 卡住時的「招式」：原地轉、後退、等待 |
| Waypoint Follower | `stop_on_failure: false`，每點停 `200` 毫秒 | 多點巡航 |
| Lifecycle Manager | — | 依序把上面節點「開機」 |

**AMCL 和上一課 SLAM 的差別**：SLAM 是「沒有地圖，一邊畫一邊猜位置」；AMCL 是「地圖已經有了，只猜位置」。所以導航時不會再改動地圖。

**行為樹（Behavior Tree）**是什麼？像一張「做事流程圖」：先規劃 → 沿路走 → 如果失敗就清除代價地圖再試 → 再失敗就原地轉一圈 → 再失敗就後退一點。好處是流程寫在 XML 裡，不用改程式就能調整策略。

### 2.2 TF 鏈：導航時誰負責哪一段

```text title="TF 樹（導航時）"
map ──(AMCL)──▶ odom ──(bringup：EKF)──▶ base_footprint ──(URDF)──▶ base_link ──(靜態 TF)──▶ laser_frame
```

和建圖時唯一的差別：`map → odom` 改由 **AMCL** 發布，不再是 SLAM 節點。

:::info
參數檔裡 AMCL 用 `base_frame_id: "base_footprint"`，但 `bt_navigator` 與 costmap 用 `robot_base_frame: base_link`。兩者能共存，是因為 URDF（bringup 裡的 `robot_state_publisher`）提供了 `base_footprint → base_link`。如果你看到「找不到 base_link」的錯誤，用 `ros2 run tf2_tools view_frames` 檢查這一段（需實車確認）。
:::

## 3. Costmap 代價地圖與 DWB 參數

> 🔊 規劃路線時，Nav2 不是直接看黑白地圖，而是看一張代價地圖。牆本身的代價最高，牆旁邊一圈也有代價，像牆壁四周塗了一層越靠近越貴的顏料，讓車子自然離牆遠一點。代價地圖分兩張：全域的那張蓋住整間房子，用來規劃大路線；局部的那張只有車子周圍三公尺見方，隨車移動，用來即時閃障礙。

### 3.1 兩張代價地圖

| | global costmap（全域） | local costmap（局部） |
| --- | --- | --- |
| 範圍 | 整張地圖 | 車子周圍 `width: 3` × `height: 3`（公尺），`rolling_window: true` 跟著車跑 |
| 座標系 | `global_frame: map` | `global_frame: odom` |
| 圖層 | `["static_layer", "obstacle_layer", "inflation_layer"]` | `["voxel_layer", "inflation_layer"]` |
| 給誰用 | Planner（全域規劃） | Controller（DWB 局部控制） |

三種圖層：

- **static_layer**：上一課存的地圖（不會變的牆）。
- **obstacle_layer / voxel_layer**：光達現在看到的障礙（會動的人、新放的箱子）；來源 `/scan`，`obstacle_max_range: 2.5` 公尺內才標成障礙。
- **inflation_layer**：在障礙周圍「膨脹」一圈代價。`inflation_radius: 0.55`、`cost_scaling_factor: 3.0`。

車子大小：`robot_radius: 0.22`（把車當成半徑 22 公分的圓）。

### 3.2 DWB：怎麼選出下一步的速度

**DWB（Dynamic Window approach B）** 的做法：每次先「想像」很多組可能的速度（`vx_samples: 20`、`vtheta_samples: 20`），每組都模擬往前走 `sim_time: 1.7` 秒，得到一條條候選軌跡；再請一群**評分員（critics）**打分數，挑最高分的那組送出去。

本車的評分員：`["RotateToGoal", "Oscillation", "BaseObstacle", "GoalAlign", "PathAlign", "PathDist", "GoalDist"]`

| 評分員 | 在意什麼 |
| --- | --- |
| BaseObstacle | 會不會撞到東西 |
| PathDist / PathAlign | 有沒有貼著規劃好的路線走 |
| GoalDist / GoalAlign | 有沒有朝目標前進 |
| RotateToGoal | 快到終點時把車頭轉對方向 |
| Oscillation | 不要左右來回抖 |

### 3.3 最常調的 DWB 與目標參數（`dwb_nav_params.yaml` 原檔數值）

| 參數 | 原值 | 調整方向 |
| --- | --- | --- |
| `max_vel_x` | `0.30` | 最高前進速度（m/s）。初學先調小到 0.2 比較安全 |
| `min_vel_x` | `-0.20` | 允許倒退的最大速度 |
| `max_vel_y` | `0.0` | **必須是 0**：差速車不能橫移 |
| `max_vel_theta` | `1.0` | 最高旋轉速度（rad/s） |
| `acc_lim_x` / `acc_lim_theta` | `2.5` / `3.2` | 加速度上限 |
| `sim_time` | `1.7` | 往前模擬幾秒；太長轉彎會鈍、太短容易撞 |
| `xy_goal_tolerance` | `0.25` | 離目標 25 公分內就算到 |
| `yaw_goal_tolerance` | `0.25` | 車頭方向差 0.25 弧度內就算到 |
| `inflation_radius` | `0.55` | 膨脹半徑；窄走廊過不去時可試著調小 |

另外 `velocity_smoother` 還會把速度再限制在 `max_velocity: [0.26, 0.0, 1.0]`。

:::tip
想改參數，不要直接改車上原檔。先複製一份，再用 `params_file:=` 指定：

```bash title="在車上 Docker 容器內"
cp /root/yahboomcar_ws/src/yahboomcar_nav/params/dwb_nav_params.yaml /root/my_nav_params.yaml
nano /root/my_nav_params.yaml
ros2 launch yahboomcar_nav navigation_dwb_launch.py params_file:=/root/my_nav_params.yaml
```

容器內若沒有 `nano` 就用 `vi`。記得改好的檔案也要像 A1 一樣 `docker cp` 到 Pi 5 主機備份，因為容器關掉就消失。
:::

:::warn
官方文件裡 `velocity_smoother` 那段縮排在 `waypoint_follower` 底下，那是文件排版錯誤，實際檔案以車上為準。另外 `navigation_dwb_launch.py` 原始碼裡有個參數拼成 `namespece`（應為 namespace），單車導航用不到，不要被搞混。
:::

## 4. 車上實作：載入地圖、設初始位置、點目標

> 🔊 上車實作分三步。第一步，和建圖一樣開 agent、進容器、跑底層 bringup。第二步，開 RViz 再啟動導航，導航啟動後地圖才會出現。第三步最關鍵：先用 2D Pose Estimate 告訴車子它在地圖的哪裡，看光達的紅點有沒有貼齊地圖的牆；貼齊了，再用 2D Goal Pose 點目標。初始位置給錯，是導航亂跑的第一名原因。

### 4.1 前置

1. **車子斷電、放穩、開機後靜置 5 秒**（IMU 初始化）。
2. 把車放在建圖時的起點附近，車頭朝向也盡量相同，等一下比較好設初始位置。
3. 開 agent 與容器（同 A1 第 4.1 節）：

```bash title="在 Pi 5 主機（終端 1）"
sh ~/start_agent_rpi5.sh
```

```bash title="在 Pi 5 主機（終端 2）"
sh ros2_humble.sh
```

1. 如果容器是新開的，上一課存的地圖已經不在容器裡，先從 Pi 5 主機放回去：

```bash title="在 Pi 5 主機"
docker ps -a
docker cp ~/maps/yahboom_map.yaml <你的 CONTAINER ID>:/root/yahboomcar_ws/src/yahboomcar_nav/maps/
docker cp ~/maps/yahboom_map.pgm <你的 CONTAINER ID>:/root/yahboomcar_ws/src/yahboomcar_nav/maps/
```

### 4.2 三個終端

第 2 個以後的終端都用 `docker exec -it <ID> /bin/bash` 進同一個容器。

```bash title="在車上 Docker 容器內（終端 A：底層）"
ros2 launch yahboomcar_bringup yahboomcar_bringup_launch.py
```

```bash title="在車上 Docker 容器內（終端 B：RViz）"
ros2 launch yahboomcar_nav display_launch.py
```

```bash title="在車上 Docker 容器內（終端 C：導航）"
ros2 launch yahboomcar_nav navigation_dwb_launch.py
```

預設載入 `/root/yahboomcar_ws/src/yahboomcar_nav/maps/yahboom_map.yaml`。要換地圖，用 Yahboom launch 的參數名 **`maps`**（注意有 s）並給完整路徑：

```bash title="在車上 Docker 容器內"
ros2 launch yahboomcar_nav navigation_dwb_launch.py maps:=/root/yahboomcar_ws/src/yahboomcar_nav/maps/living_room.yaml
```

:::info
`navigation_dwb_launch.py` 做了四件事：include 官方 `nav2_bringup` 的 `bringup_launch.py`（傳入地圖、`use_sim_time`、參數檔）、啟動 `stop_car` 節點、發布光達靜態 TF `base_link_to_base_laser`。`stop_car` 的用途是：你按 **Ctrl+C** 結束導航時，它會送一次全部為 0 的 `/cmd_vel`，避免車子帶著最後的速度繼續衝。
:::

### 4.3 在 RViz 操作

1. **設初始位置**：工具列點 **2D Pose Estimate** → 在地圖上車子實際所在位置**按住** → 往車頭方向**拖曳**出箭頭 → 放開。
2. **檢查**：光達掃到的點（`/scan`）應該大致**貼齊**地圖上的黑色牆線。沒貼齊就再設一次；也可以遙控車子原地慢慢轉一圈，讓 AMCL 自己收斂。
3. **單點導航**：工具列點 **2D Goal Pose** → 在地圖空白處按住並拖出目標方向 → 放開。車會規劃路徑、出發、避障，到點停下。
4. **試避障**：車子行走時，在它前方放一個紙箱，看它怎麼繞過去。

:::warn
導航時請在旁邊看著，手放在車子電源開關附近。第一次測試先把 `max_vel_x` 調小（見 3.3 的 tip）。導航中如果用手把或鍵盤搶控制，兩邊同時發 `/cmd_vel` 車子會抖動。
:::

## 5. 多點巡航與手機 App 導航

> 🔊 學會單點導航後，可以讓車子依序經過好幾個點，像保全巡邏一樣。做法是在 RViz 加上 Nav2 的面板，切到航點模式，一次點好幾個目標，再按開始。不想開電腦的話，手機的 ROS Robot App 也能導航，流程一樣是先設初始點、再設導航點，只是按鈕換到手機上。

### 5.1 多點巡航（Waypoint）

1. RViz 左上選單 **Panels → Add New Panel** → 加入 **Navigation 2** 面板（Nav2 的 RViz 外掛）。
2. 面板上點 **Waypoint / Nav Through Poses Mode**。
3. 用工具列的 **Nav2 Goal** 依序在地圖上點多個目標。
4. 按 **Start Waypoint Following**。車會依序到每個點，到最後一點停下，等你下一個指令。

`waypoint_follower` 設定 `stop_on_failure: false`：某一點到不了會跳過，繼續下一點。

### 5.2 手機 App「ROS Robot」導航

```bash title="在車上 Docker 容器內（終端 A）"
ros2 launch yahboomcar_bringup yahboomcar_bringup_launch.py
```

```bash title="在車上 Docker 容器內（終端 B：App 導航，換成你自己的地圖檔名）"
ros2 launch yahboomcar_nav navigation_dwb_app_launch.xml maps:=/root/yahboomcar_ws/src/yahboomcar_nav/maps/yahboom_map.yaml
```

```bash title="在車上 Docker 容器內（終端 C：相機）"
ros2 launch usb_cam camera.launch.py
```

手機：連線步驟同 A1 第 5.2 節 → 進入 **Navigation** 介面 → **先**按 **Set Initialization Point** 設初始點（雷射點與牆大致重合就是準）→ **再**按 **Set Navigation Point** 設目標。

:::warn
官方文件的範例指令是 `maps:=/root/yahboomcar_ws/src/yahboomcar_nav/maps/test1219.yaml`，`test1219.yaml` 是作者自己存的地圖，你的車上用的是你自己存的檔名（例如 `yahboom_map.yaml`）。文件排版把這行折成兩行，實際要打成同一行。另外文件裡 `navigation_dwb_app_launch.xml` 的第一行寫成 `<launch` 少了 `>`，是排版錯字，車上的檔案是正常的。
:::

## 6. 電腦模擬練習版：Jazzy 的 nav2_bringup

> 🔊 電腦模擬可以讓你放心地亂點目標、故意把初始位置設錯，看看導航會怎麼出錯，不怕撞壞車。這裡有兩種玩法：第一種拿上一課存的 room 地圖，用 AMCL 定位再導航，和車上的流程一模一樣；第二種不用地圖，讓 slam toolbox 一邊建圖、Nav2 一邊導航，適合探索沒來過的地方。

### 6.1 安裝（只做一次）

```bash title="在電腦 WSL（Jazzy）"
sudo apt update
sudo apt install ros-jazzy-navigation2 ros-jazzy-nav2-bringup
```

### 6.2 玩法一：用存好的地圖導航（AMCL）

```bash title="在電腦 WSL（Jazzy）終端 1：模擬車"
cd ~/yahboom_ws && source install/setup.bash && ros2 launch microros_pi5_sim sim.launch.xml
```

```bash title="在電腦 WSL（Jazzy）終端 2：Nav2（載入 A1 存的地圖）"
cd ~/yahboom_ws && source install/setup.bash
ros2 launch microros_pi5_sim nav2.launch.xml map:=$HOME/maps/room.yaml
# 不加 map:= 就用套件內附、在模擬小屋建好的地圖
```

:::info
`microros_pi5_sim nav2.launch.xml` 其實就是 `nav2_bringup bringup_launch.py`，只是換成為這台小車調過的參數檔 `config/nav2_params.yaml`：機器人半徑 0.12 m（官方預設 0.22 m 是給大一倍的 TurtleBot）、膨脹半徑 0.35 m、局部控制器改用 Regulated Pure Pursuit（Jazzy 預設的 MPPI 很吃 CPU，在 WSL 模擬會跟不上）。實測用官方預設參數時，車子會卡在門口，一直報「Failed to make progress」。
:::

```bash title="在電腦 WSL（Jazzy）終端 3：附 Nav2 工具的 RViz"
source /opt/ros/jazzy/setup.bash
ros2 launch nav2_bringup rviz_launch.py
```

在 RViz：**2D Pose Estimate** 設初始位置 → **Nav2 Goal**（或 2D Goal Pose）點目標。

注意：官方 `nav2_bringup` 的參數名是 **`map`**（沒有 s），Yahboom 的 `navigation_dwb_launch.py` 則是 **`maps`**，兩者不要混用。

### 6.3 玩法二：邊建圖邊導航（slam_toolbox＋navigation_launch.py）

```bash title="在電腦 WSL（Jazzy）終端 2：建圖"
source /opt/ros/jazzy/setup.bash
ros2 launch slam_toolbox online_async_launch.py use_sim_time:=true
```

```bash title="在電腦 WSL（Jazzy）終端 3：只開導航，不開 AMCL 與 Map Server"
source /opt/ros/jazzy/setup.bash
ros2 launch nav2_bringup navigation_launch.py use_sim_time:=true params_file:=$HOME/yahboom_ws/install/microros_pi5_sim/share/microros_pi5_sim/config/nav2_params.yaml
```

這時 `map → odom` 由 slam_toolbox 發布，所以**不需要** 2D Pose Estimate，直接點目標即可。

:::warn
Jazzy 與車上 Humble 的 Nav2 參數格式不同：Humble 的外掛名稱寫 `nav2_navfn_planner/NavfnPlanner`、`nav2_behaviors/Spin`，新版改用 `::`（例如 `nav2_navfn_planner::NavfnPlanner`）；`bt_navigator` 的外掛清單寫法也變了。**不要把車上的 `dwb_nav_params.yaml` 整份搬到 Jazzy**。想讓模擬車的行為像實車，從 Jazzy 內建參數檔開始，只把數值抄過去：`max_vel_x: 0.30`、`robot_radius: 0.22`、`inflation_radius: 0.55`。Jazzy 預設的局部控制器不一定是 DWB（需實機確認），所以模擬時的閃避動作可能和車上不同。
:::

## 7. 出問題時怎麼辦

> 🔊 導航出錯通常有跡可循。車子一出發就亂轉，八成是初始位置沒設好；RViz 沒有地圖，多半是地圖路徑寫錯或容器裡根本沒有那個檔；車子走到一半停住原地轉，是行為樹在執行恢復動作，代表它找不到路。先看終端印出的錯誤訊息，再對照下面這張表。

| 症狀 | 最可能的原因 | 怎麼做 |
| --- | --- | --- |
| 車一出發就亂轉、往奇怪方向走 | 初始位置錯誤 | 重新 **2D Pose Estimate**，確認光達點貼齊牆 |
| 車沒動但 RViz 車模型在漂 | IMU 沒初始化 | 斷電、放平、開機靜置 5 秒，從頭重來 |
| RViz 沒有地圖 | 地圖路徑錯、容器內沒有地圖檔（`--rm` 容器重開後就沒了） | `ls /root/yahboomcar_ws/src/yahboomcar_nav/maps`；用 `docker cp` 放回；確認參數名是 `maps:=` |
| 地圖出現了但位置歪一大截 | 換了地圖卻沒重設初始位置 | 重新設 2D Pose Estimate |
| 點了目標，車子不動 | 目標點落在膨脹區或未知區、Nav2 節點還沒全部啟動完 | 等終端出現啟動完成的訊息；把目標點在白色空地中央 |
| 走到一半停下原地轉圈、後退 | 行為樹的恢復行為：路被擋、找不到可行路徑 | 移開障礙；窄通道可試調小 `inflation_radius` |
| 到了目標附近一直來回修正 | 目標容許值太嚴 | 適度放寬 `xy_goal_tolerance`、`yaw_goal_tolerance` |
| 一直報 TF 錯誤、`transform` 逾時 | bringup 沒開，或時間戳不同步 | 先跑 bringup；按控制板 Reset 讓車重新連 agent |
| 車子抖動、忽快忽慢 | 自啟動的手把程式也在發 `/cmd_vel` | 關掉自啟動手把行程（見 B4） |
| 按 Ctrl+C 後車子還在動 | `stop_car` 沒來得及送停車 | 手動 `ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"` |
| 模擬時 Nav2 報時間相關錯誤 | 有節點沒加 `use_sim_time:=true` | 模擬時每個 launch 都加；實車時都不要加 |

```bash title="在車上 Docker 容器內（除錯用）"
ros2 run rqt_graph rqt_graph
ros2 run tf2_tools view_frames
ros2 topic echo /cmd_vel
```
