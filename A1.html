SLAM 建圖：Gmapping、Cartographer、App 建圖

⏱ 2 小時🚗 真車：是
🎯 學習目標
搞懂 SLAM「一邊找自己、一邊畫地圖」的道理，並用車上的 Gmapping 或 Cartographer 建出一張自己房間的地圖。
✅ 完成標準
建出客廳（或房間）地圖，存成 .pgm＋.yaml，並把地圖檔從容器複製到 Pi 5 主機保存。

1. SLAM 是什麼：一邊找自己、一邊畫地圖

🔊 旁白文字

想像你被蒙著眼帶進一間沒來過的房子，拿掉眼罩後手上只有一支手電筒和一張白紙。你每走幾步，就用手電筒照照四周的牆，把看到的牆畫到紙上；同時你也要記得自己大概走了幾步、轉了幾度，才知道下一道牆該畫在紙的哪裡。這就是 SLAM，中文叫同時定位與建圖。車子的手電筒就是光達，記步數的就是輪子的里程計。

SLAM（Simultaneous Localization And Mapping，同時定位與建圖）要同時解兩個互相依賴的問題：

問題 白話 車上靠什麼
定位（Localization） 「我現在在哪裡、面向哪裡？」 輪子里程計＋IMU（陀螺儀）＋光達比對
建圖（Mapping） 「這附近的牆和障礙物長什麼樣？」 光達 MS200 每圈 360 度的距離資料

雞生蛋問題：要畫準地圖必須知道自己在哪；要知道自己在哪又得靠地圖比對。SLAM 演算法就是讓兩件事互相修正、一起變準。

建出來的是一張 2D 佔據柵格地圖（occupancy grid）：把地面切成一格一格（本車預設每格 5 公分），每格是三種狀態之一：

  • 白色：確定是空地，車可以走
  • 黑色：確定有障礙（牆、桌腳）
  • 灰色：還沒看過、不知道

存檔時會得到兩個檔：.pgm（圖片本體）＋.yaml（說明這張圖每格多大、原點在哪）。下一課 A2 的 Nav2 導航就是拿這兩個檔來用。

ℹ️ 補充

這一課是「先建圖」，下一課 A2 是「拿地圖導航」。建圖時你遙控車；導航時車自己走。兩課的地圖檔是同一份，所以這課務必把地圖存好、備份好。

2. 建圖的三樣材料：/scan、/odom、TF

🔊 旁白文字

SLAM 演算法像一位廚師，要三樣材料才能下鍋。第一樣是 scan 話題，光達告訴你四周每個方向多遠有東西。第二樣是 odom 話題，里程計告訴你車子大概走了多遠、轉了多少。第三樣是 TF 座標變換，告訴演算法光達裝在車上哪個位置。少了任何一樣，地圖不是畫不出來，就是畫得歪七扭八。

2.1 三樣材料從哪來

材料 話題／來源 誰發布 白話
光達掃描 /scan（sensor_msgs/LaserScan） ESP32 韌體（/YB_Car_Node） 一圈 360 個距離值，frame_id 是 laser_frame
里程計 /odom_raw → EKF 融合 → /odom ESP32 發 /odom_raw；Pi 端 ekf_filter_node 融合 IMU 後發 /odom 「從開機的地方算起，我走到哪了」
座標關係 /tf、/tf_static bringup、URDF、launch 裡的靜態 TF 各零件之間的相對位置

2.2 TF 鏈：建圖時誰負責哪一段

TF 樹（建圖時）
map ──(SLAM 節點發布)──▶ odom ──(bringup：EKF)──▶ base_footprint ──(URDF)──▶ base_link ──(靜態 TF)──▶ laser_frame
  • odom → base_footprint：由 yahboomcar_bringup_launch.py 啟動的 EKF（robot_localization）發布。這就是為什麼每次建圖都要先跑 bringup。
  • base_link → laser_frame：建圖 launch 檔內附的靜態 TF，原始碼逐字如下：
yahboomcar_nav/launch/map_gmapping_launch.py（原始碼節錄，不用執行）
base_link_to_laser_tf_node = Node(
 package='tf2_ros',
 executable='static_transform_publisher',
 name='base_link_to_base_laser',
 arguments=['-0.0046412', '0' , '0.094079','0','0','0','base_link','laser_frame']
)

意思是：光達在車身中心往後 0.46 公分、往上 9.4 公分，沒有旋轉。

  • map → odom：由 SLAM 節點（gmapping 或 Cartographer）發布，用來「修正里程計的累積誤差」。
ℹ️ 補充

bringup 裡沒有啟動光達驅動的指令——這台車的光達接在 ESP32 上，/scan 是 ESP32 韌體直接發的。只要 agent 連上、/YB_Car_Node 出現，/scan 就有了。

2.3 開始前一定要做：陀螺儀初始化

⚠️ 注意

建圖、導航前，先把車斷電、穩穩放在地上，再開機並保持完全不動 5 秒，讓 IMU（陀螺儀）初始化。官方文件〈Precautions for Radar Mapping and Navigation〉特別提醒：沒做的話，車身明明沒動，RViz 裡的車子模型卻會原地旋轉或往一邊漂，整張地圖會糊掉。這是最常被跳過、卻會讓整個建圖失敗的步驟。

3. 三種建圖演算法比較

🔊 旁白文字

同樣是畫地圖，不同演算法有不同個性。Gmapping 像一群人同時猜你在哪，再挑最像的那個答案，小房間又快又準，但空間一大就吃不消，而且繞一圈回到原點時不會自己對齊。Cartographer 是 Google 做的，把一小段一小段拼成子地圖，繞回原點時會發現並修正，比較適合大空間。電腦上練習則用 slam toolbox，它是 Jazzy 版最常用的建圖套件。

Gmapping Cartographer slam_toolbox（電腦練習用）
核心想法 粒子濾波（RBpf）：很多「我可能在這」的猜測一起比 子圖（submap）＋圖最佳化（Ceres） 圖最佳化＋掃描比對
迴環偵測（loop closure） 沒有 有 有
適合 室內小空間、運算量小 較大的空間 一般室內，Jazzy 標準選擇
本車設定檔 /root/gmapping_ws/src/slam_gmapping/params/slam_gmapping.yaml yahboomcar_nav/params/lds_2d.lua Jazzy 套件內建預設值
本車上可用 是（從原始碼自行編譯在 gmapping_ws） 是 不在車上，電腦用

迴環偵測是什麼？你繞客廳一圈回到起點，理論上地圖的頭尾要接起來。但里程計一路累積誤差，回到原點時可能差了 20 公分，沒有迴環偵測的演算法就會畫出「兩道錯開的牆」。

3.1 Gmapping 的重要參數（slam_gmapping.yaml 原檔數值）

參數 值 白話
base_frame / odom_frame / map_frame base_footprint / odom / map 三個座標系名稱
delta 0.05 地圖解析度，每格 5 公分
particles 30 粒子數，越多越準但越吃 CPU
maxUrange / maxRange 4.0 / 6.0 光達只拿 4 公尺內的點來畫圖
linearUpdate / angularUpdate 1.0 / 0.5 走 1 公尺或轉 0.5 弧度才更新一次
map_update_interval 5.0 每 5 秒重畫一次地圖
xmin/xmax/ymin/ymax -10.0 / 10.0 地圖最大 20 m × 20 m
⚠️ 注意

Gmapping 點數限制：官方文件說 gmapping 只適用「單幀 2D 雷射點數少於 1440」，超過會出現 [mapping-4] process has died。本車 ESP32 發布的 /scan 依範例程式是每圈 360 點（每 1 度一點），在限制內；出廠韌體實際點數請用 ros2 topic echo /scan --once 數一下 ranges 長度確認（需實車確認）。若你以後換別的高解析光達，就要改用 Cartographer。

3.2 Cartographer 的重要設定（lds_2d.lua）

  • tracking_frame = "base_footprint"、published_frame = "odom"、provide_odom_frame = false、use_odometry = true
  • TRAJECTORY_BUILDER_2D.use_imu_data = false（本車的 Cartographer 沒用 IMU，靠輪式里程計）
  • min_range = 0.10、max_range = 3.5（只用 0.1～3.5 公尺內的點）
  • POSE_GRAPH.constraint_builder.min_score = 0.65（迴環比對分數要夠高才採用）

4. 車上實作：Gmapping 建圖到存檔

🔊 旁白文字

現在上車實作。整個流程像蓋房子要照順序：先開翻譯官 agent，讓 ESP32 接上 ROS；再進容器啟動底層 bringup，讓里程計和座標變換跑起來；接著開 RViz 看畫面，再啟動建圖節點，最後用鍵盤或手把慢慢開車繞一圈，存檔。順序錯了，最常見的結果就是 RViz 一片空白。

4.1 前置：agent 與容器

在 Pi 5 主機（終端 1）
sh ~/start_agent_rpi5.sh

啟動後按一下 microROS 控制板上的 Reset 鈕，等畫面出現連線成功。開機時桌面通常已自動開好 agent 視窗，不要再開第二個（agent 只能開一個）。

在 Pi 5 主機（終端 2）
sh ros2_humble.sh
在車上 Docker 容器內
ros2 node list

看到 /YB_Car_Node 才繼續。

⚠️ 注意

多開終端要進「同一個」容器。官方文件每課都只寫「再開一個終端」，但每執行一次 sh ros2_humble.sh 就會開一個全新的容器。第 2 個以後的終端請在 Pi 5 主機這樣做：

在 Pi 5 主機（終端 3、4、5…）
docker ps -a
docker exec -it <你的 CONTAINER ID> /bin/bash

<你的 CONTAINER ID> 換成 docker ps -a 最上面那筆、IMAGE 是 yahboomtechnology/ros-humble:4.0.3 的 ID（每次都不同；文件範例的 ef0e1b7da319 不能照抄）。

4.2 四個終端依序啟動

在車上 Docker 容器內（終端 A：底層）
ros2 launch yahboomcar_bringup yahboomcar_bringup_launch.py
在車上 Docker 容器內（終端 B：RViz，此時還沒有地圖是正常的）
ros2 launch yahboomcar_nav display_launch.py
在車上 Docker 容器內（終端 C：Gmapping 建圖）
ros2 launch yahboomcar_nav map_gmapping_launch.py
在車上 Docker 容器內（終端 D：遙控，鍵盤或手把二選一）
# 鍵盤
ros2 run yahboomcar_ctrl yahboom_keyboard
# 手把（兩行各開一個終端）
ros2 run yahboomcar_ctrl yahboom_joy
ros2 run joy joy_node
💡 小提示

RViz 要在 VNC 桌面上才看得到視窗。Pi 5 跑 RViz 會有點卡，A5 會教你改在電腦上開 RViz。

4.3 開車技巧

  • 慢慢走：官方原文就是 slowly walk。線速度調低，轉彎尤其要慢，否則前後兩圈光達對不上，地圖會出現重影。
  • 先沿著牆走一圈，再進房間中央補灰色區域。
  • 回到起點後再多走一小段，讓地圖頭尾接上（Gmapping 沒有迴環偵測，起點附近要更小心）。
  • 地圖中灰色區域都變白或黑了，再存檔。

4.4 存地圖

在車上 Docker 容器內（終端 E）
ros2 launch yahboomcar_nav save_map_launch.py

存在 /root/yahboomcar_ws/src/yahboomcar_nav/maps/，檔名 yahboom_map.pgm 與 yahboom_map.yaml。原始碼裡這個 launch 有一個 map_path 參數，想存成別的名字可以這樣（不用加副檔名）：

在車上 Docker 容器內
ros2 launch yahboomcar_nav save_map_launch.py map_path:=/root/yahboomcar_ws/src/yahboomcar_nav/maps/living_room

存出來的 .yaml 長這樣：

yahboom_map.yaml（範例內容）
image: yahboom_map.pgm
mode: trinary
resolution: 0.05
origin: [-10, -10, 0]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.25
欄位 白話
resolution 每像素 0.05 公尺
origin 地圖左下角在世界座標的位置 (x, y, yaw)；-10 對應 Gmapping 的 xmin/ymin
occupied_thresh / free_thresh 佔據機率大於 0.65 算牆、小於 0.25 算空地

4.5 把地圖備份到 Pi 5 主機（很重要）

⚠️ 注意

ros2_humble.sh 原始碼用的是 docker run -it --rm ...，--rm 代表容器關掉就整個刪除，而且沒有掛載地圖資料夾。所以你存在容器內的地圖，關掉容器（或重開機）後就會消失（依原始碼推論，需實車確認）。存好地圖後，容器還開著的時候，立刻在 Pi 5 主機複製出來：

在 Pi 5 主機
mkdir -p ~/maps
docker cp <你的 CONTAINER ID>:/root/yahboomcar_ws/src/yahboomcar_nav/maps/yahboom_map.pgm ~/maps/
docker cp <你的 CONTAINER ID>:/root/yahboomcar_ws/src/yahboomcar_nav/maps/yahboom_map.yaml ~/maps/

下次要用時再反向 docker cp ~/maps/yahboom_map.yaml <ID>:/root/yahboomcar_ws/src/yahboomcar_nav/maps/（.pgm 也要一起）。

4.6 看看系統長什麼樣

在車上 Docker 容器內
ros2 run rqt_graph rqt_graph
ros2 run tf2_tools view_frames

rqt_graph 一開始沒畫面時，選 Nodes/Topics (all) 再按左上角重新整理。view_frames 會在目前目錄產生 TF 樹的 .pdf，可以對照 2.2 節的鏈。

5. 換成 Cartographer，以及手機 App 建圖

🔊 旁白文字

學會 Gmapping 之後，換 Cartographer 只要改一行：把建圖節點換掉，其他步驟一模一樣。手機 App 建圖則是給不想開電腦的人用的，車上會多開一個叫 rosbridge 的橋，把 ROS 的話題變成網頁看得懂的格式，手機就能直接看地圖、遙控、存檔。要注意兩種演算法存出來的檔名一樣，後存的會蓋掉先存的。

5.1 Cartographer

步驟和第 4 節完全相同，只把終端 C 換成：

在車上 Docker 容器內（終端 C：Cartographer 建圖）
ros2 launch yahboomcar_nav map_cartographer_launch.py

這個 launch 會啟動 cartographer_ros 的 cartographer_node（讀 lds_2d.lua），再用 occupancy_grid_launch.py 把子圖轉成 /map（解析度 0.05、每 1.0 秒發布一次），並附上同一個 base_link_to_base_laser 靜態 TF。

⚠️ 注意

Gmapping 和 Cartographer 用 save_map_launch.py 存出來都叫 yahboom_map，後存的會覆蓋先存的。想比較兩種演算法，請用 map_path:= 存成不同名字，例如 .../maps/room_gmapping 與 .../maps/room_carto。

5.2 手機 App「ROS Robot」建圖

rosbridge 是什麼？它把 ROS 話題轉成 WebSocket（一種網頁常用的連線方式），手機、瀏覽器不必裝 ROS 也能訂閱和發布話題。

在車上 Docker 容器內（終端 A）
ros2 launch yahboomcar_bringup yahboomcar_bringup_launch.py
在車上 Docker 容器內（終端 B，用 docker exec 進同一個容器；二選一）
ros2 launch yahboomcar_nav map_gmapping_app_launch.xml
ros2 launch yahboomcar_nav map_cartographer_app_launch.xml
在車上 Docker 容器內（終端 C：相機畫面給 App 用）
ros2 launch usb_cam camera.launch.py

手機操作：

  1. 手機連上和車同一個網路（車的熱點 Micro_ros 時，車子 IP 是 10.42.0.1）。
  2. 開 ROS Robot App → 輸入車子 IP → 語言 zh 中文／en 英文 → 選 ROS2 → Video Topic 選下方第一個 → 按 Connect。
  3. 用畫面上的滑動轉盤慢慢開車走完區域。
  4. 按儲存地圖 → 輸入地圖名稱 → Submit。地圖同樣存在 /root/yahboomcar_ws/src/yahboomcar_nav/maps，記得照 4.5 節備份。

map_gmapping_app_launch.xml 內部一次啟動了：rosbridge_websocket_launch.xml（橋）、laserscan_to_point_publisher（把光達點轉成 App 畫得出的格式）、map_gmapping_launch.py（建圖）、robot_pose_publisher_launch.py（車子位置給 App 顯示）、yahboom_app_save_map.launch.py（App 按鈕存圖）。

⚠️ 注意

官方文件此處有幾個筆誤，不要照抄：畫面說明寫成 Video Tpoic（應為 Video Topic）、rivz（應為 rviz）。App 文件沒附下載連結，請在手機應用商店搜尋「ROS Robot」，以 Yahboom 官方影片畫面比對（需實車確認）。

6. 電腦模擬練習版：Jazzy 的 slam_toolbox

🔊 旁白文字

車子還沒到、或想先在電腦上多練幾次，可以用模擬器。我們在電腦的 WSL 裡放了一台和這台車長得一樣的模擬車，配上 Jazzy 版最常用的 slam toolbox 來建圖。演算法和車上不同，但三樣材料、TF 鏈、慢慢開、存成 pgm 和 yaml 的流程完全一樣，觀念練熟了上車就很快。

6.1 安裝需要的套件（只做一次）

在電腦 WSL（Jazzy）
sudo apt update
sudo apt install ros-jazzy-slam-toolbox ros-jazzy-nav2-map-server ros-jazzy-teleop-twist-keyboard

6.2 四個終端

在電腦 WSL（Jazzy）終端 1：啟動模擬車
cd ~/yahboom_ws && source install/setup.bash && ros2 launch microros_pi5_sim sim.launch.xml
在電腦 WSL（Jazzy）終端 2：slam_toolbox 建圖
source /opt/ros/jazzy/setup.bash
ros2 launch slam_toolbox online_async_launch.py use_sim_time:=true
在電腦 WSL（Jazzy）終端 3：遙控
source /opt/ros/jazzy/setup.bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard

模擬車是否吃 /cmd_vel（Twist）或需要 TwistStamped，依模擬套件設定而定；鍵盤按了車不動時，試 ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -p stamped:=true（需實機確認）。若模擬的 launch 已自帶 RViz 就不用再開；沒有的話：

在電腦 WSL（Jazzy）終端 4：RViz
source /opt/ros/jazzy/setup.bash
rviz2

RViz 設定：左上 Fixed Frame 改 map → 左下 Add → By topic → 加 /map（Map）與 /scan（LaserScan）。

6.3 存圖

在電腦 WSL（Jazzy）
mkdir -p ~/maps
source /opt/ros/jazzy/setup.bash
ros2 run nav2_map_server map_saver_cli -f ~/maps/room

得到 ~/maps/room.pgm 與 ~/maps/room.yaml，下一課 A2 的模擬導航會用到。

ℹ️ 補充

use_sim_time:=true 的意思是「用模擬器的時鐘，不用電腦的真實時間」。模擬器可能跑得比真實慢，如果混用兩種時間，TF 會一直報時間戳太舊。模擬時每個節點都要加；上車時不要加（車上 launch 預設都是 false）。

⚠️ 注意

電腦模擬只用來理解觀念。真正的套件名、參數與指令以車上 Humble 容器為準：電腦 Jazzy 上不要期待有 gmapping 的 apt 套件，車上的 gmapping 是 Yahboom 自己從原始碼編在 /root/gmapping_ws 的。

7. 出問題時怎麼辦

🔊 旁白文字

建圖出狀況時別慌，九成問題出在四個地方：陀螺儀沒初始化、底層 bringup 沒開、終端開到不同的容器、開車太快。先照下面的表一項一項對，大部分都能自己解決。真的不行，就整個重來一次，從車子斷電靜置五秒開始。
