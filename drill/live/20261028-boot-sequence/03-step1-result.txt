第一步的結果：翻譯官已經打開，正在等小腦。

先說下面第三格。我先打了 docker ps，結果只有一行標題，下面是空的，證明當時一個容器都沒有。接著印出了翻譯官的腳本，一共五行，第三行前面有井字號，是不會執行的 Wi-Fi 版本，第五行才是真正會執行的序列線版本。因為第三格比較矮，腳本印出來以後，把上面 docker ps 的結果擠到畫面外面去了，這是正常的。

再看左上角第一格。執行 start agent rpi5 點 sh 以後，出現了兩行：init，running，fd 三，代表翻譯官已經打開 USB 序列埠，正在線上等待；logger setup，是設定紀錄的詳細程度。

到這裡，容器的數量從零個變成一個，就是這個翻譯官。

不過小腦 ESP32 還沒有連上來，所以第一格沒有出現任何 created 的訊息。原因是我們剛才把舊的翻譯官關掉又重開，小腦不知道換了一個新的翻譯官。

下一步，第二步，要請你按 ESP32 的 Reset，讓小腦重新開機、連上翻譯官。等你說繼續，我會先念第二步的說明。
