第四步，看 TF 座標族譜。

開場說過，TF 像家族族譜，每根骨頭都記得自己在爸爸的哪裡。身體廣播員一直在廣播這份族譜，話題叫斜線 tf，和斜線 tf static。不會動的骨頭，像光達，放在 tf static，只講一次；會動的，像雲台和輪子，放在斜線 tf，一直更新。

TF 最厲害的地方是：你可以問任兩根骨頭之間的距離，它會沿著族譜自動幫你算。這一步全部在下面第三格操作，分三個小題。

第一小題，問光達在車身哪裡。先 c d 回家目錄，因為最後一小題會在目前資料夾產生檔案。然後下 ros2 run tf2 ros tf2 echo，後面接兩個名字，base link 和 radar Link，意思是：從車身看過去，光達在哪裡。預期它每秒印一次，Translation 是位移，三個數字是 x、y、z，單位是公尺。應該會看到 0、0、0.079，也就是光達在車身正上方七點九公分。這個數字就是第一步 URDF 裡 radar Joint 寫的 origin。看到以後我按 Ctrl C 停掉。

第二小題，問攝影機在車身哪裡：tf2 echo base link camera link。攝影機不是直接掛在車身上，中間隔了雲台兩節，所以 TF 要一層一層往下算。現在雲台向右轉了負 0.8，所以我預期 y 是負的，大約負 0.038，代表攝影機偏到右邊三點八公分。

接著讓 tf2 echo 繼續印，我在第二格按 Ctrl C，送一組新角度，把雲台轉回正前方。上一步你看到了，新的送角度節點大約要等一分鐘才會生效，所以這段請耐心看第三格的數字：等它生效的那一刻，y 會從負 0.038 變成 0，x 從 0.101 變成 0.117，攝影機回到車頭正前方。這就是「雲台一轉，攝影機的位置跟著變」。

第三小題，ros2 run tf2 tools view frames，它會聽幾秒鐘的 TF，然後把整棵族譜畫成一份 PDF。產生以後我會把 PDF 打開給你看。

這一步比較長。我念完以後就開始執行。
