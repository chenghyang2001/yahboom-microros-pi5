1. 影像在電腦眼中是什麼

🔊 旁白文字

在讓車子「看懂」世界之前，先要知道一張照片在電腦裡長什麼樣子。對 OpenCV 來說，一張彩色影像就是一個三層的數字表格，每個格子是一個像素，每個像素有藍、綠、紅三個數字，範圍零到兩百五十五。注意順序是藍綠紅，不是我們習慣的紅綠藍，這是初學者最常踩的第一個坑。之後的灰階、二值化、找顏色，全部都是在對這張數字表格做運算。

OpenCV（Open Source Computer Vision，開源電腦視覺函式庫）在 Python 裡把影像存成 numpy 陣列：

你想知道的 寫法 結果範例
影像大小 img.shape (480, 640, 3) → 高 480、寬 640、3 個通道
某個像素的顏色 (b, g, r) = img[100, 100] 先 y（列）後 x（行）
把某點塗黑 img[i, j] = (0, 0, 0) 顏色元組是 B、G、R
裁切 img[y1:y2, x1:x2] 一樣先 y 後 x
縮放 cv2.resize(img, (寬, 高)) 這裡卻是先寬後高
💡 小提示

img.shape 回傳（高, 寬），cv2.resize 要的卻是（寬, 高）。兩者剛好相反，記不住就每次都印出 img.shape 對照。

把下面存成 cam_basic.py，放在任一資料夾執行 python cam_basic.py：

"""筆電 webcam 練習：原圖、灰階、二值化、Canny 邊緣、畫框寫字。按 q 離開。"""
import sys
import cv2 as cv
import numpy as np


def main():
    cap = cv.VideoCapture(0)          # 0 = 第一支鏡頭；外接鏡頭可試 1
    if not cap.isOpened():
        print("錯誤：打不開鏡頭，請關掉 Teams/LINE 等占用鏡頭的程式，或改用 1", file=sys.stderr)
        sys.exit(1)
    cap.set(cv.CAP_PROP_FRAME_WIDTH, 640)
    cap.set(cv.CAP_PROP_FRAME_HEIGHT, 480)
    while True:
        ret, frame = cap.read()       # ret=False 代表這一幀沒讀到
        if not ret:
            print("讀不到畫面", file=sys.stderr)
            break
        gray = cv.cvtColor(frame, cv.COLOR_BGR2GRAY)                 # 6.3：灰階
        _, binary = cv.threshold(gray, 180, 255, cv.THRESH_BINARY_INV)  # 6.3：二值化
        edges = cv.Canny(cv.GaussianBlur(gray, (3, 3), 0), 50, 50)     # 6.3：邊緣
        cv.rectangle(frame, (220, 140), (420, 340), (0, 255, 0), 2)    # 綠框（BGR）
        cv.putText(frame, 'This is Yahboom!', (50, 50),
                   cv.FONT_HERSHEY_SIMPLEX, 1, (0, 200, 0), 2)
        # 三張灰階圖轉回三通道才能和彩色圖拼在一起
        row = np.hstack([frame, cv.cvtColor(edges, cv.COLOR_GRAY2BGR)])
        cv.imshow('frame | edges', cv.resize(row, (960, 360)))
        cv.imshow('binary', cv.resize(binary, (320, 240)))
        if cv.waitKey(1) & 0xFF == ord('q'):
            break
    cap.release()
    cv.destroyAllWindows()


if __name__ == "__main__":
    main()

試著改改看：把 threshold 的 180 改成 100、把 Canny 的 50, 50 改成 100, 200，觀察畫面怎麼變。這就是 6.3 那九支腳本的濃縮版。

ℹ️ 補充

cv.waitKey(1) 不只是讀鍵盤，它也負責讓視窗有時間重畫。迴圈裡少了它，視窗會一片灰白、沒有回應。

3. QR code 產生與辨識，與 AR 需要的相機內參

🔊 旁白文字

QR code 是讓機器人讀「指令卡」最簡單的方法，第三單元會用它來控制車子前進後退。它內建糾錯碼，就算被遮住三成左右還是讀得出來。車上官方程式用 pyzbar 解碼，但在 Windows 上 pyzbar 常常缺少底層函式庫，所以筆電練習改用 OpenCV 內建的 QR 偵測器，原理一樣：找到四個角、讀出文字、在畫面上框起來。

車上的官方版本（出廠映像已裝好 qrcode、pyzbar、libzbar-dev）：

在車上 Docker 容器內
cd /root/yahboomcar_ws/src/yahboomcar_visual/simple_qrcode/

python3 QRcode_Parsing.py   # 開鏡頭，QR code 對準鏡頭，終端機印出內容

筆電版：先產生幾張之後 M3 會用到的指令卡，再用鏡頭辨識。

在 Windows（qr_make.py）
"""產生 M3 qrTracker 用的指令卡：forward/back/left/right/stop。"""
import qrcode

for word in ["forward", "back", "left", "right", "stop"]:
    qr = qrcode.QRCode(version=1, error_correction=qrcode.constants.ERROR_CORRECT_H,
                       box_size=10, border=4)
    qr.add_data(word)
    qr.make(fit=True)
    qr.make_image(fill_color="black", back_color="white").save(f"qr_{word}.png")
    print("已產生", f"qr_{word}.png")
在 Windows（qr_webcam.py）
"""用 OpenCV 內建 QRCodeDetector 辨識，不需要 pyzbar。按 q 離開。"""
import sys
import cv2 as cv

cap = cv.VideoCapture(0)
if not cap.isOpened():
    sys.exit("錯誤：打不開鏡頭")
detector = cv.QRCodeDetector()
while True:
    ret, frame = cap.read()
    if not ret:
        break
    text, points, _ = detector.detectAndDecode(frame)
    if points is not None and text:
        pts = points.astype(int).reshape(-1, 2)
        cv.polylines(frame, [pts], True, (0, 255, 0), 3)
        cv.putText(frame, text, tuple(pts[0]), cv.FONT_HERSHEY_SIMPLEX, 1, (0, 0, 255), 2)
        print("讀到：", text)   # M3 的 qrTracker 就是把這個字串轉成速度
    cv.imshow('qr', frame)
    if cv.waitKey(1) & 0xFF == ord('q'):
        break
cap.release()
cv.destroyAllWindows()

4. ROS 2 怎麼傳影像：/image_raw 與 cv_bridge

🔊 旁白文字

到這裡為止，程式都是自己打開鏡頭自己看。可是在機器人上，常常是好幾個程式都想看同一個鏡頭，所以 ROS 的做法是：只讓一個「相機節點」打開鏡頭，把每一幀影像廣播到一個叫 image raw 的話題，誰想看就訂閱。問題是 ROS 傳的是 ROS 的影像訊息，OpenCV 看不懂，中間就需要一座翻譯橋，叫做 cv bridge，負責兩種格式互相轉換。

 鏡頭 ─▶ usb_cam_node_exe ──/image_raw──▶ 你的節點 ──(cv_bridge)──▶ OpenCV 處理
                 (sensor_msgs/Image)          │
                                              └──(cv_bridge)──/image──▶ rqt_image_view
  • sensor_msgs/Image：ROS 的影像訊息，裡面有 height、width、encoding（像素格式，例如 bgr8、rgb8、yuv422）、data（一長串位元組）。
  • cv_bridge：imgmsg_to_cv2(msg, "bgr8") 把 ROS 訊息轉成 OpenCV 陣列；cv2_to_imgmsg(frame, "bgr8") 反向轉回去。
  • 指定 "bgr8" 的好處：不管相機原本送什麼格式，拿到的都是 OpenCV 慣用的 BGR，顏色才不會紅藍顛倒。

官方 astra_rgb_image.py（訂閱並顯示）與 pub_image.py（訂閱、轉換、再發布）的核心就這幾行：

在車上 Docker 容器內（/root/yahboomcar_ws/src/yahboomcar_visual/yahboomcar_visual/ 節錄）
from cv_bridge import CvBridge
self.bridge = CvBridge()
self.sub_img = self.create_subscription(Image, '/image_raw', self.handleTopic, 100)
frame = self.bridge.imgmsg_to_cv2(msg, "bgr8")          # ROS → OpenCV
# pub_image.py 另外再發布：
self.pub_img = self.create_publisher(Image, '/image', 500)
msg = self.bridge.cv2_to_imgmsg(frame, "bgr8")          # OpenCV → ROS
self.pub_img.publish(msg)
ℹ️ 補充

套件名 yahboomcar_astra、節點名 astra_rgb_image 裡的「astra」是歷史命名，原本給 Astra 深度相機用。這台車用的是 2MP USB 相機，名字沿用而已。

5. 沒車也能練 cv_bridge：在 WSL 自己發一個影像話題

🔊 旁白文字

筆電的鏡頭要接進 WSL 很麻煩，所以我們換個方法：寫一個節點自己「畫」影像，一個會移動的綠色圓點，每秒發布十次到 image raw 話題。這樣不需要任何鏡頭，就能完整體驗發布者、cv bridge 和 rqt image view 三件事。之後在車上看到真正的相機畫面，你就知道背後發生了什麼。

在電腦 WSL（Jazzy）
sudo apt update
sudo apt install -y ros-jazzy-cv-bridge ros-jazzy-rqt-image-view python3-opencv
mkdir -p ~/m1 && cd ~/m1

把下面存成 ~/m1/fake_camera.py：

在電腦 WSL（Jazzy）（~/m1/fake_camera.py）
"""假相機節點：畫一個移動的綠點，發布到 /image_raw（sensor_msgs/Image）。"""
import math
import numpy as np
import cv2 as cv
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import Image
from cv_bridge import CvBridge


class FakeCamera(Node):
    def __init__(self):
        super().__init__('fake_camera')
        self.pub = self.create_publisher(Image, '/image_raw', 10)
        self.bridge = CvBridge()
        self.t = 0.0
        self.timer = self.create_timer(0.1, self.tick)   # 10 Hz

    def tick(self):
        frame = np.full((480, 640, 3), 40, np.uint8)       # 深灰底
        x = int(320 + 200 * math.cos(self.t))
        y = int(240 + 120 * math.sin(self.t))
        cv.circle(frame, (x, y), 40, (0, 255, 0), -1)        # BGR 綠色、填滿
        cv.putText(frame, f'x={x} y={y}', (20, 40), cv.FONT_HERSHEY_SIMPLEX, 1, (255, 255, 255), 2)
        msg = self.bridge.cv2_to_imgmsg(frame, 'bgr8')      # OpenCV → ROS
        msg.header.stamp = self.get_clock().now().to_msg()
        self.pub.publish(msg)
        self.t += 0.1


def main():
    rclpy.init()
    node = FakeCamera()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        if rclpy.ok():
            rclpy.shutdown()


if __name__ == '__main__':
    main()

開三個 WSL 終端（每個都先 source /opt/ros/jazzy/setup.bash）：

在電腦 WSL（Jazzy）
# 終端 1：發布
python3 ~/m1/fake_camera.py
# 終端 2：檢查話題、頻率、格式

ros2 topic hz /image_raw
ros2 topic echo /image_raw --no-arr     # --no-arr 不印 data 大陣列，只看 encoding、width 等欄位
# 終端 3：看畫面

看到綠點繞圈，就代表你已經懂了 ROS 影像話題的完整流程。進階練習：再寫一個節點訂閱 /image_raw、轉灰階、發布到 /image，就等於自己做了一份官方的 pub_image。

6. 上車：usb_cam、astra_rgb_image、pub_image

🔊 旁白文字

現在換成真正的車。流程是：在 Pi 5 主機上啟動 micro ROS agent，進入 ROS 2 容器，啟動 USB 相機節點，然後用官方的訂閱程式和轉發程式觀察影像。這些程式會跳出視窗，所以一定要在 VNC 遠端桌面或接螢幕的情況下操作，純 SSH 文字終端是看不到畫面的。多開終端時記得用 docker exec 進同一個容器。

步驟 1：進容器（只有影像課可以不開 agent；但 M3 起一定要開，建議養成習慣）：

在 Pi 5 主機
sh ~/start_agent_rpi5.sh      # 終端 A：啟動 agent，然後按一下控制板 reset 鈕
sh ros2_humble.sh             # 終端 B：在家目錄執行，進入 ROS 2 容器

步驟 2：多開一個終端進同一個容器（不要再跑一次 ros2_humble.sh，那會開出另一個新容器）：

在 Pi 5 主機
docker ps -a                  # 找到正在執行的容器 ID，例如 ef0e1b7da319（每次都不同）
docker exec -it ef0e1b7da319 /bin/bash

步驟 3：相機節點與兩支官方程式：

在車上 Docker 容器內
# 終端 B：啟動單目 USB 相機，發布 /image_raw
ros2 run usb_cam usb_cam_node_exe
# 終端 C：
ros2 topic list                               # 應看到 /image_raw
ros2 topic hz /image_raw
ros2 run yahboomcar_visual astra_rgb_image    # 訂閱 /image_raw 並顯示
# 終端 D：
ros2 run yahboomcar_visual pub_image          # 訂閱 /image_raw，發布 /image

在 rqt_graph 裡應該看到：usb_cam 節點 → /image_raw → 訂閱它的節點（/get_astra_rgb_node 等）；pub_image 再往外發 /image。

⚠️ 注意
  • 官方文件把 ros2 topic list 拼成 ros2 topoic list，照抄會說找不到指令。
  • 官方說 /image_raw 的 encoding 是 rgb8，同一句又說「表示 yuv422」，互相矛盾。實車確認（2026-10-28）：ros2 topic echo --once --no-arr /image_raw 看到 encoding: yuv422_yuy2、width: 640、height: 480、step: 1280（每像素 2 位元組），ros2 topic hz 約 29.8 Hz。程式裡統一指定 "bgr8" 讓 cv_bridge 幫你轉；pub_image 轉發出來的 /image 約 29.5 Hz，Pi 5 跟得上。
  • usb_cam_node_exe 啟動時印 unknown control 'exposure_auto'、unknown control 'focus_auto'：這支相機不支援這兩個設定，只是警告，不影響發布。
  • ros2 topic list 除了 /image_raw，還會看到 /image_raw/compressed、/image_raw/compressedDepth、/image_raw/theora，是 image_transport 自動多開的壓縮版。
  • 官方另有一段寫 sudo apt-get install ros-humble-usb-cam：出廠映像已裝好（位置 /opt/ros/humble/share/usb_cam/），不需要重裝。新做的容器要在啟動檔加 -v /dev/video0:/dev/video0 掛載相機；實車確認出廠的 ~/ros2_humble.sh 已經有這一行。

7. 出問題時怎麼辦

🔊 旁白文字

影像課最常見的問題只有三種：視窗出不來、畫面是黑的、話題有但沒資料。遇到時不要急著重灌，先依照下面的表一格一格檢查。尤其要記得，一支鏡頭同一時間只能被一個程式打開，相機節點開著的時候，你自己寫的程式再去開鏡頭一定會失敗，這不是程式寫錯，是鏡頭被搶走了。

症狀 可能原因 怎麼做
cannot connect to X server、視窗沒出現 用純 SSH 執行有 imshow 的程式 改在 VNC 桌面開終端執行；容器需要 X11 顯示轉發（出廠腳本已設，實車確認在 VNC 桌面跑 imshow、rqt_image_view 都能顯示）
畫面全黑、ret 一直是 False 鏡頭編號不對，或被別的程式占用 主機上 ls /dev/video* 看編號；先關掉 usb_cam_node_exe 再跑 python3 1_3.py
can't open camera by index、Camera index out of range，程式馬上結束 實車確認：usb_cam_node_exe 正開著鏡頭時就是這個訊息，看起來像編號錯，其實是被占用 關掉相機節點，或改成訂閱 /image_raw
QRcode_Parsing.py 一直讀不到紙本 QR code 實車（2026-10-28）一直沒讀到，只誤讀到一個 I25 一維條碼；相機裝得低又是廣角，QR code 在畫面裡太小，加上室內偏暗 QR code 拿近一點、放正、停住不動，光線要夠；M3 用 QR code 控車前先調好
容器裡開 rqt_image_view 印 libGL error、V3D 7.1 not supported 容器沒辦法用 Pi 的顯示卡加速，改用軟體繪圖 畫面照樣出來，可忽略（實車確認）

ros2 topic list 有 /image_raw，但 hz 沒數字 相機節點其實沒拿到鏡頭（看它的終端有沒有錯誤） 重新插拔相機、重開 usb_cam_node_exe
rqt_image_view 下拉選單是空的 在別的容器或 ROS_DOMAIN_ID 不同 用 docker exec 進同一個容器；echo $ROS_DOMAIN_ID 兩邊要一樣

WSL 的 rqt_image_view 黑畫面 WSLg 的 OpenGL 問題 先 export LIBGL_ALWAYS_SOFTWARE=1 再開
